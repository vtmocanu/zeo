zeo design book

The visual language for zeo: a frameless, tinted window where the page floats in a card and every surface draws from one token set. Each Epic 10 PRD cites a section of this book.

Space
Appearance
Surface

The window is live. Click tabs and favorites, click the space dots at the bottom of the sidebar, or click the URL pill to open the command bar. Esc closes a surface.

§1

Principles

Content is the hero

The page sits in a floating card. Everything zeo draws recedes into the tinted window around it.

Keyboard first, looks second

Every shortcut, focus order, ARIA role and data-testid that works today keeps working. The redesign changes paint, not behavior.

One visual language

Every color, size, radius, shadow and duration comes from a token. Component CSS contains no hex values.

Arc-like, not Arc

The layout language follows Arc. The work is original: no Arc name, logo, icons or assets.

§2

Window geometry

No native title bar. The sidebar owns the top-left corner, and web content lives in an inset card with its own radius, hairline and shadow.

Split view
Two cards with an 8 px gap. The gap is the existing divider hit area. The focused pane adds a 2 px --accent-soft ring.
Window material
BrowserWindow vibrancy: "sidebar" with a transparent UI background. The space tint is a UI layer above the vibrancy and below the sidebar content.
Content bounds
WebContentsView bounds are x = sidebar width, y = 8, width = W − sidebar − 8, height = H − 16. Corner radius 10 on the view; confirm setBorderRadius against the pinned Electron version in PRD 10.2. The UI renderer paints the hairline and shadow in a card-shaped layer under the view.
Title bar
titleBarStyle: "hidden" with trafficLightPosition: { x: 14, y: 16 }. The 44 px window row is a drag region except for its buttons.
§3

Color and theming

Color comes in three tiers. Components read only the semantic and component tiers, so a space theme changes every surface by changing one token set.

PaletteA 12-step neutral ramp per appearance and ten space hues defined in OKLCH. Never used directly by components.
Semantic roles--surface-window, --surface-card, --ink-primary, --ink-secondary, --accent, --hairline, --focus-ring and the rest in the table below.
Component values--sidebar-width, --row-height, --radius-tab, --card-inset. Sizes only; component colors alias semantic roles.

Neutral ramps

A slight cool bias (OKLCH hue 275, chroma 0.006) keeps the greys from reading as unconsidered mid-grey.

Space hues

Each hue is a hue angle and a chroma. The theme function derives the tint and accent lightness per appearance, so the same hue works in light and dark.

Space theme model

A space theme is one hue or a two-stop gradient plus an intensity from 0 to 1. A pure function in packages/core maps the theme and the appearance to the full semantic token set.

export type SpaceHue =
  | "iris" | "violet" | "orchid" | "rose" | "coral"
  | "amber" | "lime" | "mint" | "teal" | "sky";

export interface SpaceTheme {
  stops: [SpaceHue] | [SpaceHue, SpaceHue];
  intensity: number;
}

export type Appearance = "light" | "dark";

export function themeTokens(
  theme: SpaceTheme | null,
  appearance: Appearance,
): Record<SemanticToken, string>;
Composite
Vibrancy base, then the tint layer at 0.55 × intensity opacity in light and 0.35 × intensity in dark, then sidebar content. Tint lightness is OKLCH 0.78 in light and 0.48 in dark.
Ink
The function picks dark or light ink by the higher worst-case contrast against every stop's composite. --ink-secondary mixes ink toward the ground until it just holds 4.5:1.
Accent
From the first stop's hue. Lightness starts at 0.54 (light) or 0.76 (dark) and moves until the accent holds 3:1 against the card and the tinted window.
Null theme
No tint. The window shows plain vibrancy and the accent falls back to iris.
Guarantees
Pure and deterministic; intensity clamped to 0–1. Unit tests sweep 10 single hues and 90 ordered pairs at intensity 0, 0.5 and 1 in both appearances (600 cases) and assert every contrast floor.
Storage
PRD 10.3 adds a nullable theme JSON column to spaces in the next schema version. Existing spaces receive hues by position (§10).

Elevation

Three shadow levels, each paired with a hairline so edges hold on any tint.

§6

Surfaces

Sidebar

  1. Window row. Traffic lights, then sidebar toggle, back, forward and reload as 28 px icon buttons.
  2. URL pill. Domain of the active tab only. 34 px tall, radius 10, --fill-subtle. Click or ⌘L opens the command bar in location mode.
  3. Favorites. A global list shared by every space. Up to four columns of 48 px tiles with 24 px favicons, radius 12. The active favorite is raised.
  4. Pinned tabs. Same rows as today's tabs. They survive Clear. Keeps pinned-section.
  5. Divider and Clear. A hairline with a Clear action that archives today's tabs.
  6. Today's tabs. New Tab row, then 34 px rows. Active row is raised, hover is an 8% ink overlay. Zoom level and blocked-request count sit at the trailing edge; close appears on hover. Keeps unpinned-section.
  7. Update banner. Shown only when an update is ready. Raised surface, primary action in the accent.
  8. Bottom bar. Downloads and archived tabs on the left, one dot per space in its theme color, new space on the right.

Command bar

Floats centered about 20% from the top of the window, 680 px wide, over a blurred scrim. The input is 22 px. Results group as Tabs, History and Commands in 40 px rows, with shortcut hints right-aligned. The selected row uses --accent-soft.

Settings

A 760 × 500 sheet over the scrim, with a section list on the left. Groups sit in wells with hairline row separators. Sections map to today's groups: search engine, external links and updates under General; content blocking and allowlisted sites; profiles; history; about.

Find bar

A floating pill at the top right of the content card, inset 8 px. Query, match count, previous, next and close. Keeps every find-* test id.

Space theme picker

Opens from Edit Theme… in a space's context menu, anchored to its dot in the bottom bar. Solid or gradient, ten swatches, intensity, and a live contrast readout for both appearances. This one is live: it edits the selected space.

Popovers, menus and dialogs

Downloads, quick-browse, the update banner and dialogs share the popover tokens: --surface-popover, --shadow-popover or --shadow-palette, radius 10 or 14. Tab and space context menus stay native macOS menus.

§8

Accessibility and tests

Focus
Every control shows a 2 px --focus-ring outline on :focus-visible, offset 1 px. Press Tab inside the window below to see it.
Contrast
Enforced by the theme function, not by review: 4.5:1 for primary and secondary ink on every tint, 3:1 for the accent against the card and the window.
Hit targets
At least 28 × 28 px. Icon buttons are 28 px with 16 px icons; rows are 34 px.
Semantics
Existing ARIA roles and every data-testid stay on the same elements. Class names may change.

Contrast at full intensity

Computed live by the same function as the preview. Worst case across the composite.

§10

Decisions

  1. Favorites are global. A new favorites list shared by every space fills the tile grid. Pinned tabs stay per space and render as rows below it. PRD 10.4 adds the storage.
  2. Sidebar toggle on ⌘S. A new view.toggleSidebar command in the View menu, delivered with PRD 10.2.
  3. Existing spaces get hues by position. The migration that adds the theme column assigns iris, rose, teal, amber, violet, mint, coral, sky, orchid, lime in space order, intensity 1.
  4. Context menus stay native. Tab and space context menus remain macOS Menu popups. Only surfaces zeo draws itself take the popover tokens.
