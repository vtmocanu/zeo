# PRD 9.2 — Main-process modules and shared helpers

## Context

zeo is a keyboard-first, workspace-centric open-source browser for macOS.
Design: `docs/specs/2026-08-30-zeo-v1-design.md`. The Electron main process
is one file, `apps/desktop/src/main/index.ts`, at 3029 lines with 65
top-level functions, ~60 `ipcMain.handle` registrations, and every piece of
mutable runtime state as a module-level `let`/`const`. It already carries
`// --- Section ---` markers (command bar, command registry, content
blocking, zoom, find, settings, history, space commands) that mark where the
seams are. `apps/desktop/src/main/db.ts` (852 lines) is the only sibling.

Issue #42 lists near-identical blocks that should share helpers: `closeTab`,
`removeTab`, and `deleteSpace` each repeat the same seven-line per-tab
forget sequence; `TabStore.archiveIdle` re-implements `archive`'s stamping;
`ArchivedRow` in `apps/ui/src/App.tsx` copies `TabRow`'s favicon block
verbatim; `.archived-item__delete` in `apps/ui/src/App.css` duplicates every
declaration of `.tab-item__close`; `sweepIdle` calls `setActive` after a
sweep that by construction never changes the active tab.

This PRD is a pure refactor: it splits the main process into modules with
one responsibility each, extracts the shared helpers, and adds a lint
ceiling so the file cannot regrow. It changes no behavior: the e2e suite,
the unit suites, the IPC channel set, and every user-visible flow are
identical before and after. It lands before PRDs 9.3 to 9.6, which then
touch modules instead of one file.

## Deliverables

### 1. Module layout `apps/desktop/src/main/`

| File | Owns |
|---|---|
| `index.ts` | Bootstrap only: imports every module for its side effects (IPC registration), `app.whenReady` sequence, `activate`, `window-all-closed`, `before-quit`. Target under 150 lines. |
| `state.ts` | The mutable runtime singletons every module reads: `store`, `views`, `win`, `overlay`, `settingsView`, `settingsOpen`, `commandBar`, `commandBarRevision`, `find`, `blocking`, `blocker`, `zoom`, `settings`, `settingsSection`, `settingsSectionNonce`, `allowlist`, and the per-tab maps `failedLoads`, `navSeq`, `hasRealTitle`, `lastHistoryKey`, `lastVisitId`, `webContentsToTab`, `tabToWcId`, `tabOrigin`. Exported as one `export const runtime = { ... }` object whose properties are reassigned in place (`runtime.win = ...`), so a module never holds a stale copy of a reassigned binding. Constants `DEFAULT_URL`, `IDLE_THRESHOLD_MS`, `SWEEP_INTERVAL_MS`, `BLOCKING_BROADCAST_MS`, `HISTORY_CANDIDATES`, `moduleDir`, `cosmeticPreloadPath` live here too. |
| `broadcast.ts` | `fullSnapshot`, `broadcast`, `scheduleBlockingBroadcast`, `pushCommandBar`, `refreshCommandState`. |
| `views.ts` | `viewBounds`, `createViewFor`, `destroyView`, `setActive`, `ensureActiveView`, `activateTab`, `profileSessions`. |

| `spaces.ts` | `deleteSpace`, `remapSpaceProfile`, `showSpaceContextMenu`, and the `IPC.spaces*` / `IPC.profiles*` handlers. |
| `commands.ts` | `commandContextOf`, `commandHandlers`, `executeCommand`, and the `IPC.commands*` handlers. |

| `window.ts` | `createWindow`. |

Rules for the split:

- Every function keeps its name, signature, and doc comment; a function
  moves, it is not rewritten. The only edits inside a moved function are the
  `runtime.` qualification of state reads and writes and the import of
  sibling-module functions.
- `createViewFor`'s per-view listeners (title, favicon, navigation, blocked
  count reset, history recording, find, zoom) stay inside `createViewFor` in
  `views.ts`; the module imports `recordNavigation`, `applyViewZoom`,
  `applyZoom`, `applyFindResult`, and the reducers it calls. Splitting the
  listener body across modules is out of scope.
- Import edges are acyclic at the value level: `state.ts` imports nothing
  from its siblings; `broadcast.ts` imports `state.ts` and `menu.ts` only;
  `views.ts`, `tabs.ts`, `spaces.ts`, `command-bar.ts`, `find.ts`,
  `blocking.ts`, `history.ts`, `zoom.ts`, `settings.ts`, `window.ts` import
  `state.ts` and `broadcast.ts` and one another as needed, but any cycle
  between two of them is broken by moving the shared function into the
  module that owns the state it mutates. `menu.ts` imports `commands.ts`
  for `executeCommand` and `commandContextOf`; `commands.ts` must not import
  `menu.ts` (`refreshCommandState` in `broadcast.ts` is the only caller of
  `buildMenu`). The implementer verifies with
  `npx madge --circular apps/desktop/src/main` (dev dependency added to
  `apps/desktop`) and the check runs in `pnpm lint` through a
  `"lint:cycles"` script the root `lint` script chains.
- IPC handlers are registered at module load by a top-level
  `ipcMain.handle(...)` block in each owning module, in the same order they
  appear today. `index.ts` imports each module once
  (`import "./tabs.js";` style) so registration happens before
  `app.whenReady` resolves. A channel registered twice throws at startup in
  Electron; the e2e suite's launch covers this.
- `db.ts` and `db.test.ts` are unchanged.

### 2. Shared helpers (#42)

- `tabs.ts` `forgetTab(id: string): void` — the per-tab forget sequence
  currently repeated in `closeTab`, `removeTab`, and `deleteSpace`'s loop:
  `runtime.blocking = dropBlockedTab(runtime.blocking, id)`, then delete `id`
  from `tabOrigin`, `lastHistoryKey`, `lastVisitId`, `hasRealTitle`. It does
  NOT call `destroyView` (callers keep their own teardown order, and
  `deleteSpace` destroys views before the store delete while `closeTab`
  destroys after). `closeTab` and `removeTab` become: store call, `forgetTab`,
  `destroyView`, `ensureActiveView`, `broadcast`.
- `sweepIdle` drops its `setActive(store.activeTabId)` call: `archiveIdleAll`
  exempts every space's active tab, so the visible view never changes; the
  broadcast stays.
- `packages/core/src/tab-store.ts`: private `stampArchived(record: TabRecord, at: number): void`
  sets `archivedAt = at` and `archivalSeq = ++this.seq`; `archive` and
  `archiveIdle` both call it. Private `findRecord(id: string, verb: string): TabRecord`
  returns the record or throws `Cannot ${verb} unknown tab: ${id}`, used by
  `close`, `remove`, `activate`, `pin`, `unpin`, `reorder`, `archive`,
  `restore` in place of their inline `find`/`findIndex` + throw pairs. Error
  messages are byte-identical to today's so `tab-store.test.ts` passes
  unchanged.
- `apps/ui/src/Favicon.tsx`: `export function Favicon({ url, title }: { url: string | null; title: string })`
  renders the `<img className="tab-item__favicon">` when `url` is a
  non-empty string, else the `tab-item__favicon--fallback` span with the
  first character of `title` — the exact markup `TabRow` renders today.
  `TabRow` and `ArchivedRow` both use it.
- `apps/ui/src/App.css`: one `.icon-button` class carries every declaration
  `.tab-item__close` and `.archived-item__delete` share (reset, size, color,
  reveal-on-hover, focus ring, hover background). `.tab-item__close` and
  `.archived-item__delete` keep only their reveal selectors
  (`.tab-item:hover .tab-item__close`, etc.) and any declaration that
  differs between the two. Both buttons carry `className="icon-button tab-item__close"`
  / `"icon-button archived-item__delete"`; every existing `data-testid` and
  `aria-label` is unchanged.

### 3. Lint ceiling

`eslint.config.js` adds, for `files: ["apps/desktop/src/main/**/*.ts"]`
excluding `*.test.ts`, the rule
`"max-lines": ["error", { max: 800, skipBlankLines: true, skipComments: true }]`.
`db.ts` (852 raw lines) passes because comments and blanks are skipped; if
it does not, the implementer splits `db.ts`'s history queries into
`db-history.ts` (the `recordVisit` .. `pruneHistory` block) rather than
raising the ceiling.

### 4. Tests

- `apps/desktop/src/main/state.test.ts`: `runtime` starts with every
  documented default (`win === null`, `views.size === 0`, `commandBar.open
  === false`, `find.open === false`, `settings.searchEngine === "duckduckgo"`,
  `zoom.byHost` empty). Guards a future module from seeding state at import.
- `apps/desktop/src/main/tabs.test.ts`: `forgetTab` clears every per-tab map
  entry and the blocked count, and leaves `views` untouched. Uses the
  in-memory `runtime` with a hand-built `SpaceStore`; no Electron window.
- `packages/core/src/tab-store.test.ts`: existing tests unchanged; one added
  case proves `archiveIdle` and `archive` stamp identical `archivedAt` /
  `archivalSeq` sequences for the same clock.
- `apps/ui`: existing snapshot-free tests unchanged; `Favicon` gets a
  Vitest + React Testing Library test only if the ui workspace already has a
  DOM test setup; otherwise the e2e sidebar assertions cover it.
- e2e: no new test. The whole suite passing unchanged is the acceptance
  proof.

## Constraints

- No behavior change. Every `ipcMain.handle` channel, every accelerator,
  every broadcast shape, and every error message string is identical.
- `packages/core` stays Electron-free; the `TabStore` helpers are private.
- TypeScript strict; no `any`. `runtime` is typed as an interface
  `RuntimeState` in `state.ts`, not inferred.
- Nothing under `.github/workflows/` is written.
- Conventional Commits, one `refactor(desktop): ...` commit for the split and
  one `refactor: ...` commit for the shared helpers, so a bisect can tell
  them apart.
- Land after PR #119 (downloads) merges; the branch is cut from the `main`
  that already contains it. If a later PRD's branch is open when this lands,
  that branch merges `main` (a merge commit, not a rebase).
- Versioning: bump root `package.json` patch to the next free version at
  rebase time and add a dated `CHANGELOG.md` section under `### Changed`
  stating the main process is now modular; no schema change.

## Acceptance criteria

1. `apps/desktop/src/main/index.ts` is under 150 lines and contains no
   `ipcMain.handle` call and no function longer than the `whenReady`
   sequence.
2. Every module in the layout table exists with exactly the listed
   functions (`grep -n "^export function\|^export const\|^export async function"`
   per file matches the table); no other top-level function exists in
   `main/`.
3. `pnpm lint` fails when any `apps/desktop/src/main/*.ts` file exceeds 800
   non-blank, non-comment lines, and `lint:cycles` reports no circular
   import.
4. `closeTab`, `removeTab`, and `deleteSpace` each call `forgetTab`; the
   seven-line forget sequence appears once in the tree.
5. `sweepIdle` contains no `setActive` call.
6. `TabStore.archive` and `TabStore.archiveIdle` share `stampArchived`; the
   inline `find` + throw pairs are gone from the eight listed methods.
7. `TabRow` and `ArchivedRow` render `<Favicon>`; `.tab-item__close` and
   `.archived-item__delete` no longer duplicate a declaration, and
   `.icon-button` exists.
8. `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm e2e` pass with the
   e2e spec files byte-identical to `main` before this PRD.
