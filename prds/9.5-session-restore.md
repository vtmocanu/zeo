# PRD 9.5 — Session restore: window state, no-window accelerators, pinned close, sticky pinned section

## Context

zeo is a keyboard-first, workspace-centric open-source browser for macOS.
Design: `docs/specs/2026-08-30-zeo-v1-design.md`. `SCHEMA_VERSION` is 6 on
main, in `packages/core/src/persistence.ts`; all SQL lives in
`apps/desktop/src/main/db.ts` (`DDL`, `MIGRATION_STEPS` keyed by the version
each step produces, `migrate()`, the singleton `meta` row `id=0`).

This PRD claims an effective schema version `N`, defined as main's
`SCHEMA_VERSION` at rebase time PLUS 1. PRD 6.2 (downloads) claims 7 and
PRD 9.4 claims 8; PRD 9.6 claims the version after this one. If a
lower-numbered claim lands after this PRD, the implementer takes the next
free version at rebase. Under no collision `N` is `9`, and every version
number this PRD writes as `9` — the `MIGRATION_STEPS` step key, the
`UPDATE meta SET schemaVersion = 9 WHERE id = 0` statement, the
migration-runner test's expected final version, and any schema-version
acceptance criterion — is that same `9` written as the illustrative value
of `N`; one substitution applies everywhere at once.

The store already restores spaces, tabs, each space's active tab, and the
active space across relaunch. Four gaps remain in what "reopen where I
left off" means:

- The window always opens at 1280×800 at the OS default position;
  `createWindow` (`apps/desktop/src/main/window.ts` after PRD 9.2) hardcodes
  the size and never reads or writes bounds.
- On macOS the app stays alive after `window-all-closed`, and the
  application menu stays active. `Cmd+T` then runs `store.create` while
  `createViewFor` early-returns on `win === null` and `broadcast` pushes to
  nobody; each press adds one hidden tab that all appear on the next dock
  activation (#34).
- `Cmd+W` on a pinned tab destroys it outright: `TabStore.close` has no
  pinned guard while `archive` rejects pinned tabs, so the protection is
  inverted (#33).
- The sidebar scrolls `.sidebar__sections` as one container, so with many
  unpinned tabs the pinned section scrolls off-screen (#36).

This PRD persists window bounds, makes every accelerator recreate the
window before acting, turns close-on-pinned into "unload and stay pinned"
(the Arc model: a pinned tab is a fixture of the space; closing it frees
the page, not the slot), and pins the pinned section.

## Deliverables

### 1. Core `packages/core/src/window-state.ts`

```ts
export interface WindowState {
  x: number | null;
  y: number | null;
  width: number;
  height: number;
  maximized: boolean;
}
export interface Rect { x: number; y: number; width: number; height: number; }
export const DEFAULT_WINDOW_SIZE = { width: 1280, height: 800 } as const;
export const MIN_WINDOW_SIZE = { width: 640, height: 400 } as const;
export const MIN_VISIBLE_PX = 100;

export function resolveWindowBounds(
  saved: WindowState | null,
  workAreas: readonly Rect[],
): { x?: number; y?: number; width: number; height: number; maximized: boolean };
```

- `saved === null` (or `workAreas` empty) returns `DEFAULT_WINDOW_SIZE`
  with no `x`/`y` (Electron centers) and `maximized: false`.
- `width`/`height` are clamped to at least `MIN_WINDOW_SIZE` and at most
  the largest work area's width/height.
- `x`/`y` are kept only when both are non-null AND the saved rectangle
  intersects at least one work area by at least `MIN_VISIBLE_PX` in both
  axes; otherwise they are omitted so the window centers on the primary
  display. `maximized` passes through.
- Pure and total; exported from the index with the types.

### 2. Schema `N` (illustrative 9): `window_state`

```sql
CREATE TABLE window_state (
  id INTEGER PRIMARY KEY CHECK (id = 0),
  x INTEGER, y INTEGER,
  width INTEGER NOT NULL, height INTEGER NOT NULL,
  maximized INTEGER NOT NULL DEFAULT 0
);
```

`DDL` adds the table (no seed row: absence means "never saved").
`MIGRATION_STEPS[9]` is the `CREATE TABLE` plus
`UPDATE meta SET schemaVersion = 9 WHERE id = 0;`. `SCHEMA_VERSION` becomes
`9`. `db.ts` gains `readWindowState(): WindowState | null` (the row mapped
to the core shape, `maximized` as boolean) and
`writeWindowState(state: WindowState): void` (an `INSERT ... ON CONFLICT(id)
DO UPDATE` upsert of row 0, synchronous, throws on failure).

### 3. Main `window.ts`

- `createWindow(seed)` reads `readWindowState()` (a throw is logged and
  treated as `null`), collects `screen.getAllDisplays().map((d) => d.workArea)`,
  calls `resolveWindowBounds`, and constructs the `BrowserWindow` with the
  resolved `x`/`y`/`width`/`height` plus `minWidth`/`minHeight` from
  `MIN_WINDOW_SIZE`; when `maximized` it calls `win.maximize()` before
  loading the renderer.
- `saveWindowState()` reads `win.getNormalBounds()` and `win.isMaximized()`
  into a `WindowState` and calls `writeWindowState`; a throw is logged
  once per launch. It is debounced 500 ms behind the `resize`, `move`,
  `maximize`, and `unmaximize` window events, and called synchronously
  (cancelling any pending timer) from the window's `close` event and from
  `before-quit`. Fullscreen is not persisted: `getNormalBounds` reports the
  pre-fullscreen frame, and a fullscreen window restores as a normal
  window of that frame.
- `requireWindow(): BrowserWindow` — returns `win` when non-null; otherwise
  calls `createWindow(false)` and returns the new window. Called first
  thing in `executeCommand` (`commands.ts`), in the `Activate Tab N` and
  `Activate Space N` menu click handlers (`menu.ts`), and in `createTab`
  (`tabs.ts`). Those are the complete set of window-dependent menu paths:
  `buildMenu` today has exactly four kinds of `click` handler (the
  `executeCommand` entries, the `CmdOrCtrl+N` tab entries, the
  `CmdOrCtrl+Alt+N` space entries, and `New Tab`, which resolves to
  `createTab`), plus the `appMenu` and `editMenu` roles, which are
  Electron-native, mutate no store state, and are out of scope. Any menu
  `click` handler this PRD or a later one adds must call `requireWindow()`
  before touching the store; the no-window e2e test guards the rule. With
  a window guaranteed, `createViewFor`'s `win === null` early return is
  unreachable from user input; it stays as a guard.

### 4. Pinned close (#33)

- `TabStore.close(id): "removed" | "unloaded"` — an unknown or archived id
  throws as today. A pinned tab is NOT removed: the record stays in place
  with `pinned` untouched; when it was the active tab, the MRU among the
  OTHER open tabs becomes active (`null` when there is none); the method
  returns `"unloaded"`. An unpinned tab is removed as today and the method
  returns `"removed"`. `SpaceStore.close` forwards the result.
- Main `closeTab(id)`: `const outcome = store.close(id)`; on `"removed"`
  the existing `forgetTab` + `destroyView`; on `"unloaded"` only
  `unloadView(id)` (PRD 9.3; add-if-absent as `destroyView`) so the tab's
  history flags survive; then `ensureActiveView()` and `broadcast()`. The
  unloaded pinned tab appears in `TabsState.unloadedTabIds` (PRD 9.3;
  add-if-absent with that contract) and its row renders dimmed; activating
  it recreates the view at `tab.url`.
- `tab.close` enablement and the context-menu `Close` item are unchanged
  (both apply to a pinned tab and mean "unload").

### 5. Sidebar pinned section (#36)

`apps/ui/src/App.css`: `.sidebar__sections` stops scrolling
(`overflow: hidden`, still `flex: 1; min-height: 0; display: flex;
flex-direction: column`). `.sidebar__section--pinned` becomes
`flex: 0 0 auto; max-height: 40%; overflow-y: auto` and keeps its bottom
border. The unpinned `.sidebar__section` becomes `flex: 1; min-height: 0;
overflow-y: auto`. Drag-and-drop reorder within each list is unaffected
(each list keeps its own ref and dropzones). No markup change.

### 6. Tests

Unit (`packages/core`):

- `window-state.test.ts`: null saved returns defaults with no position;
  size clamps at both ends; a saved rect fully off every display drops
  `x`/`y`; one that overlaps by 100×100 keeps them; one that overlaps by
  99 px on one axis drops them; `maximized` round-trips.
- `tab-store.test.ts`: `close` on a pinned active tab returns `"unloaded"`,
  keeps the record pinned in place, and activates the MRU sibling (or
  `null`); on a pinned inactive tab it changes nothing but the return
  value; on an unpinned tab it returns `"removed"` and behaves exactly as
  before (every existing `close` test passes unchanged).

Unit (`apps/desktop`): `db.test.ts` migrates version 8 to 9 with an empty
`window_state`; `writeWindowState` then `readWindowState` round-trips
including nulls and the boolean; the migration-runner test expects `9`.

e2e:

- Window restore (`persistence.spec.ts`): resize the window to 900×700 and
  move it to (120, 80) over `app.evaluate`; wait for the debounced save;
  relaunch on the same user-data dir; `getNormalBounds()` reports the same
  size and position (±1 px for platform rounding). Launch with a
  pre-written `window_state` row at (−5000, −5000): the window is on-screen
  and centered.
- No-window accelerators (`app.spec.ts`, `test.skip` unless
  `process.platform === "darwin"`): close the window via
  `BrowserWindow.getAllWindows()[0].close()`; with zero windows, click the
  Tabs menu's `New Tab` item through the existing `clickTabsMenuItem`
  helper; exactly one window exists, the store's open tab count increased
  by one, and the sidebar shows every tab.
- Pinned close: pin a tab, activate it, press `Cmd+W` via
  `pressCloseTab`; the tab is still listed and pinned, its view is gone
  (`waitForViewGone`), `unloadedTabIds` contains it, another tab is
  active; click it: `waitForViewUrl` at its url and `unloadedTabIds` is
  empty.
- Sticky pinned: one pinned tab and forty unpinned; scroll the unpinned
  list to the bottom; the pinned row's `boundingBox()` is inside the
  sidebar's box.

## Constraints

- `packages/core` must not import `electron`; display geometry reaches
  `resolveWindowBounds` as plain rects.
- Window-state writes never go through `scheduleSave(store)`; they are a
  separate, small upsert so a bounds change never re-serializes the tab
  store.
- A pinned tab is never removed by `close`; only `unpin` then `close`, or
  `remove`, drops it.
- TypeScript strict; no `any`. Nothing under `.github/workflows/` is
  written. Conventional Commits; no AI attribution.
- Versioning: bump root `package.json` patch to the next free version at
  rebase time and add a dated `CHANGELOG.md` section (`### Added` window
  restore, `### Changed` pinned close, `### Fixed` #34 and #36; note the
  schema bump).

## Acceptance criteria

1. Relaunching restores the window's size, position, and maximized state;
   an off-screen saved position falls back to a centered window.
2. On macOS with no window open, every menu `click` handler listed in §3
   (`executeCommand` entries, `Activate Tab N`, `Activate Space N`, `New
   Tab`) first recreates the window and then acts; no hidden tabs
   accumulate.
3. `Cmd+W` on a pinned tab keeps it pinned in the sidebar, unloads its
   page, moves activation to the MRU sibling, and a later click reloads it.
4. The pinned section never scrolls out of view and caps at 40% of the
   sidebar height with its own scrollbar.
5. `SCHEMA_VERSION` equals `N`; a version `N-1` database migrates in place
   and a fresh database creates `window_state`.
6. `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm e2e` pass on both
   CI jobs.
