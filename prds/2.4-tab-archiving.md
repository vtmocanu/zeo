# PRD 2.4 — Auto-archive and the archived-tabs view

## Context

zeo is a keyboard-first, workspace-centric open-source browser for macOS.
Design: `docs/specs/2026-08-30-zeo-v1-design.md`. Requires PRD 2.3
(`prds/2.3-pin-reorder-context-menu.md`) merged: manual archive exists via
context menu; `TabStore` has `archive`/`restore`/`archived()` with
`lastActiveAt` stamps.

## Deliverables

### 1. Auto-archive policy (core)

- `TabStore.archiveIdle(maxIdleMs)`: archives every unpinned, non-active
  open tab whose `lastActiveAt` is older than `maxIdleMs`; returns the
  archived ids. Pinned and active tabs are never auto-archived.
- Unit tests: boundary cases (exactly at threshold, active exempt, pinned
  exempt, empty store), returned ids.

### 2. Scheduling (main process)

- Run `archiveIdle` on an interval (constant, 12h idle threshold, hourly
  sweep) and on app launch; broadcast after each sweep that archived
  anything.
- The active tab's `lastActiveAt` refreshes on window focus so a tab left
  focused overnight is not archived.

### 3. Archived view (renderer)

- Sidebar footer button ("Archived", with count) toggles an archived list:
  rows show favicon, title, archived-at relative time.
- Row click restores the tab (becomes active); a row action deletes it
  permanently (`TabStore.remove(id)` — add with tests if absent).
- Empty state when no archived tabs.

### 4. Tests

- e2e: create a tab, archive it via the bridge, assert the archived count
  and list render, restore it and assert it returns to the open list.

## Constraints

- Policy logic entirely in `packages/core`; the main process only schedules
  and broadcasts.
- No persistence yet: archived tabs live in memory and vanish on quit
  (SQLite lands in a later PRD; do not add it here).
- Do not create or modify anything under `.github/workflows/`; root script
  names stay unchanged.

## Acceptance criteria

- `pnpm lint && pnpm typecheck && pnpm build && pnpm test && pnpm e2e` green.
- In the running app: archived view lists archived tabs, restore works,
  permanent delete works.
- CI green on the merge request branch.
