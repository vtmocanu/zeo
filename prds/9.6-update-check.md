# PRD 9.6 — In-app update check

## Context

zeo is a keyboard-first, workspace-centric open-source browser for macOS.
Design: `docs/specs/2026-08-30-zeo-v1-design.md`. `SCHEMA_VERSION` is 6 on
main, in `packages/core/src/persistence.ts`; all SQL lives in
`apps/desktop/src/main/db.ts` (`DDL`, `MIGRATION_STEPS` keyed by the version
each step produces, `migrate()`, the singleton `meta` row `id=0`).

This PRD claims an effective schema version `N`, defined as main's
`SCHEMA_VERSION` at rebase time PLUS 1. PRD 6.2 (downloads) claims 7, PRD
9.4 claims 8, and PRD 9.5 claims 9. If a lower-numbered claim lands after
this PRD, the implementer takes the next free version at rebase. Under no
collision `N` is `10`, and every version number this PRD writes as `10` —
the `MIGRATION_STEPS` step key, the `UPDATE meta SET schemaVersion = 10
WHERE id = 0` statement, the migration-runner test's expected final
version, and any schema-version acceptance criterion — is that same `10`
written as the illustrative value of `N`; one substitution applies
everywhere at once.

The design doc's Distribution section promises an in-app update check
against GitHub Releases: Homebrew-managed installs are told to run
`brew upgrade`, direct dmg/zip installs are linked to the release page.
PRD 8.1 (packaging) produces the GitHub Release per `v*` tag and PRD 8.2
(Homebrew cask) publishes the cask `zeo` in the `vtmocanu/tap` tap; both
defer the check itself to this PRD. Nothing in the tree reads
`app.getVersion()` today, and there is no auto-update: zeo is ad-hoc
signed, so Squirrel-style in-place updates are out of scope (design
non-goals).

This PRD adds the check: a pure decision core, a main-side poller against
the releases API, a broadcast `update` slice, a sidebar banner, a settings
row with an on/off switch and a manual check, and a per-version dismiss.
It depends on PRD 8.1 having shipped at least one Release; until then the
feed answers 404 and the check reports an error and no update.

## Deliverables

### 1. Core `packages/core/src/update.ts`

```ts
export const UPDATE_FEED_URL = "https://api.github.com/repos/vtmocanu/zeo/releases/latest";
export const UPDATE_CHECK_INTERVAL_MS = 24 * 60 * 60 * 1000;
export const UPDATE_CHECK_STARTUP_DELAY_MS = 10_000;
export const UPDATE_FETCH_TIMEOUT_MS = 5_000;
export const HOMEBREW_UPGRADE_COMMAND = "brew upgrade --cask zeo";
export const CASKROOM_PATHS: readonly string[] = [
  "/opt/homebrew/Caskroom/zeo",
  "/usr/local/Caskroom/zeo",
];

export interface ParsedVersion { major: number; minor: number; patch: number; prerelease: string | null; }
export function parseVersion(text: string): ParsedVersion | null;
export function compareVersions(a: string, b: string): -1 | 0 | 1;

export interface LatestRelease { version: string; url: string; publishedAt: string; }
export function parseLatestRelease(json: unknown): LatestRelease | null;

export type InstallOrigin = "homebrew" | "direct";
export function installOrigin(existsDir: (path: string) => boolean, paths?: readonly string[]): InstallOrigin;

export interface AvailableUpdate { version: string; url: string; }
export function updateDecision(currentVersion: string, latest: LatestRelease | null, dismissedVersion: string | null): AvailableUpdate | null;

export interface UpdateState {
  enabled: boolean;
  origin: InstallOrigin;
  available: AvailableUpdate | null;
  checking: boolean;
  lastCheckedAt: number | null;
  error: string | null;
}
```

- `parseVersion` accepts `MAJOR.MINOR.PATCH` with an optional leading `v`
  and an optional `-prerelease` suffix; anything else (build metadata,
  missing components, non-digits) returns `null`.
- `compareVersions` compares numerically by major, minor, patch; a version
  with a prerelease sorts BELOW the same numbers without one; two
  prereleases compare by plain string order. An unparseable side is treated
  as `0.0.0`.
- `parseLatestRelease` reads `{ tag_name, html_url, published_at, draft,
  prerelease }`; returns `null` when `json` is not an object, `draft` or
  `prerelease` is `true`, `tag_name` does not parse, or `html_url` is not a
  string; `version` is the tag with its leading `v` removed.
- `installOrigin` returns `"homebrew"` when `existsDir` is `true` for any
  path in `paths` (default `CASKROOM_PATHS`), else `"direct"`. The
  filesystem probe is injected so the function is pure.
- `updateDecision` returns `null` when `latest` is `null`, when
  `compareVersions(latest.version, currentVersion) <= 0`, or when
  `latest.version === dismissedVersion`; otherwise
  `{ version: latest.version, url: latest.url }`.
- `Settings` (`packages/core/src/ipc.ts`) gains `updateCheckEnabled: boolean`.
  `TabsState` gains `update: UpdateState`, attached by main on every
  broadcast like `zoom` and `find`.
- `packages/core/src/index.ts` exports everything above.

### 2. Bridge and channels (`packages/core/src/ipc.ts`, preload)

```ts
export interface UpdateApi {
  check(): Promise<void>;
  dismiss(): Promise<void>;
  openRelease(): Promise<void>;
  copyUpgradeCommand(): Promise<void>;
  state(): Promise<UpdateState>;
}
```

`SettingsApi.setUpdateCheckEnabled(enabled: boolean): Promise<void>`;
`ZeoApi.update: UpdateApi`. Channels: `updateCheck: "zeo:update:check"`,
`updateDismiss: "zeo:update:dismiss"`, `updateOpenRelease: "zeo:update:open-release"`,
`updateCopyCommand: "zeo:update:copy-command"`, `updateState: "zeo:update:state"`,
`settingsSetUpdateCheckEnabled: "zeo:settings:set-update-check-enabled"`.
The preload maps each with `ipcRenderer.invoke`.

### 3. Schema `N` (illustrative 10)

`meta` gains `updateCheckEnabled INTEGER NOT NULL DEFAULT 1`,
`updateDismissedVersion TEXT` (nullable), `updateLastCheckedAt INTEGER`
(nullable). `DDL` adds the three columns; `MIGRATION_STEPS[10]` is three
`ALTER TABLE meta ADD COLUMN ...` statements plus
`UPDATE meta SET schemaVersion = 10 WHERE id = 0;`. `SCHEMA_VERSION` becomes
`10`. `db.ts` gains `readUpdateSettings(): { enabled: boolean; dismissedVersion: string | null; lastCheckedAt: number | null }`,
`writeUpdateCheckEnabled(enabled: boolean): void`,
`writeUpdateDismissedVersion(version: string | null): void`, and
`writeUpdateLastCheckedAt(at: number): void`, each a synchronous `UPDATE
meta ... WHERE id = 0` that throws when zero rows are affected.

### 4. Main `apps/desktop/src/main/update.ts`

- `runtime.update: UpdateState` in `state.ts`, seeded
  `{ enabled: true, origin: "direct", available: null, checking: false, lastCheckedAt: null, error: null }`
  and replaced at startup from `readUpdateSettings()` plus
  `installOrigin((p) => existsSync(p) && statSync(p).isDirectory())`, with
  `ZEO_UPDATE_ORIGIN` (`homebrew` | `direct`) overriding the probe only
  when `ZEO_E2E === "1"`.
- `feedUrl()`: `ZEO_UPDATE_FEED_URL` when `ZEO_E2E === "1"` and set, else
  `UPDATE_FEED_URL`. `startupDelayMs()`: `ZEO_UPDATE_STARTUP_DELAY_MS`
  under the same gate, else `UPDATE_CHECK_STARTUP_DELAY_MS`.
- `checkForUpdates(reason: "startup" | "timer" | "manual"): Promise<void>`:
  1. `reason !== "manual" && !runtime.update.enabled` resolves with no
     effect.
  2. A check already in flight (`checking === true`) returns the SAME
     promise (coalesced).
  3. Sets `checking = true`, `error = null`, broadcasts.
  4. `net.fetch(feedUrl(), { headers: { Accept: "application/vnd.github+json", "User-Agent": "zeo/" + app.getVersion() }, signal: AbortSignal.timeout(UPDATE_FETCH_TIMEOUT_MS) })`.
     A non-2xx status sets `error = "HTTP <status>"`; a rejection (network,
     timeout, JSON parse) sets `error = "network error"`. On error
     `available` is unchanged.
  5. On success: `latest = parseLatestRelease(await res.json())`;
     `available = updateDecision(app.getVersion(), latest, dismissedVersion)`;
     `latest === null` is not an error (a 200 with no usable release means
     "no update").
  6. In every case: `lastCheckedAt = Date.now()`, persisted with
     `writeUpdateLastCheckedAt` (a throw is logged once and does not fail
     the check), `checking = false`, broadcast. The promise resolves; it
     never rejects.
- `dismissUpdate(): void` — a no-op when `available === null`; otherwise
  `writeUpdateDismissedVersion(available.version)` (a throw rejects the
  invoke and changes nothing), then `available = null` and broadcast.
- `setUpdateCheckEnabled(enabled: boolean): Promise<void>` — the PRD 6.5
  ordered contract: no-op when unchanged; `TypeError` on a non-boolean;
  `writeUpdateCheckEnabled` synchronously (a throw rejects, nothing
  changes); then `runtime.settings.updateCheckEnabled` and
  `runtime.update.enabled` are set and broadcast. Turning it on does not
  trigger an immediate check; the next timer tick or a manual check does.
- `openRelease()` — `shell.openExternal(available.url)` when `available`
  is non-null and its url parses with an `https:` protocol; otherwise a
  no-op. `copyUpgradeCommand()` — `clipboard.writeText(HOMEBREW_UPGRADE_COMMAND)`.
- Scheduling in `index.ts` `whenReady`, after `createWindow`: when
  `app.isPackaged || (process.env.ZEO_E2E === "1" && process.env.ZEO_UPDATE_FEED_URL)`,
  `setTimeout(() => void checkForUpdates("startup"), startupDelayMs())` and
  `setInterval(() => void checkForUpdates("timer"), UPDATE_CHECK_INTERVAL_MS)`.
  An unpackaged dev build without the override never checks on its own;
  `update.check` still works there against the real feed.
- IPC handlers: `updateCheck` runs `checkForUpdates("manual")`;
  `updateDismiss`, `updateOpenRelease`, `updateCopyCommand`, `updateState`
  (returns `runtime.update`), and `settingsSetUpdateCheckEnabled`.
- `fullSnapshot()` attaches `update: runtime.update`.

### 5. Command registry

`packages/core/src/commands.ts` adds
`{ id: "update.check", title: "Check for Updates", keywords: ["update", "upgrade", "version", "release"], accelerator: null, menu: "view" }`,
always enabled. The handler runs `checkForUpdates("manual")` and, when
the settings view is closed, opens it at `general` so the result is
visible (`openSettingsAt("general")`); when already open it only checks.

### 6. Settings General section (`apps/ui/src/Settings.tsx`)

A `Updates` group below the search-engine row:

- Checkbox `Check for updates automatically` bound to
  `state.settings.updateCheckEnabled`, dispatching
  `settings.setUpdateCheckEnabled`.
- Button `Check now` (disabled while `update.checking`), dispatching
  `update.check`.
- Status line, one of: `Checking…`; `zeo <version> is available` followed
  by the action for the origin; `You're up to date (checked <relative
  time>)` using `formatRelativeArchived`-style wording via a new core
  helper `formatRelativeTime(now, at)` (reuse the existing relative-time
  module; add-if-absent); `Could not check for updates (<error>)`; or
  `Never checked` when `lastCheckedAt` is null.
- The origin action: `homebrew` renders the literal command
  `brew upgrade --cask zeo` in a `<code>` element with a `Copy` button
  (`update.copyUpgradeCommand`); `direct` renders an `Open release page`
  button (`update.openRelease`). Both render a `Dismiss this version` link
  (`update.dismiss`).
- Every control carries a `data-testid` (`update-auto-check`,
  `update-check-now`, `update-status`, `update-copy-command`,
  `update-open-release`, `update-dismiss`).

### 7. Sidebar banner (`apps/ui/src/App.tsx`)

When `state.update.available` is non-null, a `.update-banner` row renders
between `.sidebar__sections` and `.sidebar__footer`: text
`Update available: zeo <version>`, a primary button whose label is
`How to upgrade` for `homebrew` (dispatches `commands.run("settings.openGeneral")`)
or `Open release` for `direct` (dispatches `update.openRelease`), and a `×`
button (`update.dismiss`, `aria-label="Dismiss update"`). `data-testid`
`update-banner`. It is absent otherwise. The banner never steals focus and
adds no accelerator.

### 8. Tests

Unit (`packages/core`, `update.test.ts`):

- `parseVersion`: `v0.0.21`, `0.0.21`, `1.2.3-rc.1` parse; `1.2`, `1.2.3+meta`,
  `latest` return null.
- `compareVersions`: numeric (`0.0.10 > 0.0.9`), prerelease below release,
  equal, unparseable as `0.0.0`.
- `parseLatestRelease`: full object; draft and prerelease return null;
  missing `html_url` null; non-object null.
- `installOrigin`: probe true on the second default path returns
  `homebrew`; all false returns `direct`; custom paths honored.
- `updateDecision`: newer returns the pair; equal and older return null;
  dismissed version returns null; a newer-than-dismissed version returns
  the pair.
- `commands.test.ts`: `update.check` is in `COMMANDS`, enabled in every
  context, in the `view` menu.

Unit (`apps/desktop`): `db.test.ts` migrates version 9 to 10 with
`updateCheckEnabled` defaulting to 1 and the two nullable columns null; the
write/read helpers round-trip; the migration-runner test expects `10`.

e2e (`e2e/tests/update.spec.ts`), using a local fixture server (the
`startFixtureServer` pattern) whose `/latest` route returns a configurable
JSON body and status, launched with `ZEO_E2E=1 ZEO_UPDATE_FEED_URL=<server>/latest ZEO_UPDATE_STARTUP_DELAY_MS=100`:

- Feed `v9.9.9`: the banner appears with `9.9.9`; `update.state()` has
  `available.version === "9.9.9"`, `error === null`, `lastCheckedAt` set.
- Dismiss: the banner disappears; after a debounced save and relaunch on
  the same feed, no banner and `update.state().available === null`.
- Newer than dismissed: feed switches to `v9.9.10`; `update.check()`;
  banner shows `9.9.10`.
- Error: feed returns 500; `update.check()`; `error === "HTTP 500"`,
  `available` unchanged, `checking === false`; the settings status line
  shows the error.
- Prerelease and equal: feed `prerelease: true`, then feed equal to
  `app.getVersion()`; `available` is null both times.
- Disabled: `settings.setUpdateCheckEnabled(false)`, relaunch with a newer
  feed; no banner within 2 s; `update.check()` still finds it (manual
  bypasses the switch).
- Origin: launch with `ZEO_UPDATE_ORIGIN=homebrew`; the banner button
  reads `How to upgrade`, opens settings General, and `Copy` puts
  `brew upgrade --cask zeo` on the clipboard (`clipboard.readText()` via
  `app.evaluate`). With `ZEO_UPDATE_ORIGIN=direct`, `openRelease` calls
  `shell.openExternal` once with the feed's `html_url` (stubbed through
  `app.evaluate` to record the argument instead of opening a browser).

## Constraints

- `packages/core` must not import `electron` or `node:fs`; the Caskroom
  probe and every network call live in `apps/desktop`.
- The check is read-only and anonymous: no token, no telemetry, no
  download. One request per check, at most once per 24 h automatically.
- The check never blocks startup, never shows a modal, and never
  interrupts a page; a failure is a settings status line, not a dialog.
- `ZEO_UPDATE_*` overrides are read only when `ZEO_E2E === "1"`; a
  packaged build ignores them.
- TypeScript strict; no `any`. Nothing under `.github/workflows/` is
  written. Conventional Commits; no AI attribution.
- Versioning: bump root `package.json` patch to the next free version at
  rebase time and add a dated `CHANGELOG.md` section (`### Added`; note the
  schema bump).

## Acceptance criteria

1. A packaged build checks the releases feed 10 s after launch and every
   24 h, and only while the setting is on; a manual check works regardless.
2. A newer non-draft, non-prerelease release shows the sidebar banner and
   the settings status; equal, older, draft, and prerelease do not.
3. Dismissing hides that version until a newer one exists, across
   relaunches.
4. A Homebrew install is told to run `brew upgrade --cask zeo` with a
   working Copy; a direct install gets a button that opens the release
   page in the default browser.
5. Network and HTTP failures surface as the status line's error text, keep
   the previous `available`, and never throw to a renderer.
6. `SCHEMA_VERSION` equals `N`; a version `N-1` database migrates in place
   with the setting defaulting to on.
7. `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm e2e` pass on both
   CI jobs.
