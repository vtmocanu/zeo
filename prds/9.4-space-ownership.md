# PRD 9.4 — Space ownership: tab index, routed commands, composites

## Context

zeo is a keyboard-first, workspace-centric open-source browser for macOS.
Design: `docs/specs/2026-08-30-zeo-v1-design.md`. `SCHEMA_VERSION` is 6 on
main, in `packages/core/src/persistence.ts`; all SQL lives in
`apps/desktop/src/main/db.ts` (`DDL`, `MIGRATION_STEPS` keyed by the version
each step produces, `migrate()`, the singleton `meta` row `id=0`).

This PRD claims an effective schema version `N`, defined as main's
`SCHEMA_VERSION` at rebase time PLUS 1. PRD 6.2 (downloads, PR #119) is open
and claims 7; PRDs 9.5 and 9.6 claim the two versions after this one. If a
lower-numbered claim lands after this PRD, the implementer takes the next
free version at rebase so `N` ends up one more than main's value at that
time. Under no collision `N` is `8`, and every version number this PRD
writes as `8` — the `MIGRATION_STEPS` step key, the `UPDATE meta SET
schemaVersion = 8 WHERE id = 0` statement, the migration-runner test's
expected final version, and any schema-version acceptance criterion — is
that same `8` written as the illustrative value of `N`; one substitution
applies everywhere at once.

`SpaceStore` (`packages/core/src/space-store.ts`) owns one `TabStore` per
space and delegates every tab operation to the ACTIVE space's store. It
does not know which space owns a given tab except by scanning
(`spaceOfTab` iterates every space's `list()` and `archived()`), and three
places in main compensate (#57): each tracked view carries a `spaceId` tag
main keeps in sync by hand; `deleteSpace` in main tears every view down
first and trusts `canDeleteSpace` to mirror `deleteSpace`'s throw
conditions; `updateMeta` fans out to every space and main broadcasts a full
snapshot for every title or favicon event, including events from inactive
spaces whose tabs the snapshot does not contain.

Because delegation targets the active space at execution time, a
context-menu closure or a tab IPC captured against one space and executed
after a space switch throws `Cannot close unknown tab` into a swallowed
`catch` (#56). The renderer composes create-space-then-activate and
create-profile-then-assign as two IPC round trips each; a failure after the
first leaves a stray space or an orphaned profile, and `createProfile`
accepts duplicate names (#69). Double-clicking a space to rename it fires
the single-click activate first (#68). Before profiles landed, every tab ran
on Electron's default session; that data now sits orphaned in the user-data
directory and an upgrading user is logged out everywhere (#61).

This PRD gives `SpaceStore` a tab-to-space index and makes it the single
owner of routing, removes the compensating code in main, adds the two
composites as main-side IPC, dedupes profile names, guards the double-click,
and migrates the default session's cookies once.

## Deliverables

### 1. Core `SpaceStore` ownership index

- Private `ownerByTab: Map<string, string>` (tab id to space id), maintained
  by every path that adds or removes a tab record: `create`, `createInSpace`
  (PRD 9.3; add-if-absent with that contract), `fromPersisted`/`hydrate`,
  `close`, `remove`, `deleteSpace`. `archive`/`restore` do not touch it (an
  archived tab keeps its owner).
- `spaceOfTab(tabId: string): string | null` becomes an O(1) map read with
  the same contract.
- `activeTabIdOf(spaceId: string): string | null` (PRD 9.3; add-if-absent).
- `deleteSpace(id: string): string[]` — validates FIRST (unknown id throws
  `Unknown space: <id>`; last remaining space throws `Cannot delete the last
  remaining space: <id>`) with no mutation on a throw, then removes the
  space, drops its tab ids from the index, re-points the active space when
  needed, and returns the removed tab ids (open then archived, in
  `tabsOfSpace` order). `canDeleteSpace` is deleted; `buildSpaceContextMenu`'s
  `canDelete` input is computed by main as
  `store.spaces().length > 1 && store.spaces().some((s) => s.id === id)`.
- `updateMeta(id, meta): { changed: boolean; inActiveSpace: boolean }` —
  routes to the owning store via the index; an unknown id returns
  `{ changed: false, inActiveSpace: false }` (still never throws).
  `TabStore.updateMeta` returns `boolean`: `true` when at least one of the
  present fields differs from the stored value (`faviconUrl` compared with
  `===`, so `null` to `null` is unchanged).

### 2. Core routed tab operations (#56)

The delegated mutators `close`, `pin`, `unpin`, `reorder`, `archive`,
`restore`, `remove` resolve the owning store through the index instead of
the active space. An id with no owner throws the same message the
`TabStore` would (`Cannot close unknown tab: <id>`, etc.), produced by
`SpaceStore` so the wording is unchanged for every existing test. `activate`
resolves the owner too and throws `Cannot activate a tab outside the active
space: <id>` when the owner is not the active space; main switches space
before activating (§4). The read accessors `list`, `archived`,
`activeTabId`, `activeTab`, and `create` keep their active-space meaning.

### 3. Core profile name uniqueness (#69)

`createProfile(name)` and `renameProfile(id, name)` store `name.trim()` and
throw `Profile name already exists: <name>` when another profile's stored
name equals the trimmed input case-insensitively (`toLowerCase()` on both
sides). A rename to the profile's own name (any case) is accepted. Blank
names keep throwing `Profile name must not be blank`.

### 4. Main: owner-driven views

- `views` becomes `Map<string, WebContentsView>`; `TrackedView` and its
  `spaceId` tag are deleted. Every former `tracked.spaceId` read becomes
  `store.spaceOfTab(tabId)`.
- `deleteSpace(id)` in `spaces.ts`: `const removed = store.deleteSpace(id)`
  (a throw propagates before any teardown); then `destroyView` and
  `forgetTab` (PRD 9.2) for each removed id; then the `wasActive` branch
  (`ensureActiveView`); then `broadcast`.
- `remapSpaceProfile` captures its tab ids as
  `[...views.keys()].filter((id) => store.spaceOfTab(id) === spaceId)`.
- `activateTab(id)` — when `store.spaceOfTab(id)` is a different space than
  the active one, call `switchSpace(owner)` (PRD 9.3; add-if-absent as
  `setActiveSpace` + `ensureActiveView`) before `store.activate(id)`. The
  `IPC.tabsRestore` handler does the same before `store.restore(id)`.
  `performSuggestion`'s `tab` and `archived-tab` cases drop their own
  space-switch lines and rely on this.
- Metadata broadcast gating: the `page-title-updated`, `page-favicon-updated`,
  and `did-navigate` listeners in `createViewFor` read the `updateMeta`
  result; `changed === false` returns before any push; `inActiveSpace ===
  true` calls `broadcast()`; otherwise `noteInactiveChange()` — a new
  `broadcast.ts` export that calls `scheduleSave(store)` and
  `refreshCommandState()` (the catalog contains inactive tabs' titles) and
  pushes no snapshot. The `navigateTab` seed write keeps its unconditional
  `broadcast()` (it targets the active space by contract).

### 5. Main composites (#69)

- `packages/core/src/ipc.ts`: `SpacesApi.createAndActivate(name: string): Promise<Space>`;
  `ProfilesApi.createAndAssign(spaceId: string, name: string): Promise<Profile>`;
  channels `spacesCreateAndActivate: "zeo:spaces:create-and-activate"` and
  `profilesCreateAndAssign: "zeo:profiles:create-and-assign"`. The preload
  maps both.
- `spaces.ts` `createSpaceAndActivate(name)`: `store.createSpace(name)`
  (throws on blank, nothing created), then `switchSpace(space.id)` inside a
  `try`; a throw from `switchSpace` calls `store.deleteSpace(space.id)`
  (never the last space, since the previously active one still exists),
  broadcasts, and rethrows, so the store holds no space the switch did not
  reach. Returns the space. The `space.new` command handler calls it with
  `defaultSpaceName(store.spaces())`.
- `spaces.ts` `createProfileAndAssign(spaceId, name)`: `store.spaceProfileId(spaceId)`
  first (an unknown space throws before any profile exists);
  `store.createProfile(name)` (blank or duplicate throws, nothing created);
  then, inside a `try`, attach the blocker to `persist:<profile.id>` when
  enabled, as `profilesCreate` does, and `remapSpaceProfile(spaceId,
  profile.id)`. A throw from either step calls `store.deleteProfile(profile.id)`
  (unassigned by construction, so the delete cannot throw), broadcasts,
  and rethrows. Returns the profile. Both handlers reject the invoke on a
  throw, and after a rejection `store.spaces()` and `store.profiles()` equal
  their pre-call values.
- `apps/ui/src/App.tsx` `commitEdit`: the `create` branch calls
  `spaces.createAndActivate(name)`; the `new-profile` branch calls
  `profiles.createAndAssign(spaceId, name)`. The separate `spaces.create`,
  `spaces.activate`, `profiles.create`, and `spaces.setProfile` bridge
  methods stay for callers that want the pieces.

### 6. Renderer double-click guard (#68)

The space row's `onClick` no longer activates synchronously. A click with
`event.detail === 1` arms a `setTimeout` of `SPACE_ACTIVATE_DELAY_MS`
(exported from `packages/core/src/layout.ts`, value `250`) that dispatches
the activation; a click with `event.detail > 1` and `onDoubleClick` both
clear that pending timer before doing anything else, and `onDoubleClick`
opens the rename input as today. Unmount clears the timer. Result: a
double-click on an inactive space never activates it (the first click's
activation is cancelled by the second), a single click activates after the
delay, and Escape leaves the active space where it was. The context-menu Rename path is unchanged, so both rename
paths now behave alike.

### 7. Default-session migration (#61)

- Schema `N` (illustrative 8): `meta` gains
  `defaultSessionMigratedAt INTEGER` (nullable). `DDL` adds the column and
  the `create` path's `INSERT INTO meta` sets it to the current time (a
  fresh install has nothing to migrate). `MIGRATION_STEPS[8]` is
  `"ALTER TABLE meta ADD COLUMN defaultSessionMigratedAt INTEGER;" +
  "UPDATE meta SET schemaVersion = 8 WHERE id = 0;"` so an upgraded database
  reads `NULL` exactly once. `SCHEMA_VERSION` becomes `8`.
- `db.ts`: `readDefaultSessionMigratedAt(): number | null` and
  `writeDefaultSessionMigratedAt(at: number): void` (throws when zero rows
  are affected, like `writeSearchEngine`).
- Core `packages/core/src/cookie-url.ts`:
  `cookieUrlFor(cookie: { domain?: string; path?: string; secure?: boolean }): string | null`
  returns `(secure ? "https://" : "http://") + domain-without-leading-dot + (path ?? "/")`,
  or `null` when `domain` is missing or empty. Exported from the index.
- Main `session-migration.ts` `migrateDefaultSession(): Promise<void>`,
  awaited in `whenReady` after `loadStore` and before `createWindow`:
  returns at once when `readDefaultSessionMigratedAt()` is non-null.
  Otherwise reads `session.defaultSession.cookies.get({})`, and for each
  cookie with a non-null `cookieUrlFor` calls
  `session.fromPartition("persist:default").cookies.set({ url, name, value, domain, path, secure, httpOnly, expirationDate, sameSite })`,
  collecting each rejection instead of throwing. When every `cookies.set`
  resolved, it calls
  `session.defaultSession.clearStorageData({ storages: ["cookies", "localstorage", "indexdb", "websql", "serviceworkers", "cachestorage"] })`
  and then `writeDefaultSessionMigratedAt(Date.now())`. When any
  `cookies.set` rejected, it logs the count once, clears nothing, and
  leaves the marker null, so the source session survives intact and the
  next launch retries the whole copy (`cookies.set` on an already-copied
  cookie overwrites the same cookie, so a retry is idempotent). The entire
  body, starting with the `readDefaultSessionMigratedAt()` read, runs inside
  one `try`/`catch`: `readDefaultSessionMigratedAt` is not assumed
  non-throwing (like every `db.ts` accessor it calls `requireDb()`, which
  throws when the database is not open, and its `.get()` can surface a
  database error), so a throw from the `readDefaultSessionMigratedAt`,
  `cookies.get`, `clearStorageData`, or `writeDefaultSessionMigratedAt` call
  is caught and logged once and migrates nothing — a read failure leaves the
  on-disk marker untouched (null for an unmigrated database), the write
  failures likewise leave the marker null. `migrateDefaultSession` resolves
  rather than rejecting, so `whenReady` proceeds to `createWindow` in every
  case, and because the read is the first step every case is retried from the
  top on the next launch. If `clearStorageData` succeeds
  but `writeDefaultSessionMigratedAt` then throws, the source storage is
  already empty while the marker stays null; the next launch re-runs the
  migration over the now-empty source (the copy finds nothing and is
  idempotent regardless, the clear a no-op) and retries the marker write,
  so the migrated state is reached on the first later launch whose marker
  write succeeds.

### 8. Tests

Unit (`packages/core`):

- `space-store.test.ts`: `spaceOfTab` answers after `create`,
  `createInSpace`, `fromPersisted`, `close`, `remove`, `deleteSpace`, and
  survives `archive`/`restore`; `deleteSpace` returns the removed ids
  open-then-archived and throws without mutation on the last space; routed
  `close`/`pin`/`archive`/`restore`/`remove` on a tab in an inactive space
  act on that space's store and leave the active space untouched;
  `activate` of a foreign tab throws the stated message; `updateMeta`
  reports `changed`/`inActiveSpace` for the four combinations and
  `{false,false}` for an unknown id; `createProfile`/`renameProfile`
  reject duplicates case-insensitively and accept a self-rename.
- `tab-store.test.ts`: `updateMeta` returns `false` for an identical
  partial update and `true` when any present field differs.
- `cookie-url.test.ts`: secure/insecure scheme, leading-dot domain
  stripped, missing path defaults to `/`, missing domain returns `null`.

Unit (`apps/desktop`): `db.test.ts` migrates a version-7 database to 8 with
`defaultSessionMigratedAt` null, and a fresh `create` sets it non-null; the
migration-runner test's expected final version is `8`.
`session-migration.test.ts` drives `migrateDefaultSession` with injected
fake sessions: all cookies copy, storage is cleared, marker written;
`readDefaultSessionMigratedAt` throws — the error is logged once,
`migrateDefaultSession` resolves without reading cookies or clearing
storage, and a later call whose read returns null migrates normally; one
`cookies.set` rejects, nothing is cleared, marker stays null, and a second
call copies again and completes; `cookies.get` rejects, marker stays null;
`writeDefaultSessionMigratedAt` throws after the clear succeeded — the
error is logged, `migrateDefaultSession` resolves (does not reject) and the
marker stays null, and a second call over the now-empty source copies
nothing, retries the marker write, and completes.
`spaces.test.ts` drives the composites with an injected `switchSpace` /
`remapSpaceProfile` that throws: the call rejects, and `store.spaces()` /
`store.profiles()` equal their pre-call values.

e2e:

- Composite create: the `+` space button with a name creates one space and
  activates it in one `stateChange` sequence; `spaces.createAndActivate("")`
  over the bridge rejects and the space count is unchanged.
- Composite profile: the New profile entry assigns the created profile;
  `profiles.createAndAssign(spaceId, "Default")` rejects with the duplicate
  message and `profiles` is unchanged; `createAndAssign("<unknown>", "X")`
  rejects and no profile is created.
- Double-click: a double-click on an inactive space row opens the rename
  input, the active space id is unchanged after `SPACE_ACTIVATE_DELAY_MS`
  plus a margin, and a single click activates the space.
- Foreign close: open the context menu on a tab in space A, switch to space
  B over the bridge, invoke `tabs.close(idInA)`; the tab in A is closed and
  B is unchanged.
- Foreign activate: `tabs.activate(idInA)` while B is active resolves, A
  becomes the active space, and the tab's view is visible.
- Double-click rename: double-click an inactive space; the rename input
  opens and `activeSpaceId` is unchanged; Escape restores the row with the
  same active space.
- Inactive-space metadata: navigate a tab in space A to a titled fixture
  page while B is active; the sidebar receives no `stateChange` for the
  title (count broadcasts through a bridge listener over a 1 s window), the
  command bar lists the new title, and after a debounced save the title is
  persisted.

## Constraints

- `packages/core` must not import `electron`; the cookie type in
  `cookie-url.ts` is a structural minimum, not Electron's `Cookie`.
- Error message strings for every pre-existing throw are unchanged.
- The routed operations never switch the active space inside `SpaceStore`;
  only main decides to switch (through `switchSpace`).
- The default-session migration runs at most once per user-data directory
  and never on a fresh install.
- TypeScript strict; no `any`. Nothing under `.github/workflows/` is
  written. Conventional Commits; no AI attribution.
- Versioning: bump root `package.json` patch to the next free version at
  rebase time and add a dated `CHANGELOG.md` section (`### Fixed` for #56,
  #68, #69; `### Changed` for the schema bump and the one-time session
  migration).

## Acceptance criteria

1. `SpaceStore` exposes `spaceOfTab` in O(1), `deleteSpace` returns the
   removed tab ids, and `canDeleteSpace` no longer exists anywhere in the
   tree.
2. `apps/desktop/src/main/` contains no per-view `spaceId` tag; every
   owner lookup goes through `store.spaceOfTab`.
3. A tab command on a tab in an inactive space acts on that tab; a foreign
   `activate` switches the space first.
4. A title/favicon event for an inactive-space tab pushes no
   `stateChange`, still schedules a save, and still refreshes the command
   catalog; an unchanged metadata event pushes nothing.
5. `spaces.createAndActivate` and `profiles.createAndAssign` exist on the
   bridge, the renderer uses them, and no failure path can leave a created
   but unactivated space or an unassigned profile.
6. Two profiles cannot share a name modulo case and whitespace.
7. Double-clicking a space opens rename without activating it; a single
   click activates it within `SPACE_ACTIVATE_DELAY_MS`.
8. Upgrading a version-7 database migrates the default session's cookies
   into `persist:default` once, clears the default session's storage, and
   stamps `meta.defaultSessionMigratedAt`; a launch on which any cookie
   fails to copy clears nothing, stamps nothing, and retries next launch;
   a marker-write failure after the clear never fails startup and is
   retried on the next launch (which finds nothing to copy) until it
   succeeds; a fresh install stamps it at creation and copies nothing.
9. `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm e2e` pass on both
   CI jobs.
