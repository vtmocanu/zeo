# PRD 10.3 — Space themes

## Context

zeo is a keyboard-first, workspace-centric open-source browser for macOS. Epic 10's design book is
`docs/design/README.md` (authoritative) with the interactive `docs/design/design-book.html`; §3, §6
and §10 below refer to the README. This PRD assumes PRDs 10.1 and 10.2 have merged.

PRD 10.1 shipped the theme function in `@zeo/core` (`themeTokens`, `themeReport`, `normalizeTheme`,
`SpaceTheme`, `SpaceHue`, `SPACE_HUES`, `HUE_DEFINITIONS`, `MIGRATION_HUE_ORDER`, `Appearance`,
`oklchToRgb`, `toHex`) and `apps/ui/src/theme.ts` (`useThemeTokens`, `useAppearance`), but every
renderer still calls `useThemeTokens(null)`. PRD 10.2 made the window frameless: the sidebar renderer
paints a full-window `.window-tint` layer from `--tint` / `--tint-opacity`, and `TabsState.chrome:
ChromeState` plus `cardLeft(chrome)` exist in `packages/core/src/chrome.ts`.

Today a space is `{ id, name, profileId, createdAt }` (`packages/core/src/space.ts:9-19`).
`SpaceStore` keeps spaces in creation order and serializes them through `toPersisted` /
`fromPersisted` (`packages/core/src/space-store.ts:618-760`) into `SpaceRow`
(`packages/core/src/persistence.ts:45-52`). SQL lives in `apps/desktop/src/main/db.ts`: spaces DDL
:94-98, `MIGRATION_STEPS` :157-188, `readState` :1049-1074, `writeState` :1084-1137. The space
context menu is described by `buildSpaceContextMenu` (`packages/core/src/space-menu.ts:23-44`),
popped by `showSpaceContextMenu` (`apps/desktop/src/main/spaces.ts:129-206`), and renderer-side
actions travel as `SpaceMenuAction` (`packages/core/src/ipc.ts:163-165`) on `IPC.spaceMenuAction`.
The switcher is `nav.space-switcher` of `SpaceItem` buttons (`apps/ui/src/App.tsx:505-553`,
`:850-904`).

This PRD claims an effective schema version `N` = main's `SCHEMA_VERSION` at rebase time + 1 (PRD
10.2 claims the version before it). Under no collision `N` is `14`; every `14` below (the
`MIGRATION_STEPS` key, the `UPDATE meta SET schemaVersion = 14` statement, the migration tests'
expected version, the acceptance criterion) is the illustrative value of `N`, and `13` is `N − 1`.
One substitution applies everywhere at once.

Scope: a nullable theme on every space, persisted as JSON and migrated by position (§3, §10); a
bridge call to change it; every renderer re-tints from the active space on each broadcast; "Edit
Theme…" in the space context menu opens the theme picker in the sidebar (§6); each switcher item
shows its theme color. The re-tint is instant (PRD 10.7 animates it) and the switcher keeps its
layout (PRD 10.4 turns it into dots).

## Deliverables

### 1. Core model `packages/core/src/space.ts`, `packages/core/src/space-theme.ts`, `packages/core/src/theme.ts`

```ts
import type { SpaceTheme } from "./theme.js";
export interface Space { id: string; name: string; profileId: string; createdAt: number; theme: SpaceTheme | null }
```

New module `packages/core/src/space-theme.ts`, exported from the barrel:

```ts
export const SPACE_DOT_LIGHTNESS = 0.66;
export const SPACE_DOT_CHROMA_BOOST = 0.02;
export const GRADIENT_SECOND_STOP_OFFSET = 3;

export function defaultSpaceTheme(spaceCount: number): SpaceTheme;
export function encodeSpaceTheme(theme: SpaceTheme | null): string | null;
export function decodeSpaceTheme(text: string | null): SpaceTheme | null;
export function themesEqual(a: SpaceTheme | null, b: SpaceTheme | null): boolean;
export function cloneTheme(theme: SpaceTheme | null): SpaceTheme | null;
export function activeSpaceTheme(state: SpacesState | null): SpaceTheme | null;
export function hueSwatchColor(hue: SpaceHue): string;
export function spaceDotColor(theme: SpaceTheme | null): string | null;

export type ThemeKind = "solid" | "gradient";
export function pickerSetKind(theme: SpaceTheme | null, kind: ThemeKind): SpaceTheme;
export function pickerSelectHue(theme: SpaceTheme | null, stopIndex: 0 | 1, hue: SpaceHue): SpaceTheme;
export function pickerSetIntensity(theme: SpaceTheme | null, percent: number): SpaceTheme;
```

- `defaultSpaceTheme(n)` = `{ stops: [MIGRATION_HUE_ORDER[n % 10]], intensity: 1 }`.
- `encodeSpaceTheme`: `null` → `null`, else `JSON.stringify({ stops, intensity })`.
  `decodeSpaceTheme`: `null` for `null`, for text `JSON.parse` rejects (caught, never thrown) and for
  anything `normalizeTheme` rejects; otherwise the normalized theme (stored intensity 3 reads as 1).
- `themesEqual`: both null, or equal stop count, hues in order and intensity. `cloneTheme` copies
  `stops`. `activeSpaceTheme`: the theme of the space whose id is `state.activeSpaceId`; `null` for a
  null state or a missing space.
- `hueSwatchColor(h)` = `toHex(oklchToRgb(SPACE_DOT_LIGHTNESS, HUE_DEFINITIONS[h].c +
  SPACE_DOT_CHROMA_BOOST, HUE_DEFINITIONS[h].h))`, the design book's swatch color in both appearances.
  `spaceDotColor`: `null` for a null theme or intensity 0; one stop → its swatch color; two stops →
  `linear-gradient(135deg, <swatch1>, <swatch2>)`.
- Picker transitions are pure, never return `null`, and treat a `null` input as
  `{ stops: ["iris"], intensity: 0 }`:
  - `pickerSetKind(t, "solid")` keeps `stops[0]`; `"gradient"` on one stop appends
    `SPACE_HUES[(SPACE_HUES.indexOf(stops[0]) + GRADIENT_SECOND_STOP_OFFSET) % 10]`; same kind is a
    no-op. Intensity 0 becomes 1.
  - `pickerSelectHue(t, i, hue)` replaces `stops[min(i, stops.length − 1)]`; intensity 0 becomes 1,
    so picking a color on an untinted space shows it.
  - `pickerSetIntensity(t, p)` sets `intensity = clamp(round(p / 5) × 5, 0, 100) / 100`.

`packages/core/src/theme.ts`:

- Accent hue: `themeTokens` and `themeReport` take the accent hue from `theme.stops[0]` for every
  non-null theme, intensity 0 included. Intensity 0 removes the tint only; the accent keeps the first
  stop's hue. Only a `null` theme uses the iris accent.
- `ThemeReport` gains `inkOnAccentContrast: number`: `contrastRatio` of `--ink-on-accent` over
  `--accent`, both taken as the rounded channels `toHex` emits. It is shown nowhere else: no picker
  chip, `data-*` attribute or token carries it.
- Ink-on-accent floor: `themeTokens` guarantees `inkOnAccentContrast ≥ 4.5` (WCAG AA) for every hue,
  stop combination, intensity and appearance. After the ink on accent is chosen, while the ratio is
  below 4.5 the accent's OKLCH lightness moves by 0.02 away from the ink (−0.02 when the ink is white,
  +0.02 when it is the dark ink); hue, chroma and the chosen ink stay unchanged. `accentContrast` is
  measured on the final accent. Equal input returns equal output.

### 2. Store and codec

`packages/core/src/space-store.ts`:

- `insertSpace` sets `theme: defaultSpaceTheme(this.order.length)`, so the seeded "Personal" space is
  iris and a space created while k spaces exist gets `MIGRATION_HUE_ORDER[k % 10]` (count, not
  history, decides; repeats are allowed).
- `spaceTheme(id: string): SpaceTheme | null` and `setSpaceTheme(id: string, theme: SpaceTheme |
  null): void`. Both throw `Unknown space: <id>`; `setSpaceTheme` throws `Invalid space theme` when
  a non-null theme fails `normalizeTheme` and stores the normalized value.
- `spaces()` and `activeSpace` return copies with `cloneTheme`d themes.
- `toPersisted` writes `theme: encodeSpaceTheme(space.theme)`; `fromPersisted` reads
  `theme: decodeSpaceTheme(row.theme)`.

`packages/core/src/persistence.ts`: `SpaceRow` gains `theme: string | null` (JSON text: the codec
parses, the desktop layer only moves text). `SCHEMA_VERSION` becomes `14`. Test fixtures that build
`SpaceRow` or `Space` literals (`persistence.test.ts`, `space-store.test.ts`, `space-name.test.ts`,
desktop tests) add `theme`.

### 3. Schema `N` (illustrative 14) in `apps/desktop/src/main/db.ts`

`DDL`'s spaces table gains `theme TEXT` after `position`. New step, `MIGRATION_STEPS[14] =
SPACE_THEME_MIGRATION`:

```ts
const SPACE_THEME_MIGRATION =
  "ALTER TABLE spaces ADD COLUMN theme TEXT;" +
  "UPDATE spaces SET theme = json_object('stops', json_array(json_extract('" +
  JSON.stringify(MIGRATION_HUE_ORDER) + "', '$[' || ((SELECT COUNT(*) FROM spaces AS prior " +
  "WHERE prior.position < spaces.position OR (prior.position = spaces.position AND prior.id < spaces.id)) % " +
  MIGRATION_HUE_ORDER.length + ") || ']')), 'intensity', 1);" +
  "UPDATE meta SET schemaVersion = 14 WHERE id = 0;";
```

The subquery is each row's rank in `position` order (gaps tolerated, ties broken by id), so the rows
receive iris, rose, teal, amber, violet, mint, coral, sky, orchid, lime, repeating, stored as text
such as `{"stops":["teal"],"intensity":1}`. `readState` selects `theme`; `writeState`'s space upsert
inserts `@theme` and adds `theme=excluded.theme` to its `ON CONFLICT` list. A fresh database runs the
full DDL, never this step, and its seeded store supplies iris.

### 4. Bridge, channel and main handler

`packages/core/src/ipc.ts`: `SpacesApi.setTheme(id: string, theme: SpaceTheme | null):
Promise<void>`; `IPC.spacesSetTheme: "zeo:spaces:set-theme"`; `SpaceMenuAction` gains
`{ action: "edit-theme"; spaceId: string }`. The union already discriminates on `action` with
kebab-case values (`App.tsx:655-661`, `apps/desktop/src/main/commands.ts:115-119`), so the new
variant keeps that shape. Preload: `setTheme: (id, theme) => ipcRenderer.invoke(IPC.spacesSetTheme,
id, theme)`.

`apps/desktop/src/main/spaces.ts` exports `setSpaceTheme(id: unknown, theme: unknown): void` and
registers `ipcMain.handle(IPC.spacesSetTheme, (_event, id: unknown, theme: unknown): void =>
setSpaceTheme(id, theme))`:

1. `typeof id !== "string"` → `TypeError("spaces.setTheme: id must be a string")`.
2. `next = theme === null ? null : normalizeTheme(theme)`; non-null input normalizing to `null` →
   `TypeError("spaces.setTheme: invalid theme")`.
3. `runtime.store.spaceTheme(id)` (throws on an unknown id); `themesEqual(current, next)` returns
   without a broadcast.
4. `runtime.store.setSpaceTheme(id, next)`, then `broadcast()`, which schedules the debounced save.

Any throw rejects the invoke with nothing changed.

- `buildSpaceContextMenu` inserts `{ id: "edit-theme", label: "Edit Theme…", enabled: true }`
  (U+2026) right after `rename`: ids read `["rename", "edit-theme", "profile"]` for the last space
  and `["rename", "edit-theme", "delete", "profile"]` otherwise.
- `showSpaceContextMenu` handles `"edit-theme"` before its profile fallthrough branch: it sends
  `{ action: "edit-theme", spaceId: id }` on `IPC.spaceMenuAction` to `runtime.win.webContents`, then

- `packages/core/src/commands.ts` appends `{ id: "space.editTheme", title: "Edit Space Theme…",

  "spaces" }` last to `COMMANDS` (after 10.2's `view.toggleSidebar`), always enabled; its handler sends the same action for `runtime.store.activeSpaceId`
  and focuses the main window's webContents, like `space.rename`.

### 6. Theme picker `apps/ui/src/ThemePicker.tsx`, `apps/ui/src/styles/theme-picker.css`

```ts
export interface ThemePickerProps {
  space: Space;          // the edited space, not necessarily the active one
  sidebarWidth: number;  // state.chrome.sidebarWidth
  onChange(theme: SpaceTheme): void;
  onClose(): void;
}
export function ThemePicker(props: ThemePickerProps): ReactElement;
```

Structure, top to bottom (every `data-testid` here is new):

- Root `div.theme-picker`, `role="dialog"`, `aria-label="<space name> theme"`,
  `data-testid="theme-picker"`, `data-space-id`; `position: fixed; left: 8px; bottom: 8px`, inline
  `width: sidebarWidth − 16` px, so it stays inside the sidebar renderer left of the content card.
  Padding and gap `--space-5`, `--surface-popover`, `--shadow-popover`, `--radius-card`, text
  `--ink-popover`. Header `<space name> theme` in `--text-md`.
- Kind segment (`role="group"`, `aria-label="Theme kind"`): Solid (`theme-kind-solid`) and Gradient
  (`theme-kind-gradient`) buttons with `aria-pressed`; track `--popover-well`, pressed segment
  `--control-raised`.
- Stop segment, two stops only (`role="group"`, `aria-label="Gradient stop"`): `Color 1` / `Color 2`
  (`theme-stop`, `data-stop-index` 0 | 1), each with a 10 px dot of its swatch color. It sets a local
  `stopIndex`; switching to gradient selects stop 1, to solid resets 0.
- Swatches: a five-column grid of ten 28 px round buttons in `SPACE_HUES` order (`theme-swatch`,
  `data-hue`, `aria-label` and `title` = `HUE_DEFINITIONS[h].label`, `aria-pressed` for the selected
  stop's hue on a non-null theme). Background `var(--swatch)`, with `--swatch` set inline to
  `hueSwatchColor(h)`; pressed ring `box-shadow: 0 0 0 2px var(--surface-popover), 0 0 0 4px
  var(--ink-popover)`. Arrow Left/Right move focus by one, Up/Down by five, wrapping.
- Intensity: `<label>Intensity</label>`, `<output data-testid="theme-intensity-value">NN%</output>`,
  `<input type="range" min="0" max="100" step="5" data-testid="theme-intensity">` with
  `accent-color: var(--accent)`.
- Contrast readout: two 52 px chips side by side (`theme-contrast`, `data-appearance` `light` |
  `dark`, radius `--radius-tab`). With `r = themeReport(draft, appearance)`: background
  `var(--chip-ground)` = `toHex(r.grounds[0])` or `linear-gradient(160deg, <g1>, <g2>)`; line one
  `Aa` in `var(--chip-ink)` (`toHex(r.ink)`) with `Light` / `Dark` right-aligned; line two
  `<inkContrast.toFixed(1)> · <inkSecondaryContrast.toFixed(1)>` in `var(--chip-ink-secondary)`.
  `aria-label` e.g. `Light: text 12.8 to 1, secondary 5.1 to 1`; `data-ink-contrast` and
  `data-secondary-contrast` hold the values to two decimals.

Behavior:

- A local `draft: SpaceTheme | null` starts from `space.theme`. Kind, stop, swatch and slider
  `input` events compute the next draft with the §1 `picker*` functions, store it and call
  `onChange(next)` at once (live apply; an active space re-tints on the next broadcast). A broadcast
  theme that differs from the last value the picker sent replaces the draft.
- A `null` draft shows Solid pressed, no swatch pressed and the slider at 0.
- On open, focus moves to the pressed kind button. Escape closes and focuses the space's
  `space-item`.
- It also closes on a `pointerdown` outside it, on the sidebar window's `blur` (focus went to a page
  view or another window), when the edited space leaves `state.spaces`, when `state.activeSpaceId`
  changes, and when the sidebar hides (`cardLeft(state.chrome) !== state.chrome.sidebarWidth`).

`App.tsx` keeps `themeEditSpaceId: string | null`. The `onSpaceMenuAction` listener sets it for
`"edit-theme"` after cancelling any inline edit; its `else` branch becomes an explicit
`"new-profile"` check. `onChange` calls `window.zeo.spaces.setTheme(space.id, theme)` and swallows
rejections like the rename path. The picker renders inside the `<aside>`, right before 10.2's
`SidebarResizeHandle` (which stays the last child).
`styles/theme-picker.css` holds the picker rules and is imported by `styles/index.css`.

### 7. Re-tint every surface

- `App`, `Settings` and `QuickBrowse`: `useThemeTokens(activeSpaceTheme(state))` (a `null` state
  gives the null theme).
- `Overlay` holds no `TabsState`. `apps/ui/src/theme.ts` adds `useActiveSpaceTheme(): SpaceTheme |
  null`: it subscribes to `onStateChange`, seeds from `tabs.list()` unless a broadcast already
  arrived (the pattern at `QuickBrowse.tsx:37-52`) and returns `activeSpaceTheme(state)`. `Overlay`
  calls `useThemeTokens(useActiveSpaceTheme())`.
- `Divider` keeps the stylesheet defaults.

Tokens apply in a layout effect on each broadcast, so a space switch re-tints `.window-tint` and the
accent in the same frame as the tab list, with no transition.

### 8. Space-switcher items show their theme

`SpaceItem` renders, before the name, `<span className="space-item__dot" data-testid="space-dot"
data-hue={theme === null ? "none" : theme.stops.join("+")} aria-hidden="true" style={{
"--space-dot": spaceDotColor(theme) ?? undefined } as CSSProperties} />`. In
`styles/space-switcher.css`, `.space-item` becomes `inline-flex` with `gap: var(--space-3)` and
`.space-item__dot { width: 8px; height: 8px; border-radius: 50%; flex: none; background:
var(--space-dot, var(--ink-secondary)); }`. The button text stays the space name; `space-item`,
`data-space-id`, `aria-current`, click, double-click rename and the context menu are unchanged. PRD
10.4 replaces the switcher with dots and reuses `spaceDotColor`.

## Constraints

- `packages/core` stays free of `electron`, DOM and `node:*` imports.
- Plain CSS with custom-property tokens; no literal colors outside `tokens.css`
  (`scripts/check-css-tokens.mjs` passes). Core-computed colors reach CSS only as inline custom
  properties.
- No new runtime dependencies; `node:sqlite` (Node 24 built-in) is used only by the e2e spec.
- The picker lives in the sidebar renderer: no new WebContentsView, window or native popover.
- Keep every existing `data-testid`, ARIA role and e2e-asserted class name; the only migrated
  assertions are the two context-menu id lists and the commands-mode id list.
- `apps/desktop/src/main` modules stay under the 800-line `max-lines` ceiling.
- TypeScript strict; no `any`. Nothing under `.github/workflows/` is written. Conventional Commits;
  no AI attribution.
- Versioning: bump the root `package.json` patch to the next free version at rebase time and add a
  dated `CHANGELOG.md` section (`### Added`: space themes and picker; `### Changed`: schema version
  `N`, existing spaces receive hues by position).
- Leave `prds/` and `docs/design/` untouched.

## Acceptance criteria

1. `Space.theme` exists; a fresh install's Personal space is iris at intensity 1 and each new space
   takes `MIGRATION_HUE_ORDER[spaceCount % 10]`.
2. `SCHEMA_VERSION` equals `N`; a version `N − 1` database migrates in place and its spaces receive
   iris, rose, teal, amber, violet, mint, coral, sky, orchid, lime by position, repeating, at
   intensity 1.
3. `window.zeo.spaces.setTheme` validates through `normalizeTheme`, rejects invalid input without
   side effects, and a set theme survives relaunch.
4. Switching spaces re-tints the sidebar, settings, overlay and quick-browse surfaces instantly; their
   computed tokens equal `themeTokens(activeSpace.theme, appearance)`.
5. "Edit Theme…" in the space context menu and the `space.editTheme` command open the picker inside
   the sidebar; solid/gradient, stop selection, ten swatches, the 0–100 intensity slider in steps of
   5 and the two-appearance contrast readout work and apply live.
6. Each space-switcher item shows a dot in its theme color, neutral when untinted.
7. A non-null theme at intensity 0 has no tint and keeps the accent of its first stop; only a `null`
   theme has the iris accent.
8. `themeReport(theme, appearance).inkOnAccentContrast ≥ 4.5` for every hue, two-stop pair,
   intensity 0, 0.25, 0.5, 0.75 and 1, and appearance.
9. `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` and `pnpm e2e` pass on both CI jobs.
