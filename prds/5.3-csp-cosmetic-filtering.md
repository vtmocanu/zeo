# PRD 5.3 — CSP injection and cosmetic filtering

## Context

zeo is a keyboard-first, workspace-centric open-source browser for macOS.
Design: `docs/specs/2026-08-30-zeo-v1-design.md`. Requires PRD 5.1
(`prds/done/5.1-content-blocking-engine.md`) merged: `@zeo/adblock` owns
one long-lived `Blocker` whose `attach` registers `onBeforeRequest` on a
profile session and delegates every callback to the current engine, so a
list refresh swaps the engine without re-registering session hooks.

Network blocking is the only layer wired today. Two layers that the uBlock
Origin lists rely on are parsed by the engine but never applied: `$csp`
rules, which need an `onHeadersReceived` handler rewriting the response's
`Content-Security-Policy`, and cosmetic filters (`##.selector` element
hiding and `##+js(...)` scriptlets), which need a preload script in every
browsing frame and an IPC round trip so the engine can push CSS and
scriptlets into the page. Without them, sites whose ads are hidden rather
than blocked show empty ad slots and anti-adblock scripts run unopposed.
This PRD wires both layers inside `packages/adblock` with the same
current-engine delegation as `onBeforeRequest`. Per-site allowlisting and
the blocking settings surface remain PRD 5.2. Feature #85, follow-up to
issue #83.

## Deliverables

### 1. Session hooks (`packages/adblock`)

- `attach(session)` registers, on an unattached session, in this order:
  (1) `session.webRequest.onBeforeRequest({ urls: ["<all_urls>"] }, ...)`
  as today; (2) `session.webRequest.onHeadersReceived({ urls:
  ["<all_urls>"] }, ...)` whose callback calls
  `this.engine.onHeadersReceived(details, callback)`; (3)
  `session.registerPreloadScript({ type: "frame", filePath: preloadPath
  })`, keeping the returned id per session. Every callback reads
  `this.engine` at call time, so a refresh keeps working for all three
  without touching the session. Attach stays idempotent per session: a
  second call is a no-op and never registers a second preload script.
- `detach(session)` removes exactly what attach installed, in reverse
  order: unregisters the stored preload script id, passes `null` to
  `onHeadersReceived`, then `null` to `onBeforeRequest`. It never touches a
  session that is not attached, and detaching one session leaves every
  other attached session's hooks and preload in place.
- Electron allows one listener per `webRequest` event per session. The
  wrapper is the sole owner of `onBeforeRequest` and `onHeadersReceived`
  on every attached session; that ownership is documented on `attach`, and
  `apps/desktop` registers no other listener for those events on profile
  sessions. There is no Electron API to detect a foreign listener, so this
  is a contract, not a runtime check.
- The CSP rewrite is the library's: for `mainFrame` and `subFrame`
  responses whose request matches a `$csp` filter, the response's existing
  `Content-Security-Policy` values are merged with the filter's directives
  into one header; any other response passes through with an empty
  callback. No `BlockingState` counter changes: neither a CSP rewrite nor a
  hidden element is a blocked request, so `blockedByTab` and
  `blockedUnattributed` count network blocks only, exactly as in PRD 5.1.

### 2. Cosmetic injection channel

- The preload script is the library's `@ghostery/adblocker-electron-preload`
  entry, resolved once at wrapper load with `createRequire(import.meta.url)
  .resolve("@ghostery/adblocker-electron-preload")`; the package becomes a
  direct dependency of `@zeo/adblock` so pnpm's strict layout can resolve
  it. The resolved path is the `preloadPath` used by attach. It runs in the
  frame's isolated world under the default `sandbox: true` and
  `contextIsolation: true` of tab views, and exposes nothing to page
  scripts.
- The preload talks to main over the library's two channels,
  `@ghostery/adblocker/inject-cosmetic-filters` (`(url, dom?) =>
  Promise<void>`; the first call per document carries no `dom`, later calls
  carry observed classes, ids, and hrefs) and
  `@ghostery/adblocker/is-mutation-observer-enabled` (`() =>
  Promise<boolean>`). The wrapper registers one `ipcMain.handle` per channel
  when the first session is attached and removes both when the last session
  is detached, so the process never holds two handlers for one channel;
  `attachedSessions().length` is the reference count. At most one `Blocker`
  may hold attached sessions at a time; `apps/desktop` already detaches the
  outgoing blocker before dropping it.
- Handler contract, both channels: the handler resolves without doing
  anything when `event.sender.session` is not an attached session (a frame
  in the sidebar or overlay renderer, or a session detached between the
  preload's send and the handler's run). Otherwise it delegates to
  `this.engine.onInjectCosmeticFilters(event, url, dom)` and
  `this.engine.onIsMutationObserverEnabled(event)` respectively, so styles
  are inserted with `insertCSS(styles, { cssOrigin: "user" })` and
  scriptlets run with `executeJavaScript(script, true)` against the sending
  frame, using whatever engine is current at that moment.
- Ordering is documented, not changed: a frame loaded before attach (or
  before a refresh) keeps the CSS and scriptlets it already received until
  its next navigation; a frame loaded after detach receives nothing; a
  frame loaded while attached receives the first injection during document
  start and DOM-driven updates as the page mutates.
- Electron is reached through a seam so the package's unit tests still run
  under plain Vitest: `BlockerIpc { handle(channel, listener): void;
  removeHandler(channel): void }`. Production resolves it lazily from
  Electron's `ipcMain` on the first attach (never at module load).
  `CreateBlockerOptions` and `createBlockerFromFilters` accept it under an
  optional `internals?: { ipc?: BlockerIpc; preloadPath?: string }`
  argument; `createBlockerFromFilters(filters, listVersion?, internals?)`
  keeps its two existing positional parameters unchanged.

### 3. Main process (`apps/desktop`)

- No new wiring: every existing attach and detach call site (startup gate,
  `setEnabled`, profile creation, profile remap, the cap-lost swap, and the
  drop-old-blocker cleanup) gets CSP and cosmetic filtering through the
  wrapper. `setEnabled(false)` therefore also stops injection for frames
  loaded afterwards, and `setEnabled(true)` restores it, with the same
  ordering and rollback contract as PRD 5.1 §2.
- The `ZEO_ADBLOCK_FILTERS` fixture path builds the engine with
  `ElectronBlocker.parse` as today; cosmetic and `$csp` filters in the
  fixture file are honoured because the library's default config loads
  cosmetic filters. Nothing else in main changes.

### 4. Tests

- Unit (`packages/adblock`, fake session extended with
  `onHeadersReceived`, `registerPreloadScript` returning a fresh id, and
  `unregisterPreloadScript`; fake `BlockerIpc` recording handled channels):
  attach registers both request hooks, one preload script, and both IPC
  handlers; a second attach registers nothing more; attaching a second
  session registers its hooks and preload but no second IPC handler;
  detaching one of two sessions removes only its hooks and preload and
  keeps the handlers; detaching the last session removes both handlers;
  detaching an unattached session is a no-op; the `onHeadersReceived`
  callback rewrites the CSP header of a `mainFrame` response matching a
  `$csp` filter and passes an unmatched response through; after `refresh`
  the same registered callbacks use the new engine (a `$csp` rule present
  only in the new lists takes effect with no re-attach); the IPC handler
  ignores a sender whose session is not attached and delegates for an
  attached one.
- e2e (`e2e/tests/blocking.spec.ts`, same loopback fixture server, offline):
  the server also serves `/cosmetic.html`, whose body holds
  `<div class="zeo-ad-slot">` above a visible marker, and `/csp.html`,
  whose body holds an inline `<script>` that sets `document.title` to
  `scripted` and a `<p id="marker">`. The fixture list gains the generic
  element-hiding rule `##.zeo-ad-slot` and the rule
  `/csp.html$csp=script-src 'none'`. Assertions:
  - After loading `/cosmetic.html` in a tab, the ad slot's computed
    `display` becomes `none` (polled, since injection follows document
    start) while the marker stays visible; `blockedByTab` for the tab has
    no entry and `blockedUnattributed` is 0.
  - After loading `/csp.html`, `document.title` is not `scripted`, the
    marker rendered, and the main response the server sent carried no
    `Content-Security-Policy` of its own (so the block came from the
    injected header alone).
  - `blocking.setEnabled(false)`, then reload both pages in new tabs: the
    ad slot is displayed and the title reads `scripted`. `setEnabled(true)`
    and reload again: both effects return without a relaunch.
  - A second space on a distinct profile loading `/cosmetic.html` hides
    the slot too.
  - The sidebar's own document is unaffected: after the above, the
    sidebar renderer still has no element with class `zeo-ad-slot` hidden
    by user CSS (guard that the preload never reaches the default
    session).

## Constraints

- Only `packages/adblock` imports the adblocker library and its preload
  package; `packages/core` stays Electron-free and is untouched by this
  PRD except where a shared type is needed (none expected).
- No per-site allowlist, no settings UI, no filter-list management UI.
- No new IPC channel in `packages/core/src/ipc.ts`: the cosmetic channels
  are the library's own, spoken only between its preload and the wrapper.
- Do not create or modify anything under `.github/workflows/`; root script
  names stay unchanged. CI stays offline-deterministic.
- Version bump to 0.0.14 with a dated `CHANGELOG.md` section.

## Acceptance criteria

- `pnpm lint && pnpm typecheck && pnpm build && pnpm test && pnpm e2e` green.
- In the running app with the default lists: a news site that reserves ad
  slots shows no empty placeholders where the list hides them; toggling
  content blocking off and reloading brings the placeholders back.
- CI green on the merge request branch.
