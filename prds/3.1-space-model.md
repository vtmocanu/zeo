# PRD 3.1 — Space model and switching

## Context

zeo is a keyboard-first, workspace-centric open-source browser for macOS.
Design: `docs/specs/2026-08-30-zeo-v1-design.md`. Requires PRD 2.4
(`prds/done/2.4-tab-archiving.md`) merged: the flat tab model with pinning,
archiving, and the archived view is complete.

A space is a named workspace with its own tab set. This PRD introduces the
space domain model and space switching end to end, with no space UI yet: the
renderer keeps rendering the active space's tabs exactly as today, and
switching is driven over the IPC bridge (exercised by e2e). The space switcher
UI lands in PRD 3.3.

## Deliverables

### 1. Space model (core)

- `Space` type: `id`, `name`, `profileId`, `createdAt`. `profileId` is a plain
  string reference for now (the profile entity lands in PRD 3.2); every space
  created without an explicit profile references `"default"`.
- A store in `packages/core` that owns the spaces and their tab sets:
  - Always at least one space; a fresh store seeds one named "Personal".
  - `createSpace(name)`, `renameSpace(id, name)`, `deleteSpace(id)`,
    `setActiveSpace(id)`, plus read access to the space list and active space.
  - Each space has its own tab set with the full PRD 2.x behavior (create,
    close, activate, pin, reorder, archive, restore, remove, archiveIdle) and
    its own active tab.
  - Deleting a space drops its tabs; deleting the last remaining space throws;
    deleting the active space activates another space.
  - All existing tab operations act on the active space's tab set.
- Unit tests: seeding, create/rename/delete rules, per-space tab isolation
  (tabs created in one space never appear in another), active-space switching
  preserves each space's own active tab, idle sweep covers every space's tabs.

### 2. IPC contract (core)

- Snapshot gains the space dimension: the broadcast state carries the space
  list, the active space id, and the active space's `tabs`/`activeTabId`/
  `archived` in the existing shape, so current renderer code keeps working.
- New bridge methods and channels: `spaces.create(name)`, `spaces.rename(id,
  name)`, `spaces.delete(id)`, `spaces.activate(id)`, `spaces.list()`.

### 3. Main process wiring

- Main owns one store instance; all existing tab IPC handlers route to the
  active space.
- Space switch: hide the outgoing space's views, show the incoming space's
  active tab view, broadcast. Views for tabs in inactive spaces stay alive but
  hidden (view lifecycle per space is not persisted or torn down here).
- The idle sweep runs across all spaces.

### 4. Tests

- e2e (bridge-driven, no UI): create a second space, create a tab in it,
  switch back and forth asserting each space shows only its own tabs and
  restores its own active tab; delete the second space and assert its tabs are
  gone and the first space is active.

## Constraints

- All space/tab state logic in `packages/core`; main only wires views and IPC.
- No persistence: spaces and tabs still vanish on quit (SQLite lands in PRD
  3.4).
- No renderer UI changes beyond keeping the existing sidebar working against
  the new snapshot shape.
- Do not create or modify anything under `.github/workflows/`; root script
  names stay unchanged.

## Acceptance criteria

- `pnpm lint && pnpm typecheck && pnpm build && pnpm test && pnpm e2e` green.
- In the running app: behavior is unchanged from v0.0.4 (single seeded space).
- CI green on the merge request branch.
