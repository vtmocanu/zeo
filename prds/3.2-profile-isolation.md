# PRD 3.2 — Profiles: per-space session isolation

## Context

zeo is a keyboard-first, workspace-centric open-source browser for macOS.
Design: `docs/specs/2026-08-30-zeo-v1-design.md`. Requires PRD 3.1
(`prds/3.1-space-model.md`) merged: spaces exist and each references a
`profileId` (currently the `"default"` placeholder).

A profile maps to an Electron session partition (`persist:<profile-id>`),
giving real cookie/storage isolation. Each space references a profile;
multiple spaces may share one.

## Deliverables

### 1. Profile model (core)

- `Profile` type: `id`, `name`, `createdAt`.
- Profile management in the core store: `createProfile(name)`,
  `renameProfile(id, name)`, `deleteProfile(id)`, read access to the list.
  A fresh store seeds one profile named "Default" with id `"default"`.
- Spaces reference profiles: `createSpace(name, profileId?)` defaults to
  `"default"`; `setSpaceProfile(id, profileId)` re-points a space. Deleting a
  profile that any space references throws; deleting `"default"` throws.
- Unit tests: seeding, reference rules, delete guards.

### 2. IPC contract (core)

- Snapshot carries the profile list and each space's `profileId`.
- New bridge methods and channels: `profiles.create(name)`,
  `profiles.rename(id, name)`, `profiles.delete(id)`,
  `spaces.setProfile(spaceId, profileId)`.

### 3. Main process wiring

- Every `WebContentsView` is created with
  `webPreferences.partition = "persist:" + profileId` resolved from the tab's
  space at creation time.
- Re-pointing a space's profile applies to views created afterwards; existing
  views keep their partition until their tab is closed and reopened (no live
  re-partitioning — Electron cannot change a WebContents partition in place).

### 4. Tests

- e2e: two spaces on two different profiles; set a cookie via the bridge in a
  page loaded in space A, assert it is absent from the same origin loaded in
  space B, and present in a second space that shares profile A. Use
  `about:blank`-based or local fixtures; no external network dependency.

## Constraints

- Profile/space logic in `packages/core`; partition strings and session
  objects only in `apps/desktop`.
- No persistence of profiles yet (SQLite lands in PRD 3.4); partition data
  itself persists on disk under Electron's control, which is fine.
- No profile management UI (PRD 3.3 exposes what it needs).
- Do not create or modify anything under `.github/workflows/`; root script
  names stay unchanged.

## Acceptance criteria

- `pnpm lint && pnpm typecheck && pnpm build && pnpm test && pnpm e2e` green.
- In the running app: cookies set in a space on profile X are invisible to
  spaces on profile Y.
- CI green on the merge request branch.
