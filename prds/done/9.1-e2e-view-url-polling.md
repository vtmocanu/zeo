# PRD 9.1 — e2e: poll the live view URL before snapshotting it

## Context

zeo is a keyboard-first, workspace-centric open-source browser for macOS.
Design: `docs/specs/2026-08-30-zeo-v1-design.md`. The Playwright Electron
suite lives in `e2e/tests/*.spec.ts` and runs on both CI jobs in
`.github/workflows/ci.yml`: the Linux job under `xvfb-run` and the macOS job
natively. `e2e/playwright.config.ts` runs one worker serially with a 60 s
per-test timeout and one retry on CI.

Issue #66: the test `reassigning a profile on a space with a loaded tab
migrates the live view to the new partition` (`e2e/tests/app.spec.ts`)
failed twice in a row on the macOS runner with
`expected the recreated tab view on the destination partition at the
navigated URL`, then passed on a plain rerun with no code change. The test
awaits `webContents.loadURL("data:text/html,ZEOISO_FOXTROT")`, then calls
`zeo.spaces.setProfile(...)` over the bridge, then polls with `expect.poll`
for a webContents on the destination partition whose `getURL()` contains the
token. Two timing assumptions hide in that sequence:

1. `remapSpaceProfile` (`apps/desktop/src/main/index.ts`) snapshots each live
   view's `webContents.getURL()` before teardown and reloads the recreated view
   from that snapshot. The awaited `loadURL` resolves on load completion, but
   nothing in the test proves `getURL()` already reports the new URL at the
   moment `setProfile` runs. When the snapshot still reads the previous URL,
   the recreated view never carries the token and the final poll can only
   time out.
2. Every `expect.poll` in the suite uses Playwright's default 5 s poll
   timeout. On a cold macOS runner, tearing down and recreating a
   `WebContentsView` plus committing a `data:` navigation can exceed 5 s,
   which turns a slow-but-correct run into a failure.

This PRD removes both assumptions from every spec that snapshots a live
view URL, with one shared helper and one shared poll timeout. It changes no
production code.

## Deliverables

### 1. Shared e2e helpers `e2e/tests/helpers/view.ts`

New module, imported by the spec files that need it. Every helper takes the
`ElectronApplication` handle the spec already holds and evaluates in the
main process through `app.evaluate`, exactly as the existing inline probes
do.

- `export const VIEW_POLL_TIMEOUT_MS = 20_000;` — the poll timeout for any
  assertion that waits on a `WebContentsView` being created, destroyed,
  navigated, or moved between partitions. The value is one constant so a
  future runner slowdown is tuned in one place.
- `export async function waitForViewUrl(app, urlSubstring: string): Promise<void>`
  — polls with `expect.poll(..., { timeout: VIEW_POLL_TIMEOUT_MS, message })`
  until some `webContents.getAllWebContents()` entry has
  `getURL().includes(urlSubstring)`. The message names the substring.
  Resolves on the first observation; rejects with the poll failure when the
  timeout elapses.
- `export async function waitForViewOnPartition(app, urlSubstring: string, profileId: string): Promise<void>`
  — the same poll, additionally requiring
  `wc.session === session.fromPartition("persist:" + profileId)` by identity
  (the assertion shape the migration test already uses). Message names both
  the substring and the profile id.
- `export async function waitForViewGone(app, urlSubstring: string): Promise<void>`
  — polls with the same timeout until NO webContents has a URL containing
  `urlSubstring`.
- `export async function loadViewUrl(app, currentUrlSubstring: string, url: string): Promise<void>`
  — finds the webContents whose URL contains `currentUrlSubstring`, throws
  `live view for <substring> not found` when absent, awaits `loadURL(url)`,
  then calls `waitForViewUrl(app, url)` so the caller's next step runs only
  once `getURL()` observably reports `url`. A `data:` URL is passed verbatim
  as the substring.

The helpers are typed against `@playwright/test`'s `ElectronApplication` and
`electron`'s `WebContents`; no `any`.

### 2. Profile-migration test (`e2e/tests/app.spec.ts`)

- The `wc.loadURL("data:text/html," + liveToken)` step becomes
  `loadViewUrl(app, setup.token, "data:text/html," + liveToken)`.
- The pre-remap partition poll becomes
  `waitForViewOnPartition(app, setup.token, setup.fromId)`.
- The post-remap poll becomes
  `waitForViewOnPartition(app, liveToken, setup.toId)`.
- The `staleViewExists` one-shot read becomes `waitForViewGone(app, setup.token)`
  (a torn-down webContents can still be enumerable for a tick after
  `close()`; polling to absence is the assertion the test means).

### 3. Suite sweep

Every other `expect.poll` or one-shot `getAllWebContents()` read in
`e2e/tests/app.spec.ts`, `blocking.spec.ts`, `page-search.spec.ts`,
`persistence.spec.ts`, `history.spec.ts`, `zoom.spec.ts`, and
`settings.spec.ts` that waits on a view's URL, partition, existence, or
absence is rewritten onto the helpers above. A poll that waits on
sidebar-renderer state (a `state-change` broadcast, a DOM locator) keeps its
current form; the sweep is scoped to `WebContentsView` observations only.
Any spec that awaits `loadURL` and then reads main-process state derived
from `getURL()` inserts `waitForViewUrl` between the two.

Each rewritten site keeps its assertion message text so a failure still
identifies the step.

### 4. Retry hygiene

`e2e/playwright.config.ts` keeps `retries: process.env.CI ? 1 : 0`. The fix
is the poll discipline, not more retries; a retry count change is out of
scope.

## Constraints

- No file under `apps/`, `packages/`, or `.github/workflows/` changes.
- The helpers add no fixed sleeps (`waitForTimeout`) anywhere; every wait is
  a condition poll bounded by `VIEW_POLL_TIMEOUT_MS`.
- The 60 s per-test timeout stays; a test that composes several 20 s polls
  is acceptable because each poll returns on first observation.
- Conventional Commits; a single `test(e2e): ...` commit.
- Root `package.json` version and `CHANGELOG.md` are unchanged: no
  user-visible behavior changes.

## Acceptance criteria

1. No `expect.poll` in `e2e/tests/*.spec.ts` evaluates
   `getAllWebContents()`; every view URL, partition, existence, or absence
   wait goes through `e2e/tests/helpers/view.ts`.
2. The migration test calls `loadViewUrl` before `setProfile`, and both
   partition assertions carry `VIEW_POLL_TIMEOUT_MS`.
3. `pnpm e2e` passes on Linux under `xvfb-run` and on the macOS CI job three
   consecutive times with no retry consumed (the Playwright `list` reporter
   shows no `retry #1` line).
4. `pnpm lint` and `pnpm typecheck` pass; the `e2e` workspace compiles the
   helper module under `tsc --noEmit`.
