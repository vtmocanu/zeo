# PRD 10.2 — Frameless chrome: hidden title bar, inset content card, resizable and collapsible sidebar

## Context

zeo is a keyboard-first, workspace-centric open-source browser for macOS. Epic 10's source is the
design book: `docs/design/README.md` (authoritative) and `docs/design/design-book.html`. If it is
not on `main` yet: `git fetch origin docs/epic-10-design && git show FETCH_HEAD:docs/design/README.md`.
This PRD implements README §2 (window geometry) and the window row of §6. PRD 10.1 has merged:
tokens live in `apps/ui/src/styles/` and `useThemeTokens` applies them.

On origin/main (64d4e67) the main window has a native title bar (`apps/desktop/src/main/window.ts:105-115`:
no `titleBarStyle`, `vibrancy` or `backgroundColor`). The sidebar is the window's own webContents
(`apps/ui/src/App.tsx:833-836`, fixed `SIDEBAR_WIDTH = 240`, `packages/core/src/layout.ts:3`);
tab views, split panes (6 px divider), settings and the command-bar/find overlay all butt against
it, e.g. tab views at `{240, 0, W−240, H}` (`apps/desktop/src/main/views.ts:25-36`). Nothing calls
`setBorderRadius` or `setBackgroundColor`; the sidebar cannot be resized or hidden.

This PRD makes the window frameless and vibrant, floats every page in an inset rounded card, and
makes the sidebar resizable (200–360 px) and collapsible (⌘S) with an edge reveal. Tints arrive in
10.3 and the rest of the sidebar in 10.4; every surface here renders the null theme.

**Schema.** This PRD claims an effective schema version `N` = main's `SCHEMA_VERSION`
(`packages/core/src/persistence.ts:19`, 12 today) at rebase time plus 1. Under no collision `N` is
`13`; every `13` below (step key, `UPDATE meta` stamp, test expectations, acceptance criterion) is
that one illustrative value and one substitution applies everywhere. 10.3 and 10.4 claim the
versions after it.

## Deliverables

### 1. Core `packages/core/src/chrome.ts`

Pure TypeScript, no DOM, no Electron; everything exported from the core barrel.

```ts
import type { Rect } from "./window-state.js";
export type { Rect };

export const SIDEBAR_DEFAULT_WIDTH = 240;
export const SIDEBAR_MIN_WIDTH = 200;
export const SIDEBAR_MAX_WIDTH = 360;
export const CARD_INSET = 8;
export const WINDOW_ROW_HEIGHT = 44;
export const SIDEBAR_REVEAL_EDGE = 6;
export const SIDEBAR_HIDE_DELAY_MS = 400;
export const CARD_RADIUS = 10;
export const TRAFFIC_LIGHT_POSITION = { x: 14, y: 16 } as const;

export interface ChromeState { sidebarWidth: number; sidebarCollapsed: boolean; sidebarRevealed: boolean }
export type PersistedChrome = Pick<ChromeState, "sidebarWidth" | "sidebarCollapsed">;
export const DEFAULT_CHROME_STATE: ChromeState = { sidebarWidth: 240, sidebarCollapsed: false, sidebarRevealed: false };

export function clampSidebarWidth(w: number): number;
export function sidebarVisible(chrome: ChromeState): boolean;
export function cardLeft(chrome: ChromeState): number;
export function contentRect(contentW: number, contentH: number, chrome: ChromeState): Rect;
export function withSidebarWidth(chrome: ChromeState, w: number): ChromeState;
export function withSidebarRevealed(chrome: ChromeState, revealed: boolean): ChromeState;
export function toggleSidebar(chrome: ChromeState): ChromeState;
export function restoreChrome(saved: PersistedChrome | null): ChromeState;
```

- `clampSidebarWidth`: non-finite → `SIDEBAR_DEFAULT_WIDTH`, else `Math.round` then clamp to 200–360.
- `sidebarVisible` = `!sidebarCollapsed || sidebarRevealed`; `cardLeft` = `sidebarVisible ?
  sidebarWidth : CARD_INSET`.
- `contentRect` = `{ x: cardLeft, y: CARD_INSET, width: max(0, W − cardLeft − CARD_INSET),
  height: max(0, H − 2·CARD_INSET) }`.
- `withSidebarWidth` clamps. `withSidebarRevealed` returns the input reference unchanged when not
  collapsed or when the flag already matches. `toggleSidebar` flips `sidebarCollapsed` and sets
  `sidebarRevealed: false`. `restoreChrome(null)` = `DEFAULT_CHROME_STATE`, otherwise the saved
  values with the width clamped and `sidebarRevealed: false`.

### 2. Core geometry `packages/core/src/layout.ts`

`SIDEBAR_WIDTH` is deleted. Every function that read it takes `chrome: ChromeState` as its third
parameter, as `contentRect` does (later PRDs rely on this order), and derives the page region as
`r = contentRect(contentWidth, contentHeight, chrome)`. `DIVIDER_WIDTH` becomes
`8`. `quickBrowsePageBounds` never read the sidebar (quick-browse is its own window) and is unchanged.

```ts
export function commandBarBounds(contentWidth: number, contentHeight: number, chrome: ChromeState, rowCount: number): Rect;
export function settingsBounds(contentWidth: number, contentHeight: number, chrome: ChromeState): Rect;
export function splitPaneBounds(contentWidth: number, contentHeight: number, chrome: ChromeState, ratio: number): { left: Rect; divider: Rect; right: Rect };
export function findBarBounds(contentWidth: number, contentHeight: number, chrome: ChromeState): Rect;
```

- `commandBarBounds`: width `max(0, min(640, r.width − 48))`, zero rect when 0; `x = r.x +
  round((r.width − width) / 2)`; `y = r.y + round(r.height × 0.12)`; zero rect when `r.y + r.height
  − y < COMMAND_BAR_HEIGHT`; height `min(56 + rowCount × 44, r.y + r.height − y)`. (10.5 replaces it.)
- `settingsBounds` = `contentRect(...)`: settings covers the card until 10.6 makes it a sheet.
- `splitPaneBounds`: `usable = r.width − DIVIDER_WIDTH`, all-zero rects when `usable <= 0`;
  `leftW = round(usable × clampRatio(ratio))`; left `{r.x, r.y, leftW, r.height}`, divider
  `{r.x + leftW, r.y, 8, r.height}`, right `{r.x + leftW + 8, r.y, usable − leftW, r.height}`.
- `findBarBounds`: width `max(0, min(360, r.width − 2·FIND_BAR_INSET))`, zero rect when 0;
  `x = r.x + r.width − width − FIND_BAR_INSET`, `y = r.y + FIND_BAR_TOP`, height 44 (10.6 restyles).

### 4. Main process

New `apps/desktop/src/main/chrome.ts`, imported by `index.ts` for its IPC handlers. It imports
`views`, `layout`, `overlay`, `settings`, `broadcast`, `db` and `state`, never `window.ts` or
`commands.ts`, so `lint:cycles` stays clean.

```ts
export function relayoutWindow(): void;
export function applyWindowButtons(): void;
export function setChrome(next: ChromeState, opts: { persist: boolean }): void;
export function toggleSidebarChrome(): void;
export function scheduleChromeSave(): void;
export function flushChromeSave(): void;
```

- `relayoutWindow()` sets bounds only; it never changes visibility or focus. Single: the active view
  gets `viewBounds()`. Split: left, right and divider get `splitPaneBounds(W, H, runtime.chrome,
  runtime.layout.ratio)`, then `sendDividerGeometry()`. Open settings get `settingsBoundsRect()`. An open
  command bar or find bar runs `layoutOverlay()` with the hidden→visible focus rule now at
  `window.ts:178-188`. Last, `applyWindowButtons()`.
- `applyWindowButtons()` calls `runtime.win?.setWindowButtonVisibility(sidebarVisible(runtime.chrome))`;
  under `ZEO_E2E === "1"` it also stores the value in `globalThis.__zeoWindowButtonsVisible`
  (Electron has no getter).
- `setChrome` is a no-op when all fields are equal; otherwise it assigns `runtime.chrome`, calls
  `relayoutWindow()` and `broadcast({ persist: false })`, and `scheduleChromeSave()` when
  `opts.persist`. `toggleSidebarChrome()` = `setChrome(toggleSidebar(runtime.chrome), { persist: true })`.
- IPC: set-sidebar-width rejects a non-number, else `setChrome(withSidebarWidth(..), { persist:
  true })`; set-sidebar-revealed rejects a non-boolean, else `setChrome(withSidebarRevealed(..),
  { persist: false })`; state returns `runtime.chrome`.
- `scheduleChromeSave()` debounces 500 ms, then calls `writeChromePrefs({ sidebarWidth,
  sidebarCollapsed }, frame)`, `frame` being `getNormalBounds()` plus `isMaximized()` as in
  `saveWindowState` (`window.ts:28-48`). `flushChromeSave()` cancels a pending timer and writes
  synchronously. A write error logs once per launch.

Existing modules:

- `views.ts:25-36`: `viewBounds()` returns `contentRect(W, H, runtime.chrome)`; with no window,
  `{ x: cardLeft(runtime.chrome), y: CARD_INSET, width: 0, height: 0 }`. `createViewFor` calls
  `view.setBorderRadius(CARD_RADIUS)` after constructing the view (`:83-96`).
- `settings.ts:14-20` passes `runtime.chrome` (same no-window fallback); `openSettings` calls
  `setBorderRadius(CARD_RADIUS)` when it creates the view.
- `layout.ts`: `dividableWidth()` (`:30-36`) = `contentRect(W, H, runtime.chrome).width −
  DIVIDER_WIDTH`; `:107` passes `runtime.chrome`; `ensureDividerView` (`:45-70`) calls
  `setBackgroundColor("#00000000")` on the new divider view. `overlay.ts:25-28` passes `height`
  and `runtime.chrome`.
- `window.ts`: `createWindow` sets `runtime.chrome = restoreChrome(readChromePrefs())` before
  building the window (a throw logs and uses `null`). The `BrowserWindow` options (`:105`) add
  `titleBarStyle: "hidden"`, `trafficLightPosition: TRAFFIC_LIGHT_POSITION`, `vibrancy: "sidebar"`,
  `visualEffectState: "followWindow"`, `backgroundColor: "#00000000"`, followed by
  `applyWindowButtons()`. The `resize` handler (`:169-196`) becomes `scheduleWindowStateSave();
  relayoutWindow();`. The `blur` handler (`:213-215`) also runs `setChrome(withSidebarRevealed(
  runtime.chrome, false), { persist: false })`. `flushWindowStateSave()` (`:62-68`) also calls
  `flushChromeSave()`, covering `close` and `before-quit` (`index.ts:149-152`).

**`setBorderRadius` check.** Electron is pinned at 44.0.0 (`pnpm-lock.yaml`). The View API
documents `view.setBorderRadius(radius: Integer)`, added well before 44. Before writing code, run
`rg -n "setBorderRadius" node_modules/electron/electron.d.ts`. If it is absent, do not call it and
do not cast around the typings: views keep square corners, the `.window-card` layer (§6) still
draws radius, hairline and shadow, and the PR description says so. The corners the radius cuts
still take clicks (documented Electron behavior); that is accepted.

### 6. Renderer

New `apps/ui/src/WindowChrome.tsx`, `apps/ui/src/icons.tsx` (the single inline-SVG icon module;
`export function Icon(props: { name: IconName }): ReactElement` with `type IconName = "sidebar" |
"back" | "forward" | "reload"`, later PRDs extend it) and `apps/ui/src/styles/window.css` (added
to `index.css` after `base.css`). `tokens.css` gains static `--card-inset: 8px` and `--window-row-height: 44px`;
`App` sets `--sidebar-width` on `document.documentElement` in a layout effect from
`state.chrome.sidebarWidth`.

```ts
export function useWindowSize(): { width: number; height: number };
export function WindowBackdrop(props: { chrome: ChromeState; layout: WindowLayout }): ReactElement;
export function WindowRow(): ReactElement;
export function SidebarResizeHandle(props: { width: number }): ReactElement;
export function useSidebarReveal(chrome: ChromeState): void;
```

- **Transparency.** `base.css`: `html, body, #root { background: transparent; }`. `sidebar.css`
  drops the `.sidebar` background and right border.
- **`WindowBackdrop`**, rendered before the `<aside>`, all `position: fixed`: `.window-tint`
  (`data-testid="window-tint"`, `inset: 0`, background `var(--surface-window)`, and an `::after`
  at `inset: 0` painting `var(--tint)` at `opacity: var(--tint-opacity)`); `.window-card`
  (`data-testid="window-card"`) at `contentRect(innerWidth, innerHeight, chrome)`, or two with
  `data-pane="left"`/`"right"` at `splitPaneBounds(...)` in split, each `background:
  var(--surface-card); box-shadow: var(--shadow-card); border-radius: var(--radius-card)`;
  `.window-drag-strip` (`top: 0; left: 0; right: 0; height: var(--card-inset);
  -webkit-app-region: drag`) so a collapsed window can still be dragged.
- **`App.tsx`** (`:833-837`): the `<aside>` keeps its class and `data-testid="sidebar"`, becomes
  `position: relative; z-index: 1`, takes `style={{ width: state.chrome.sidebarWidth }}`, and adds
  `sidebar--hidden` (`visibility: hidden`) when `!sidebarVisible(state.chrome)`. First child
  `<WindowRow />`, last child `<SidebarResizeHandle width={state.chrome.sidebarWidth} />`; the
  content between is untouched (10.4 restyles it). `App` calls `useSidebarReveal(state.chrome)`.
- **`WindowRow`**: `div.window-row` (`data-testid="window-row"`), `height:
  var(--window-row-height)`, flex, centered, `padding: 0 var(--space-4) 0 78px` (clear of the
  traffic lights), `-webkit-app-region: drag`. A right-aligned group (`margin-left: auto; gap:
  var(--space-1)`) holds four 28 × 28 `button.icon-button`, each `-webkit-app-region: no-drag`,
  radius `var(--radius-control)`, color `var(--ink-secondary)`, hover background
  `var(--surface-hover)` and color `var(--ink-primary)`: `sidebar-toggle` ("Toggle sidebar",
  `view.toggleSidebar`), `nav-back` ("Back", `tab.back`), `nav-forward` ("Forward",
  `tab.forward`), `nav-reload` ("Reload", `tab.reload`), all via
  `window.zeo.commands.run(id).catch(() => {})`. The sidebar has no navigation flags, so the
  buttons stay enabled and a disabled command is a silent no-op. `Icon` renders a 16 × 16
  `<svg className="icon" viewBox="0 0 16 16">`, `fill="none" stroke="currentColor"
  stroke-width="1.5"`, round caps and joins, `aria-hidden="true"`: toggle `<rect x="2" y="3" width="12" height="10" rx="2.2"/><path
  d="M6.2 3v10"/>`, back `<path d="M10 3.5 5.5 8l4.5 4.5"/>`, forward `<path d="M6 3.5 10.5 8 6
  12.5"/>`, reload `<path d="M12.8 8.6A4.9 4.9 0 1 1 11.4 4.3"/><path d="M11.8 1.8v2.9H8.9"/>`.
- **`SidebarResizeHandle`**: `div.sidebar__resize-handle` (`data-testid="sidebar-resize-handle"`,
  `role="separator"`, `aria-orientation="vertical"`, `aria-valuemin={200}`,
  `aria-valuemax={360}`, `aria-valuenow={width}`, `tabIndex={0}`), `position: absolute; top: 0;
  bottom: 0; right: 0; width: 6px; cursor: col-resize; -webkit-app-region: no-drag`, the strip
  just left of the card's edge. `pointerdown` captures and records `clientX` and `width`;
  `pointermove` sends `setSidebarWidth(clampSidebarWidth(startWidth + dx))` at most once per
  animation frame; `pointerup` releases. ArrowLeft/ArrowRight step 10 px while focused.
- **`useSidebarReveal`**, active only while collapsed: a `document` `pointermove` with `clientX <
  SIDEBAR_REVEAL_EDGE` calls `setSidebarRevealed(true)`. While revealed, `pointerleave` on
  `document.documentElement` or a `pointermove` with `clientX >= sidebarWidth` starts a
  `SIDEBAR_HIDE_DELAY_MS` timer that calls `setSidebarRevealed(false)`; a `pointermove` with
  `clientX < sidebarWidth` cancels it. The reveal pushes the card to `x = sidebarWidth` because the
  sidebar is the window's own webContents beneath every native view and cannot float over them.
- **Divider** (`styles/divider.css`): `.divider-handle` is `transparent`, hover
  `var(--accent-soft)`, so the 8 px gap shows the window between the two cards.

## Acceptance criteria

1. The main window has no title bar; the traffic lights sit at (14, 16) in the sidebar's 44 px
   window row, which drags the window everywhere except its four buttons.
2. The window shows `sidebar` vibrancy under the `.window-tint` layer. Every tab view, split pane
