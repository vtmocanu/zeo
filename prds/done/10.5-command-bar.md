# PRD 10.5 — Command bar: floating bar, scrim, grouped results

## Context

zeo is a keyboard-first, workspace-centric open-source browser for macOS. Epic 10 gives it
an Arc-like visual language; the source is the design book `docs/design/README.md`
(authoritative) and `docs/design/design-book.html` (visual reference: its `renderCmd` mock
and `ICONS` table). If the book is not on `main` yet, read it with
`git fetch origin docs/epic-10-design && git show FETCH_HEAD:docs/design/README.md`. This
PRD implements §6 "Command bar" with §4 type and §5 radius and elevation. PRDs 10.1
(tokens, `styles/command-bar.css`), 10.2 (frameless chrome, geometry through
`contentRect`), 10.3 (space themes; `Overlay` calls `useThemeTokens`) and 10.4 (sidebar)
have merged. No schema change.

Today on `origin/main`, with PRD 10.2's geometry applied:

- One overlay `WebContentsView` (`?view=command-bar`) is created in
  `apps/desktop/src/main/window.ts:143-162`. Its `webContents` `blur` closes the bar
  (`window.ts:163-167`), as does window blur (`window.ts:212-215`). It hosts two surfaces
  chosen by `CommandBarState.surface` (`packages/core/src/command-bar.ts:69`,
  `apps/ui/src/Overlay.tsx:17-43`).
- `layoutOverlay()` (`apps/desktop/src/main/overlay.ts:17-41`) sizes the view to the panel
  alone with 10.2's `commandBarBounds(width, height, runtime.chrome, rows)`
  (`packages/core/src/layout.ts`: centred on `r = contentRect(...)`, width
  `min(640, r.width − 48)`, `y = r.y + round(r.height × 0.12)`, height `56 + rows × 44`). `raiseOverlays()` (`apps/desktop/src/main/views.ts:56-69`) keeps it
  topmost (tabs < divider < settings < overlay).
- Main owns ranking and selection: `recomputeSuggestions()`
  (`apps/desktop/src/main/command-bar.ts:105-120`) stores `suggest(...)` (`packages/core/src/suggest.ts:232-496`:
  mixed modes sorted by score, kind, active space, recency, order at `:485-492`, capped at
  `MAX_MATCHES = 8` after row 0; other modes single-kind) and resets `selectedIndex` to 0.
- `apps/ui/src/CommandBar.tsx` draws emoji glyphs, primary and secondary text (`:17-86`)
  in 44 px two-line rows, `formatAccelerator` hints on command rows (`:323-328`), handles
  keys in `onKeyDown` (`:197-245`) and accepts clicks on `onMouseDown` (`:257-263`).
- e2e `overlayNativeBounds` (`e2e/tests/app.spec.ts:309-336`) feeds the check against
  `commandBarBounds(w, h, chrome, 2 | 1).height` at `app.spec.ts:2740-2808` (the chrome
  argument added by 10.2).

Nothing dims the window, and the page and sidebar stay clickable around the panel. This PRD
makes the overlay cover the window, draws a scrim and a 680 px panel, and groups results.

## Deliverables

### 1. Core geometry `packages/core/src/layout.ts`

Delete `COMMAND_BAR_HEIGHT`, `SUGGESTION_ROW_HEIGHT` and `commandBarBounds` (as reshaped by
PRD 10.2) and their exports in `packages/core/src/index.ts`. Add and export (`Rect` is the
type `packages/core/src/chrome.ts` re-exports since 10.2):

```ts
export const COMMAND_BAR_WIDTH = 680;
export const COMMAND_BAR_MARGIN = 24;
export const COMMAND_BAR_TOP_RATIO = 0.2;
export const COMMAND_BAR_INPUT_HEIGHT = 58;
export const COMMAND_BAR_ROW_HEIGHT = 40;
export const COMMAND_BAR_GROUP_HEIGHT = 28;
export const COMMAND_BAR_LIST_PADDING_TOP = 4;
export const COMMAND_BAR_LIST_PADDING_BOTTOM = 8;

export function commandBarPanelRect(
  contentW: number,
  contentH: number,
  rows: number,
  groups?: number,
): Rect;
```

Formula (`ZERO = { x: 0, y: 0, width: 0, height: 0 }`; negative `rows`/`groups` count as
0; `groups` defaults to 0):

1. `width = min(COMMAND_BAR_WIDTH, contentW − 2 × COMMAND_BAR_MARGIN)`; `width ≤ 0` → `ZERO`.
2. `x = round((contentW − width) / 2)`: centred on the window, not on the content card
   (§6 "centered … from the top of the window"). No `ChromeState` input.
3. `y = round(contentH × COMMAND_BAR_TOP_RATIO)`.
4. `room = contentH − y − COMMAND_BAR_MARGIN`; `room < COMMAND_BAR_INPUT_HEIGHT` → `ZERO`.
5. `list = rows === 0 ? 0 : COMMAND_BAR_LIST_PADDING_TOP + COMMAND_BAR_LIST_PADDING_BOTTOM
   + rows × COMMAND_BAR_ROW_HEIGHT + groups × COMMAND_BAR_GROUP_HEIGHT`.
6. `height = min(COMMAND_BAR_INPUT_HEIGHT + list, room)`.

Coordinates are relative to the overlay, which (§3) equals the window content area. At
`MIN_WINDOW_SIZE` (640 × 400) the panel is 592 wide at y 80 with at most 296 px of height.

### 2. Core grouping and row anatomy `packages/core/src/command-bar-groups.ts` (new)

```ts
export type SuggestionGroupId = "go" | "tabs" | "spaces" | "history" | "commands" | "downloads";
export const SUGGESTION_GROUPS: readonly { id: SuggestionGroupId; label: string; kinds: readonly Suggestion["kind"][] }[] = [
  { id: "go", label: "Go to", kinds: ["navigate", "search"] },
  { id: "tabs", label: "Tabs", kinds: ["tab", "archived-tab"] },
  { id: "spaces", label: "Spaces", kinds: ["space"] },
  { id: "history", label: "History", kinds: ["history"] },
  { id: "commands", label: "Commands", kinds: ["command"] },
  { id: "downloads", label: "Downloads", kinds: ["download"] },
];
export interface SuggestionGroup { id: SuggestionGroupId; label: string; start: number; suggestions: Suggestion[] }
export function groupOf(kind: Suggestion["kind"]): SuggestionGroupId;
export function groupSuggestions(suggestions: readonly Suggestion[]): Suggestion[];
export function suggestionGroups(suggestions: readonly Suggestion[]): SuggestionGroup[];

export type SuggestionIcon = "arrow" | "search" | "globe" | "archive" | "grid" | "bolt" | "history" | "download";
export interface SuggestionRowView { icon: SuggestionIcon; primary: string; secondary: string; hint: string; tone: "default" | "danger" }
export function suggestionRowView(suggestion: Suggestion, mode: CommandBarMode, selected: boolean): SuggestionRowView;
```

- **`groupSuggestions`** is a stable partition: a new array holding every input row exactly
  once, ordered by its group's index in `SUGGESTION_GROUPS` and, within a group, in the
  input's relative order. It never re-ranks, drops or adds rows, so the same capped rows
  appear as today and only the cross-kind interleaving changes: `[search, history (score 1),
  tab (score 2), command]` becomes `[search, tab, history, command]`.
- **`suggestionGroups`** splits an already-grouped list into consecutive runs of equal
  `groupOf(kind)`; `start` is the flat index of the run's first row. Empty groups never
  appear; an empty list returns `[]`.
- **`suggestionRowView`** holds the row anatomy, pure and in core next to the grouping so
  core unit tests cover it:

| Kind | `icon` | `primary` | `secondary` |
| --- | --- | --- | --- |
| `navigate` / `search` | `arrow` / `search` | `label` | `""` |
| `tab` | `globe` | `title` | url host; the raw url when it does not parse |
| `archived-tab` | `archive` | `title` | `Archived · <spaceName>` |
| `space` | `grid` | `name` | `""` (the heading replaces the old `"Space"`) |
| `history` | `history` | `title` | url host; the raw url when it does not parse |
| `command` | `bolt` | `title` | `""` (the heading replaces the old `"Command"`) |
| `download` | `download` | `filename` | `detail`, verbatim |

  `hint` is `formatAccelerator(accelerator)` for a `command` with a non-null accelerator;
  `"⌘⌫ Delete"` for the selected `history` row in `history` mode;
  `"↵ Open · ⌘↵ Reveal · ⌘⌫ Remove"` for the selected `download` row in `downloads` mode;
  otherwise `""`. `tone` is `"danger"` for a `download` in state `cancelled` or
  `interrupted`, else `"default"`. Export everything from `packages/core/src/index.ts`.

### 3. Main process

- **`recomputeSuggestions`** (`apps/desktop/src/main/command-bar.ts:105-120`) stores
  `groupSuggestions(suggest(query, buildCatalog(), options))`. The broadcast `suggestions`
  are in display order, so `selectedIndex`, `moveSelection`, `accept(index, revision)`, the
  revision comparison and every e2e `findIndex` keep meaning "the n-th visible row". Row 0
  stays the default selection. Nothing else in the file changes.
- **`layoutOverlay`** (`overlay.ts:17-41`): for `surface === "bar"` the bounds are
  `{ x: 0, y: 0, width, height }` from `runtime.win.getContentSize()`; it hides the overlay
  and returns `false` when `commandBarPanelRect(width, height, 0).width === 0`, which keeps
  the hidden→visible focus hand-off in 10.2's `relayoutWindow()`
  (`apps/desktop/src/main/chrome.ts`, run on window resize and chrome changes) working. The
  `find` branch stays as PRD 10.2 left it (region-sized; PRD 10.6 restyles it). Row count
  no longer affects native bounds; the existing calls on query change are harmless.
- **`window.ts`**: right after creating the overlay, call
  `runtime.overlay.setBackgroundColor("#00000000")` (both surfaces). Both `blur` handlers
  stay: window blur and focus moving to another `webContents` (quick-browse, DevTools)
  still close the bar.
- **Input routing.** While the bar is open the overlay is the topmost child
  (`raiseOverlays`) and covers the full content area. A transparent view still hit-tests
  over its whole rect, so every click in the window lands in the overlay. Tab views, split
  panes, the divider, settings and the sidebar (the window's own `webContents`, beneath
  every view) receive none. Only the native traffic lights stay clickable. The scrim is not
  a drag region, so the window cannot be dragged while the bar is open. Opening the bar does
  not change `ChromeState`, and a collapsed sidebar cannot reveal because it receives no
  pointer events.
- **Focus.** Unchanged: `openCommandBar` focuses the overlay `webContents`, the renderer
  focuses the input, and `closeCommandBar` hides the overlay and focuses the active tab's
  view, or the sidebar when there is none (`command-bar.ts:172-196`). Covering the sidebar
  changes one thing: a click on the sidebar area closes the bar through the scrim and no
  longer also acts on the sidebar (before, blur closed the bar and the click went through).

### 4. Renderer `apps/ui/src/CommandBar.tsx`, `apps/ui/src/Overlay.tsx`

`Overlay` sets `document.documentElement.dataset.surface = surface` in a layout effect and
otherwise stays as is (including the 10.3 `useThemeTokens` call). `CommandBar` keeps its
state, both effects, the input's attributes and placeholders (`CommandBar.tsx:267-291`) and
`onKeyDown`. Its markup becomes:

```tsx
<div className="command-bar-overlay">
  <div className="command-bar-scrim" data-testid="command-bar-scrim" aria-hidden="true" onMouseDown={onScrimMouseDown} />
  <div className="command-bar" data-testid="command-bar" role="dialog" aria-modal="true" aria-label="Command bar" style={panelStyle} onMouseDown={keepInputFocus}>
    <div className="command-bar__field"><Icon name="search" size={20} /><input className="command-bar__input" data-testid="command-bar-input" /></div>
    <div className="command-bar__list" role="listbox" ref={listRef}>
      <div className="command-bar__group" role="group" aria-labelledby="command-bar-group-tabs">
        <div className="command-bar__group-label" id="command-bar-group-tabs" data-testid="command-bar-group" data-group="tabs">Tabs</div>
        <div className="command-bar__row" data-testid="command-bar-suggestion" data-kind="tab" role="option" aria-selected="false">
          <Icon name="globe" /><span className="command-bar__row-primary" /><span className="command-bar__row-secondary" /><span className="command-bar__row-accel" />
        </div>
      </div>
    </div>
  </div>
</div>
```

- **Rows.** The list renders only when `suggestions.length > 0`, and the panel then carries
  `command-bar--has-list`. Groups come from `suggestionGroups(suggestions)`. A row's flat
  index is `group.start + i`, used for `selected` and for `commandBar.accept(index,
  revision)`. Rows keep `data-testid`, `data-kind`, `role="option"`, `aria-selected`, the
  `command-bar__row--selected` modifier and the `onMouseDown` accept. Download rows add
  `data-state={state}`, and `tone === "danger"` adds `command-bar__row--danger`. Secondary
  and accel spans render only when non-empty. `iconFor`, `primaryText` and `secondaryText`
  are deleted; `suggestionRowView` replaces them.
- **Panel layout.** A `useViewportSize()` hook tracks `window.innerWidth` and `innerHeight`
  on `resize`. `panelStyle` is `{ left, top, width, height }` in px from
  `commandBarPanelRect(innerWidth, innerHeight, suggestions.length, groups.length)`, plus
  the custom properties `--command-bar-input-height`, `--command-bar-row-height`,
  `--command-bar-group-height`, `--command-bar-list-padding-top` and
  `--command-bar-list-padding-bottom` set from the §1 constants. The CSS takes heights only
  from these, so the formula and the rendered layout cannot drift.
- **Scrim and focus.** `onScrimMouseDown` calls `preventDefault()` and then
  `window.zeo?.commandBar.close()`, swallowing a rejection. `keepInputFocus` calls
  `preventDefault()` whenever the target is not the input, so clicks on padding, headings or
  the field icon never take focus from the input. A `document` `keydown` listener also
  closes on `Escape` when the input is not focused.
- **Scrolling.** A clamped list scrolls (commands mode's uncapped empty query, up to 100
  downloads). On a `selectedIndex` or `revision` change the selected row gets
  `scrollIntoView({ block: "nearest" })`; at index 0 the list scrolls to the top.
- **Keyboard unchanged.** Enter accepts, Esc closes, ↑/↓ move and wrap over rows only
  (headings are outside the index space); `history` ⌘⌫ deletes; `downloads` Enter opens,
  ⌘Enter reveals, ⌘⌫ removes, bar stays open. Hover never moves the selection.
- **History and downloads modes** use the same panel: one `History` or `Downloads` group,
  the §2 row anatomy, the mode's action hint on the selected row, unchanged placeholders.
  With no rows the panel is just the input, as today.
- **Icons** (§5: 16 px line, 1.5 stroke, round caps and joins, `currentColor`). Extend the
  icon module 10.2 created (`apps/ui/src/icons.tsx`, `Icon` rendering `<svg className="icon"
  viewBox="0 0 16 16">`, with the `size` prop 10.4 added): `IconName` gains `arrow`,
  `search`, `globe`, `grid`, `bolt` and `history`, with path data copied verbatim from the
  design book's `ICONS` table. `archive` and `download` come from 10.4. No emoji remain.

## Acceptance criteria

1. With the bar open, the overlay view's bounds equal the window content size, it is the
   topmost child view, its background is transparent, and a click anywhere outside the
   panel closes the bar without reaching the page, the sidebar, the divider or settings.
2. The panel is `min(680, W − 48)` wide, centred on the window with its top at
   `round(0.2 × H)`, and its rendered rect equals `commandBarPanelRect` at every window
   size. `commandBarBounds`, `COMMAND_BAR_HEIGHT` and `SUGGESTION_ROW_HEIGHT` are gone.
3. Results appear under Go to, Tabs, Spaces, History, Commands and Downloads, in that
   order, with empty groups hidden and rows keeping their previous relative order within a
   group. The broadcast `suggestions` follow the DOM order.
4. Rows are 40 px, each with a 16 px line icon, primary and secondary text and a
   right-aligned hint. Accelerators render through `formatAccelerator`, and the selected
   row uses `--accent-soft`. The input is 22 px (`--text-xl`); the panel has radius 14 and
   `--shadow-palette`.
5. History and downloads modes render as one group each, with their action hint on the
   selected row, and their keys behave as before.
6. Enter, Esc, ↑/↓, ⌘⌫ and ⌘Enter behave as before; a long list scrolls to keep the
   selected row visible. The find surface keeps a region-sized overlay.
7. `pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm e2e` pass on both CI jobs.
