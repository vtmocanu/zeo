# PRD 9.3 — View lifecycle: unload hidden views, popups, archive teardown

## Context

zeo is a keyboard-first, workspace-centric open-source browser for macOS.
Design: `docs/specs/2026-08-30-zeo-v1-design.md`. Each tab is a
`WebContentsView` owned by the main process (`apps/desktop/src/main/views.ts`
after PRD 9.2; `index.ts` before it), tracked in the `views` map keyed by tab
id. Only the active space's active tab is visible; every other tracked view
is hidden but alive: a real Chromium renderer with timers, network, and
audio.

Views are already lazy in two places: `createWindow` materializes only the
active tab on a restored launch, and `ensureActiveView` creates a space's
active tab on activation. Everything else keeps its view forever:

- Archiving a tab (`archiveTab`, the hourly `sweepIdle`) leaves its view in
  `views` (#40). Only permanent delete or window close frees it.
- Switching away from a space leaves all of its views alive; a user with ten
  spaces of ten tabs runs a hundred renderers (#58).
- A page calling `window.open` (or a `target="_blank"` link) gets a popup
  window that inherits the space's partition but never enters `views`, so a
  profile remap leaves it on the old partition and a profile delete can clear
  storage under it (#62).
- `createWindow(seed)` seeds a default tab when `allOpenTabs()` is empty,
  which is also true for a store whose every tab is archived (#23).
- When a sidebar row is clicked after the idle sweep archived that tab, the
  `tabs.activate` invoke rejects with `Cannot activate an archived tab`; the
  renderer's `.catch(() => {})` swallows it and nothing re-syncs (#41).

This PRD makes a view a cache of a tab, not its identity: a tab is always in
the store; its view exists only while it is useful. It adds two unload
policies (on space switch and on idle time), tears views down on archive,
routes popups into tabs, fixes the seed predicate, and re-syncs the renderer
on a rejected tab command.

## Deliverables

### 1. Core `packages/core/src/view-unload.ts`

Pure policy, no Electron.

```ts
export const VIEW_UNLOAD_AFTER_MS = 30 * 60 * 1000;
export const VIEW_UNLOAD_INTERVAL_MS = 5 * 60 * 1000;

export interface UnloadCandidate {
  tabId: string;
  lastActiveAt: number;
  visible: boolean;
  audible: boolean;
}

export function selectViewsToUnload(
  candidates: readonly UnloadCandidate[],
  now: number,
  maxIdleMs: number,
): string[];
```

- Returns the ids of every candidate with `visible === false`,
  `audible === false`, and `now - lastActiveAt > maxIdleMs` (strictly
  greater, matching `archiveIdle`). Input order is preserved. Pure and
  total: an empty input returns `[]`; a negative `maxIdleMs` unloads every
  hidden, silent candidate.
- `packages/core/src/index.ts` exports all of the above.

### 2. Core `SpaceStore.createInSpace`

`packages/core/src/space-store.ts` gains
`createInSpace(spaceId: string, input: { url: string; title?: string }): Tab`:
delegates to that space's `TabStore.create` (so the tab becomes that space's
active tab and lands at the end of its unpinned group), throws
`Unknown space: <id>` on an unknown id, and never changes the active space.
`create(input)` stays as the active-space shorthand. Exported through the
class; no new index export.

### 3. `TabsState.unloadedTabIds`

`packages/core/src/ipc.ts` `TabsState` gains `unloadedTabIds: string[]`:
the ids of the ACTIVE space's open tabs that currently have no live view,
in `tabs` order. Main attaches it in `fullSnapshot()` as
`store.list().filter((t) => !views.has(t.id)).map((t) => t.id)`, so it is
never absent. Renderers use it to mark a row as unloaded; it is never
persisted.

### 4. Main `views.ts`

- `unloadView(id: string): void` — `destroyView(id)` for a tab that stays
  in the store. It is `destroyView` by another name so call sites read as
  intent; it adds no behavior. A no-op when `views` has no entry.
- `unloadSpaceViews(spaceId: string, keepTabId: string | null): void` —
  for every tracked view whose owning space is `spaceId`
  (`store.spaceOfTab(tabId) === spaceId`), except `keepTabId` and except a
  view whose `webContents.isCurrentlyAudible()` is `true`, call
  `unloadView`. Snapshot the `views` entries before iterating.
- `unloadIdleViews(now: number): void` — builds an `UnloadCandidate` per
  tracked view from the store's tab (`lastActiveAt`; a tab not found in any
  space is skipped), `visible = tabId === store.activeTabId && spaceOfTab(tabId) === store.activeSpaceId`,
  `audible = webContents.isCurrentlyAudible()`; calls
  `selectViewsToUnload(candidates, now, viewUnloadAfterMs())`; unloads each
  returned id; broadcasts once if it unloaded anything (the
  `unloadedTabIds` slice changed). The interval and threshold come from
  `viewUnloadAfterMs()` / `viewUnloadIntervalMs()`: the core constants,
  overridden by `ZEO_VIEW_UNLOAD_AFTER_MS` / `ZEO_VIEW_UNLOAD_INTERVAL_MS`
  only when `process.env.ZEO_E2E === "1"` and the value parses as a
  positive integer; a packaged build ignores both.
- `index.ts` starts `setInterval(() => unloadIdleViews(Date.now()), viewUnloadIntervalMs())`
  in `whenReady` after `createWindow`, alongside the existing `sweepIdle`
  interval. No launch-time run: a restored session materializes only the
  active view already.
- `createViewFor` registers, right after `views.set(...)`:

  ```ts
  view.webContents.setWindowOpenHandler(({ url }) => {
    openPopupAsTab(tab.id, url);
    return { action: "deny" };
  });
  ```

  Every popup is denied; no `BrowserWindow` is ever created by page script.

### 5. Main `tabs.ts`

- `openPopupAsTab(ownerTabId: string, url: string): void` — resolves the
  owning space with `store.spaceOfTab(ownerTabId)`; a `null` owner or a
  `url` that is not `http:`/`https:` (per `new URL(url).protocol`, an
  unparseable url included) returns with no effect. Otherwise
  `store.createInSpace(spaceId, { url, title: titleForUrl(url) })`. When
  `spaceId === store.activeSpaceId`: `createViewFor(tab, spaceId)`,
  `setActive(tab.id)`, `broadcast()` — the same lifecycle as `createTab`.
  When the owner is an inactive space: no view is created (the tab is now
  that space's active tab and materializes on the next switch);
  `broadcast()` only (the catalog and the space's tab count change).
- `archiveTab(id)` — after `store.archive(id)`, `unloadView(id)`, then the
  existing `ensureActiveView()` and `broadcast()`.
- `sweepIdle()` — `unloadView` for every id `archiveIdleAll` returned, then
  broadcast when the list is non-empty.
- `switchSpace(id: string): void` in `spaces.ts` — the single space-switch
  transition: `const outgoing = store.activeSpaceId`; return with no effect
  when `id === outgoing`; `store.setActiveSpace(id)`;
  `unloadSpaceViews(outgoing, store.activeTabIdOf(outgoing))`;
  `ensureActiveView()`; `broadcast()`. `SpaceStore` gains
  `activeTabIdOf(spaceId: string): string | null` (the space's own active
  tab, throws on unknown id) to supply the keep id. Every path that today
  calls `store.setActiveSpace` followed by `ensureActiveView`/`setActive`
  calls `switchSpace` instead: the `IPC.spacesActivate` handler, the
  `Activate Space N` menu items, `performSuggestion`'s `space` case, the
  `space.new` command handler (create, then `switchSpace(space.id)`), and
  `deleteSpace`'s `wasActive` branch (the store already re-pointed the
  active space; call `unloadSpaceViews` for nothing — the deleted space's
  views are gone — then `ensureActiveView`). `performSuggestion`'s `tab`
  and `archived-tab` cases call `switchSpace(s.spaceId)` before
  `activateTab` / `store.restore`; `switchSpace`'s `ensureActiveView` may
  materialize the space's previous active tab, and `activateTab` then
  shows the target — one extra view at most, torn down by the idle policy.
- Renderer re-sync on rejection (#41): `withResync<T>(fn: () => T): T` in
  `tabs.ts` runs `fn`, and on a throw calls `broadcast()` before rethrowing.
  The handlers for `IPC.tabsClose`, `tabsActivate`, `tabsPin`, `tabsUnpin`,
  `tabsReorder`, `tabsArchive`, `tabsRestore`, `tabsRemove`, and
  `tabsNavigate` wrap their body in it. `showTabContextMenu`'s per-item
  `catch` also calls `broadcast()` after logging. The renderer keeps its
  `.catch(() => {})`: the re-broadcast is what removes the stale row.

### 6. Seed predicate (#23)

`createWindow(seed)` seeds the default tab only when
`seed && store.allOpenTabs().length === 0 && store.allArchivedTabs().length === 0`.
A store whose every tab is archived opens with an empty content pane and
the archived list available in the sidebar footer.

### 7. Renderer `apps/ui/src/App.tsx`

`TabRow` receives `unloaded: boolean` (from `state.unloadedTabIds`) and adds
the class `tab-item--unloaded` plus `data-unloaded="true"` when set.
`App.css` renders the row's favicon and title at reduced opacity (`0.55`);
nothing else changes. Activating an unloaded row goes through the unchanged
`tabs.activate` path, which materializes the view.

### 8. Tests

Unit (`packages/core`):

- `view-unload.test.ts`: empty input; visible tab never selected; audible
  tab never selected; boundary `now - lastActiveAt === maxIdleMs` kept,
  `+ 1` selected; order preserved.
- `space-store.test.ts`: `createInSpace` on an inactive space makes the tab
  that space's active tab and leaves the active space and its tab list
  untouched; unknown space throws; `activeTabIdOf` mirrors each space's
  pointer and throws on unknown id.

e2e (`e2e/tests/app.spec.ts` unless noted; helpers from PRD 9.1):

- Archive tears down: create a tab at a token `data:` URL, archive it,
  `waitForViewGone(token)`; restore it, `waitForViewUrl(token)`;
  `unloadedTabIds` never lists it while archived (it is not in `tabs`).
- Space switch unload: space A with two tabs (token A1 active, A2), switch
  to space B; `waitForViewGone(A2)`, A1 view still present; switch back;
  A1 visible, `unloadedTabIds` equals `[A2's id]` until A2 is activated,
  then `waitForViewUrl(A2)` and `unloadedTabIds` is `[]`.
- Idle unload: launch with `ZEO_E2E=1 ZEO_VIEW_UNLOAD_AFTER_MS=500 ZEO_VIEW_UNLOAD_INTERVAL_MS=200`;
  two tabs in one space; the inactive one's view is gone within the poll
  timeout and the active one's view stays; `unloadedTabIds` lists exactly
  the unloaded id.
- Popup: a local fixture page (the `startLocalPageServer` helper) whose
  script calls `window.open("<fixture>/child")`; after a click on the page,
  `BrowserWindow.getAllWindows().length` stays `1`, a new tab with the
  child URL exists in the same space and is active, and its view runs on
  the owning space's partition. A second fixture calls
  `window.open("javascript:void 0")`: no tab is created and the tab count
  is unchanged.
- Seed (`persistence.spec.ts`): archive every tab, wait for the debounced
  save, relaunch; `tabs` is empty, `archived` has the tab, and no
  `example.com` seed tab exists.
- Re-sync (#41): register an `onStateChange` counter in the sidebar,
  archive a tab over the bridge, then call `tabs.activate(archivedId)`;
  the invoke rejects with `Cannot activate an archived tab` AND the
  counter increments after the rejection settles; the same holds for
  `tabs.close(archivedId)`.

## Constraints

- `packages/core` must not import `electron`; `isCurrentlyAudible` and
  every `webContents` read stays in `apps/desktop`.
- A view is never unloaded while it is the visible tab, and never while
  audible. A pinned tab is unloadable like any other; pinning is a sidebar
  position, not a memory pledge.
- Unloading changes no persisted state: `lastActiveAt`, order, pin, and
  archive flags are untouched; only `views` and `unloadedTabIds` change.
- The `ZEO_VIEW_UNLOAD_*` overrides are read only when `ZEO_E2E === "1"`.
- TypeScript strict; no `any`.
- Nothing under `.github/workflows/` is written.
- Conventional Commits; no AI attribution.
- Versioning: bump root `package.json` patch to the next free version at
  rebase time and add a dated `CHANGELOG.md` section (`### Changed` for
  unloading and popups, `### Fixed` for #23 and #41). No schema change:
  `unloadedTabIds` is derived, not stored.

## Acceptance criteria

1. Archiving a tab (manually or by the idle sweep) leaves no `WebContents`
   for it; restoring recreates one at the tab's stored url.
2. Switching spaces destroys every view of the outgoing space except its
   own active tab and any audible tab; switching back shows the kept view
   without a reload and the rest reload on activation.
3. With the e2e overrides, a hidden silent view older than the threshold
   is unloaded by the timer and the visible view is not.
4. `window.open` and `target="_blank"` never create a `BrowserWindow`; an
   http(s) target becomes a tab in the owning space on that space's
   partition; a non-http(s) target is dropped.
5. Relaunching with an archive-only store seeds no tab.
6. A rejected tab command from the sidebar is followed by a
   `stateChange` broadcast, and the stale row disappears.
7. `TabsState.unloadedTabIds` is present on every broadcast and lists
   exactly the active space's open tabs without a view; the sidebar dims
   those rows.
8. `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm e2e` pass on both
   CI jobs.
