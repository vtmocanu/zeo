# PRD 10.6 — Secondary surfaces: settings sheet, find pill, quick-browse, split, dialogs

## Context

zeo is a keyboard-first, workspace-centric open-source browser for macOS. Epic 10 gives it an
Arc-like visual language defined in `docs/design/README.md` (the design book; section numbers below
refer to it). PRDs 10.1–10.5 have merged: tokens and per-component CSS (10.1), frameless chrome with
`contentRect`, `ChromeState` and `DIVIDER_WIDTH = 8` (10.2), space themes with
`useThemeTokens(activeSpaceTheme(state))` (`useActiveSpaceTheme()` in the overlay) in every
renderer (10.3), the sidebar (10.4) and the full-window command bar with its scrim (10.5).

This PRD restyles the surfaces zeo draws outside the sidebar and the command bar (§6 Settings, Find
bar, Popovers/dialogs; §2 Split view). Before this PRD (`origin/main` plus 10.1–10.5):

- Settings is a lazily created `WebContentsView` covering the content card
  (`apps/desktop/src/main/settings.ts:14-20,30-70`; 10.2's `settingsBounds(W, H, chrome)` =
  `contentRect(W, H, chrome)`, radius `CARD_RADIUS`), a two-column page with no sheet.
- The find bar is the `surface === "find"` branch of the command-bar overlay, a 360 × 44 view
  inset 12 px from the card's top right (10.2's `findBarBounds(W, H, chrome)`;
  `apps/desktop/src/main/overlay.ts:25-28`) with text glyphs ↑ ↓ ✕
  (`apps/ui/src/FindBar.tsx:150,161,172`).
- Quick-browse is a frameless 480 × 640 `BrowserWindow` whose own webContents renders the chrome
  (`apps/desktop/src/main/quick-browse.ts:181-194`) above a page view at `y =
  QUICK_BROWSE_CHROME_HEIGHT` (44, `packages/core/src/layout.ts:82,89-94`). Its root is `height:
  100vh; align-items: center`, so the buttons render at the vertical middle of the window, under the
  page view, instead of in the top bar.
- Split view shows two `.window-card` layers (10.2's `WindowBackdrop`) around an 8 px divider
  view that 10.2 made transparent, with a transparent `.divider-handle`
  (`apps/ui/src/Divider.tsx:97-107`), and marks the focused pane only in the sidebar
  (`.tab-item--pane-focused`).
- The only confirm-style UI is the two-step history clear (`apps/ui/src/Settings.tsx:969-988`): a
  button reveals an inline "Confirm clear" danger button. `apps/ui/src/App.tsx` has none
  (`archived-delete`, App.tsx:446-448, deletes at once; space delete is a native menu item).

No schema change. Downloads stay a command-bar mode (restyled in 10.5); no downloads popover is
added. Open animations belong to 10.7.

## Deliverables

### 1. Core geometry (`packages/core/src/layout.ts`)

```ts
import type { ChromeState, Rect } from "./chrome.js";
import type { PaneSide, WindowLayout } from "./split-view.js";

export const SETTINGS_SHEET_WIDTH = 760;
export const SETTINGS_SHEET_HEIGHT = 500;
export const SHEET_MARGIN = 24;
export const FIND_BAR_WIDTH = 360;
export const FIND_BAR_HEIGHT = 38;
export const FIND_BAR_INSET = 8;
export const FIND_BAR_SHADOW_MARGIN = 16;
export const QUICK_BROWSE_CHROME_HEIGHT = 48;

export function settingsBounds(contentWidth: number, contentHeight: number): Rect;
export function settingsSheetRect(viewportWidth: number, viewportHeight: number): Rect;
export function findAnchorRect(
  contentWidth: number, contentHeight: number, chrome: ChromeState,
  layout: WindowLayout, tabId: string | null,
): Rect;
export function findPillRect(anchor: Rect): Rect;
export function findBarBounds(anchor: Rect): Rect;
export interface WindowCardRect { pane: "single" | PaneSide; rect: Rect; focused: boolean }
export function windowCardRects(
  contentWidth: number, contentHeight: number, chrome: ChromeState, layout: WindowLayout,
): WindowCardRect[];
```

`FIND_BAR_WIDTH` is unchanged; `FIND_BAR_HEIGHT` (44 → 38), `FIND_BAR_INSET` (12 → 8) and
`QUICK_BROWSE_CHROME_HEIGHT` (44 → 48) change value; the other constants are new.

- `settingsBounds` returns `{ x: 0, y: 0, width: W, height: H }`: the whole content area. It
  replaces 10.2's `settingsBounds(W, H, chrome)` and no longer takes `chrome`.
- `settingsSheetRect`: `width = max(0, min(760, W − 2·24))`, `height = max(0, min(500, H − 2·24))`,
  `x = round((W − width) / 2)`, `y = round((H − height) / 2)`; all-zero when either dimension is 0.
  At `MIN_WINDOW_SIZE` (640 × 400) the sheet is 592 × 352 at (24, 24), so it always fits with its
  margin.
- `findAnchorRect` is the card the find session belongs to: when `layout.mode === "split"` and
  `tabId` is `layout.left` or `layout.right`, the matching pane rect from
  `splitPaneBounds(contentWidth, contentHeight, chrome, layout.ratio)` (the 10.2 signature);
  otherwise `contentRect(contentWidth, contentHeight, chrome)`.
- `findPillRect`: `width = min(360, anchor.width − 2·8)`; all-zero when `width <= 0`; else `{ x:
  anchor.x + anchor.width − width − 8, y: anchor.y + 8, width, height: 38 }`.
- `findBarBounds` replaces 10.2's `findBarBounds(W, H, chrome)`. It is the overlay view's rect:
  the pill grown by 16 px on every side so `--shadow-popover` is not clipped (all-zero when the
  pill is). With `CARD_INSET = 8` the grown
  rect never has a negative `x` or `y`.
- `windowCardRects`: single → one `{ pane: "single", rect: contentRect(...), focused: false }`;
  split → `left` and `right` from `splitPaneBounds`, with `focused` true on `layout.focused`.
- Remove `FIND_BAR_TOP` (the top inset is `FIND_BAR_INSET`) and its export in
  `packages/core/src/index.ts`; export every new name above.

`packages/core/src/settings.ts:30`: the `blocking` section title becomes `"Content blocking"` (§6).
Ids and order do not change.

`packages/core/src/commands.ts:253`: `find.open` is enabled only when `context.activeTab !== null &&
!context.settingsOpen`. Update the doc comment.

### 2. Settings sheet

**Main (`apps/desktop/src/main/settings.ts`).** `settingsBoundsRect()` returns `settingsBounds(w,
h)` (full window). On creation the view gets `setBackgroundColor("#00000000")`, and 10.2's
`setBorderRadius(CARD_RADIUS)` call on it is dropped. `openSettings()`
calls `runtime.closeFindSession?.(false)` before adding the view, so a find pill never floats over
the scrim. Z-order stays tabs < divider < settings < overlay (`raiseOverlays`, views.ts:56-69), so
the 10.5 command bar still opens above the sheet. 10.2's `relayoutWindow()`
(`apps/desktop/src/main/chrome.ts`), run on window resize, already re-applies the bounds. While the sheet is open the view covers the sidebar: sidebar clicks, hover
reveal and window dragging are unavailable until it closes. The native traffic lights stay visible
and usable above it.

### 3. In-app confirmation dialog

New `apps/ui/src/ConfirmDialog.tsx` and `apps/ui/src/styles/dialog.css` (added to
`styles/index.css`); pure helpers in `apps/ui/src/dialog.ts`.

```ts

  title: string;
  body: string;
  confirmLabel: string;
  destructive: boolean;

  onCancel: () => void;
}
export function ConfirmDialog(props: ConfirmDialogProps): ReactElement;
export function nextFocusIndex(current: number, count: number, backwards: boolean): number;
```

- Markup: `div.dialog-scrim` (`position: absolute; inset: 0`, `--scrim`) containing `div.dialog`
  with `role="alertdialog"`, `aria-modal="true"`, `aria-labelledby` and `aria-describedby` pointing
  at its title and body, `data-testid={testId}`. The dialog is `width: min(380px, calc(100% −
  48px))`, padding 20 px, radius `--radius-palette`, `--surface-popover`, `--ink-popover`,
  `--shadow-palette`. Title 15/600 (`--text-md`), margin 0 0 6 px. Body 13 px, line-height 1.45,
  `--ink-popover-secondary`, margin 0 0 18 px. Actions right-aligned with 8 px gap: Cancel
  (`.dialog__button`, the `.settings__button` look), then confirm (`.dialog__button--danger` when
  `destructive`, else `--primary`). Buttons get testids `${testId}-cancel` and the caller's confirm
  testid (below).
- Behavior: Cancel is focused on open (macOS default for destructive dialogs). Tab and Shift+Tab
  cycle between the two buttons through `nextFocusIndex` (wraps both ways). Escape calls
  `preventDefault()`, `stopPropagation()` and `onCancel`. A scrim click uses the same both-targets
  rule as the settings scrim. On close, focus returns to the element that was focused before the
  dialog opened.
- The dialog is rendered inside the sheet (`.settings` is its containing block), so it dims only the
  sheet and no extra native view is needed.
- History clear (Settings.tsx:924-991): the trigger stays `settings-history-clear`, relabeled "Clear
  Browsing History…" in the `--danger` text color. It opens `ConfirmDialog` with `testId =
  "settings-history-clear-dialog"`, title "Clear browsing history?", body "This removes {entries}
  entries and {visits} visits. It cannot be undone." (from the loaded stats), confirm label "Clear
  History" with testid `settings-history-clear-confirm`, and `destructive: true`. Confirm runs the
  existing `onConfirmClear` (clear, re-read stats, close). Cancel closes with no call.
- No other confirm-style UI exists in `Settings.tsx` or `App.tsx`; this PRD adds no new
  confirmations (archived delete and space delete keep their current behavior).

## Constraints

- `packages/core` stays free of `electron`, DOM and `node:*` imports.
- Plain CSS with custom-property tokens; no literal colors outside `tokens.css`
  (`scripts/check-css-tokens.mjs` passes). The `"#00000000"` view background strings are TypeScript,
  not CSS.
- No new runtime dependencies. TypeScript strict, no `any`.
- Keep every `data-testid`, ARIA role and e2e-asserted class name, in particular
  `.settings__sections`, `.settings__section-item--highlight`, `aria-current` on section rows, every
  `find-*`, `quick-browse*`, `settings-*`, `divider-handle` and `.tab-item--pane-focused`. New
  testids: `settings-scrim`, `settings-close`, `settings-history-clear-dialog`,
  `settings-history-clear-cancel`.
- Main-process files stay under the 800-line `max-lines` ceiling; `lint:cycles` stays green
  (settings.ts reaches find only through `runtime.closeFindSession`).
- No animations in this PRD (10.7 owns `--motion-*`).
- Nothing under `.github/workflows/` is written. Conventional Commits; no AI attribution.

## Acceptance criteria

1. The settings view covers the whole window with a transparent background, paints `--scrim`, and
   shows a sheet at `settingsSheetRect` at every window size down to 640 × 400. Escape, the close
   button and a scrim click close it; a click inside the sheet does not.
2. The sheet has a 200 px nav in a well with the five sections (Content blocking renamed), selected
   row `--accent-soft`, and every group in a well with hairline row separators; all existing
   settings e2e cases pass.
3. Clearing history goes through an `alertdialog` with Cancel focused. Escape and Cancel leave
   history and the sheet intact, and only `settings-history-clear-confirm` clears.
4. The find overlay's bounds equal `findBarBounds(findAnchorRect(...))`; the 38 px pill sits 8 px
   inside the top-right of the active card, including collapsed sidebar and either split pane, and
   follows ratio and sidebar changes.
5. `find.open` is disabled while settings is open, and opening settings closes an open find session.
6. The quick-browse bar is 48 px with the title/URL stack, Open in Tab (accent), Move to Space… and
   a Dismiss icon button, all inside the top 48 px; the page view starts at y 48; the bar drags the
   window.
7. In split, the focused pane's card shows a 2 px `--accent-soft` ring that moves with pane focus;
   the divider view is transparent with a grip in the 8 px gap.
8. `pnpm lint`, `pnpm typecheck`, `pnpm build`, `pnpm test` and `pnpm e2e` pass.
