# PRD 10.4 — Sidebar: URL pill, global favorites, Clear, bottom bar

## Context

zeo is a keyboard-first, workspace-centric open-source browser for macOS. Epic 10 source: `docs/design/README.md`
(authoritative) and `docs/design/design-book.html` (visual detail, `renderSidebar` and the `.zw-*` rules). This PRD
implements README §6 "Sidebar, top to bottom" and the §10 decision "Favorites are global". It assumes PRDs 10.1
(tokens, `apps/ui/src/styles/`), 10.2 (frameless chrome, `.window-row`, `TabsState.chrome`, `contentRect`) and 10.3
(`Space.theme`, `ThemePicker`) have merged.

Today `apps/ui/src/App.tsx` renders a "Tabs" header with "+ New tab" (:838-848), a text space switcher (:850-904),
pinned and unpinned sections in `.sidebar__sections` (:906-927), the update banner (:929-956) and a text footer
(:958-1001). Pinning is a per-tab boolean inside one space (`tab.ts:17`); there are no favorites, no domain display
and no bulk archive.

Effective schema version `N` = main's `SCHEMA_VERSION` (`persistence.ts:19`) at rebase time + 1; PRDs 10.2 and 10.3
each claim one before it, so with no collision `N` is `15`. Every `15` below (step key, `UPDATE meta`, test
expectations, acceptance criterion) is that same `N`, substituted once.

```ts
export interface Favorite {
  id: string;
  url: string;
  title: string;

export interface FavoriteContextMenuResult {

```

`faviconUrl` lets a tile show its icon while no tab for it is open. `position` is always the contiguous index `0..n-1`
in display order; every mutation renumbers. Export everything from the core barrel.

### 2. Tab, store and snapshot changes

**`Tab`** (`tab.ts:7-20`) gains `favoriteId: string | null`. A tab with a non-null `favoriteId` is that favorite's
instance in its space: it is never pinned, never archived, and is drawn as the favorite tile, not as a row.

**`TabStore`** (`tab-store.ts`):

```ts
create(input: { url: string; title?: string; favoriteId?: string | null }): Tab;
setFavorite(id: string, favoriteId: string | null): void;
archiveToday(): string[];
```

- `TabRecord`, `hydrate` (:66-96) and `toTab` (:103-114) carry `favoriteId` (default `null`).
- `setFavorite` throws on an unknown or archived id. A non-null value sets `pinned = false`; any change moves the
  record to the end of the array, so it lands last in its new group.
- Groups become three: pinned, today (unpinned, `favoriteId === null`) and favorite (unpinned, `favoriteId !== null`).
  `reorder` (:406-438) computes its group with this three-way key, so a today-section drop index matches the rendered
  rows. `list()` (:541-546) returns pinned, then today, then favorite tabs, each in array order. `menu.ts:30-44`
  "Activate Tab N" follows this order.
- `pin` throws `Cannot pin a favorite tab: <id>`; `archive` throws `Cannot archive a favorite tab: <id>`;
  `archiveIdle` (:498-514) skips favorite tabs like pinned ones. `close` and `remove` are unchanged.
- `archiveToday` archives every open today tab (unpinned, non-favorite), the active one included, with one `now()`
  stamp and fresh `archivalSeq` in `list()` order. If the active tab was archived, `activateMru()` picks among the
  remaining pinned and favorite tabs, or `null`. It returns the archived ids, `[]` when there were none.

**`SpaceStore`** (`space-store.ts`) owns the ordered favorites array:

```ts
favorites(): Favorite[];
addFavorite(tabId: string): Favorite;
removeFavorite(favoriteId: string): string[];
reorderFavorite(favoriteId: string, toIndex: number): void;
favoriteTabId(favoriteId: string): string | null;
createFavoriteTab(favoriteId: string): Tab;
archiveToday(): string[];
```

- `addFavorite` throws for an unknown tab, an archived tab, a tab outside the active space, a tab that already has a
  `favoriteId`, and when `favorites().length === FAVORITES_MAX` (`Favorites are full: 12`). Otherwise it appends `{
  id: idFactory(), url, title, faviconUrl }` copied from the tab with `createdAt: now()`, then `setFavorite(tabId,
  id)` (which unpins a pinned tab). Duplicate URLs are allowed.
- `removeFavorite` throws on an unknown id, deletes the favorite, calls `setFavorite(tabId, null)` on every open tab
  in every space that links it (each becomes the last today row of its space) and returns those tab ids.
- `reorderFavorite` has `TabStore.reorder` semantics: non-integer throws, unknown id throws, index clamped to `0..n-1`
  against the pre-removal length.
- `favoriteTabId` returns the active space's open tab with that `favoriteId`, or `null`. `createFavoriteTab` throws
  when one already exists (at most one open tab per favorite per space), otherwise creates it in the active space with
  the favorite's url and title and that `favoriteId`; it becomes the active tab.
- `archiveToday` delegates to the active space's `TabStore.archiveToday`. `deleteSpace` (:295-311) leaves favorites
  untouched; the space's favorite tabs go with its other tabs.
- `updateMeta` (:507-517) returns `{ changed, inActiveSpace, favoritesChanged }`. When a `faviconUrl` update is
  non-null, the tab has a `favoriteId` and `siteKeyForUrl(tab.url) === siteKeyForUrl(favorite.url)` (both non-null),
  the favorite's `faviconUrl` is set too.
- `snapshot()` (:592-597) adds `favorites: this.favorites()`.

**`StoreSnapshot`** (`ipc.ts:42`) gains `favorites: Favorite[]`, so `TabsState.favorites` rides every broadcast. The
`App.tsx` initial `TabsState` literal (:561-600, the only renderer default; Settings and QuickBrowse start from `null`)
adds `favorites: []`; every hand-built
`Tab` in tests adds `favoriteId: null`.

**Persistence codec** (`persistence.ts:60-83`): `TabRow` gains `favoriteId: string | null`; `export type FavoriteRow =
Favorite`; `PersistedState` gains `favorites: FavoriteRow[]`. `toPersisted` emits favorites with their positions and
each tab's `favoriteId`. `fromPersisted` restores favorites sorted by `position` and renumbers them, then repairs tabs
before `TabStore.hydrate`: a `favoriteId` naming no restored favorite, on an archived row, or on a second open tab of
the same space for the same favorite (the first in `position` order wins) becomes `null`; a repaired favorite tab with
`pinned = 1` restores unpinned.

### 3. Schema `N` (illustrative 15), `apps/desktop/src/main/db.ts`

```sql
CREATE TABLE favorites (
  id TEXT PRIMARY KEY, url TEXT NOT NULL, title TEXT NOT NULL,
  faviconUrl TEXT, position INTEGER NOT NULL, createdAt INTEGER NOT NULL
);
```

- `FAVORITES_DDL` holds that statement; `DDL` (db.ts:90-137) includes it before `tabs`, and `tabs` gains `favoriteId
  TEXT REFERENCES favorites(id) ON DELETE SET NULL`. `MIGRATION_STEPS[15]` = `FAVORITES_DDL` + `ALTER TABLE tabs ADD
  COLUMN favoriteId TEXT REFERENCES favorites(id) ON DELETE SET NULL;` + `UPDATE meta SET schemaVersion = 15 WHERE id
  = 0;`. `SCHEMA_VERSION` becomes `15`.
- `readState` (:1049-1074) selects `favoriteId` for tabs and `SELECT id, url, title, faviconUrl, position, createdAt
  FROM favorites ORDER BY position`.
- `writeState` (:1084-1137) keeps favorites inside the full-state flush so `tabs.favoriteId` and the favorites rows
  are always written in the same transaction. Order: upsert profiles, spaces, favorites, tabs (with `favoriteId`);
  delete-absent tabs, spaces, profiles, favorites; update meta.

### 4. Commands, context and native menus

`packages/core/src/commands.ts` adds three `CommandId`s and registry entries after `tab.unpin`:

| id | title | keywords | accelerator | menu |
| --- | --- | --- | --- | --- |
| `tab.favorite` | Add to Favorites | favorite, favourite, star, tab | null | tabs |
| `tab.unfavorite` | Remove from Favorites | unfavorite, favorite, remove, tab | null | tabs |
| `tabs.clearToday` | Clear Today's Tabs | clear, archive, today, tabs, all | null | tabs |

`tab.pin` drops the `favorite` and `essentials` keywords. `CommandContext.activeTab` gains `favorite: boolean`;
`CommandContext` gains `favoritesFull: boolean` and `clearableTabCount: number`. Enablement: `tab.favorite` needs an
active non-favorite tab and `!favoritesFull`; `tab.unfavorite` needs an active favorite tab; `tabs.clearToday` needs
`clearableTabCount > 0`; `tab.pin` and `tab.archive` additionally need `!activeTab.favorite`. Main `commandContextOf`
(main commands.ts:41-82) fills the new fields from the store (`clearableTabCount =
clearableTabIds(store.list()).length`). Handlers (main commands.ts:90): `tab.favorite` → `addFavorite(activeTabId)`,
`tab.unfavorite` → `removeFavorite(activeTab.favoriteId)`, `tabs.clearToday` → `clearTodayTabs()`.

Native tab menu (`tabs.ts:266-342`): a second item after pin/unpin, id `favorite` "Add to Favorites" (enabled while
not full) or `unfavorite` "Remove from Favorites" for a favorite tab. Pin/unpin and Archive are disabled on a favorite
tab. Unpinned descriptor order: `pin, favorite, moveToTop, moveToBottom, archive, close, copyUrl`.

Native favorite menu, `showFavoriteContextMenu(favoriteId, x, y)`, gated on `ZEO_E2E` like the tab menu: `open`
"Open", `copyUrl` "Copy URL", `close` "Close Tab" (enabled only when the active space has an open tab for it),
`remove` "Remove from Favorites". An unknown id returns `items: []`.

### 6. Core sidebar helpers `packages/core/src/sidebar.ts`

```ts
export const URL_PILL_HEIGHT = 34;
export const TAB_ROW_HEIGHT = 34;
export const FAVORITE_TILE_HEIGHT = 48;
export const FAVORITE_TILE_GAP = 6;
export const FAVORITES_MAX_COLUMNS = 4;

export function favoriteGridColumns(count: number, sidebarWidth: number): number;
```

- `sidebarSections` partitions by pinned / `favoriteId === null` / favorite, keeping input order; `clearableTabIds` is

- `urlPillLabel`: `null`, `""`, `about:blank` and unparseable input → `""`; `http:`/`https:` → `hostname` without a
  leading `www.` (no port); any other parseable URL → its protocol without the colon (`data`, `file`, `about`).
- `favoriteGridColumns`: `0` when `count === 0`, else `max(1, min(4, count, floor((sidebarWidth − 2·8 + 6) / (48 +

- `favoriteInsertIndex` counts tiles that precede the pointer in reading order: `y > bottom`, or `top ≤ y ≤ bottom`
  and `x > (left + right) / 2`.
- `belowPinnedClip` = `max(0, scrollTop + pinnedHeight − belowOffsetTop)`.
