# PRD 10.1 — Design foundation: tokens, theme function, per-component CSS

## Context

zeo is a keyboard-first, workspace-centric open-source browser for macOS.
Epic 10 gives it an Arc-like visual language. The source for every Epic 10
PRD is the design book: `docs/design/README.md` (text spec, authoritative)
and `docs/design/design-book.html` (interactive version). Section numbers
below (§3, §4, …) refer to the README. If the design book is not on `main`
yet, read it from PR #161: `git fetch origin docs/epic-10-design && git show
FETCH_HEAD:docs/design/README.md`.

Today all renderer styling lives in one file, `apps/ui/src/App.css` (about
1,190 lines, about 150 hard-coded hex colors, dark-only, `system-ui` font,
`:root { color-scheme: light dark; }` but no light palette). It is imported
separately by `App.tsx`, `CommandBar.tsx`, `Divider.tsx`, `FindBar.tsx`,
`QuickBrowse.tsx` and `Settings.tsx`. There are no CSS custom properties, no
`prefers-color-scheme` handling and no CSS lint. One bundle serves five
surfaces, selected by the `?view=` query param in `apps/ui/src/main.tsx`: the
sidebar (`App`, the main window's own webContents), the command-bar/find
overlay (`Overlay`), settings (`Settings`), the quick-browse chrome
(`QuickBrowse`) and the split divider (`Divider`).

This PRD lays the foundation every later Epic 10 PRD builds on:

- the pure theme function `themeTokens()` in `packages/core`, with an
  exhaustive contrast sweep;
- the three token tiers as CSS;
- `App.css` split into one file per component, every color read from a
  semantic token;
- light and dark appearance following the system in every surface;
- a lint step that rejects literal colors in component CSS.

Layout, geometry, spacing and components stay as they are: this PRD changes
colors, fonts and file structure, not layout. Spaces have no theme yet
(PRD 10.3 adds it), so every surface renders the null theme: plain window,
iris accent. The visible result is that zeo gains a light appearance and
its dark appearance moves to the new neutral palette.

## Deliverables

### 1. Core `packages/core/src/theme.ts`

Pure TypeScript, no DOM, no Electron. Export everything below from the core
barrel (`packages/core/src/index.ts`).

Algorithm (it must match §3 of the design book; the interactive book runs a
prototype of the same steps):

- **Constants.** Window base `light [234,234,238]`, `dark [32,32,36]`. Card
  `light [255,255,255]`, `dark [27,27,31]`. Popover base `light
  [250,250,252]`, `dark [44,44,49]`. Ink candidates: dark `[26,26,31]`, light
  `[245,245,247]`. Tint lightness `light 0.78`, `dark 0.48`. Max tint
  opacity `light 0.55`, `dark 0.35`.
- **`oklchToRgb`.** Standard OKLCH → OKLab → linear sRGB → gamma-encoded
  sRGB, each channel clamped to 0–1 before encoding, returned as 0–255
  floats.
- **`contrastRatio`.** WCAG 2.x relative luminance and `(L1 + 0.05) / (L2 + 0.05)`.
- **Intensity.** Clamp to 0–1; `NaN` counts as 0.
- **Tint.** When the theme is null or intensity is 0, the tint is removed:
  no tint stops, tint `transparent`, opacity `0.000`. Otherwise each stop is
  `oklchToRgb(tintL, hue.c, hue.h)`, opacity = max opacity × intensity.
- **Grounds.** Each stop composited over the window base:
  `base + (tint − base) × opacity` per channel. With no stops, the single
  ground is the base.
- **Ink.** The candidate with the higher minimum contrast across all
  grounds.
- **Window backgrounds.** For each ground, four backgrounds that
  secondary text can sit on: the ground itself, and the ground with
  `--surface-raised`, `--surface-hover` and `--fill-subtle` composited over
  it (alpha blend of the token color at its alpha, see the token table).
- **Ink secondary.** For `m` from 0.56 to 1.00 in steps of 0.02, mix the
  average ground toward the ink by `m`; take the first result whose minimum
  contrast across all window backgrounds is ≥ 4.5. If none, use the ink.
- **Accent.** Hue from the first stop, intensity 0 included: intensity 0
  removes the tint but the accent still comes from the first stop. The
  accent falls back to iris only for a null theme. Chroma
  `min(hue.c + 0.03, 0.19)`. Lightness starts at 0.54 (light) or 0.76
  (dark); up to 14 times, stop when contrast against the card ≥ 3 and the
  minimum against the grounds ≥ 3, otherwise move lightness by −0.02
  (light) or +0.02 (dark).
- **Ink on accent.** White or the dark ink, whichever has higher contrast
  on the accent.
- **Popover ink.** Dark ink in light, light ink in dark. Popover
  backgrounds: the popover base, and the base with `--popover-well`,
  `--popover-hover` and `--control-raised` composited over it. Secondary:
  mix the popover base toward the popover ink from 0.50 in steps of 0.02
  until the minimum contrast across popover backgrounds is ≥ 4.5.
- **Danger.** `oklchToRgb(0.55, 0.20, 27)` light, `oklchToRgb(0.70, 0.17, 25)` dark.
  Ink on danger: white or the dark ink, whichever has higher contrast on
  the danger color (white in light, dark ink in dark).

Token values (`rgba(x, a)` means `rgb(r g b / a)` with rounded channels;
hex via `toHex`, lower case):

| Token | Value |
| --- | --- |
| `--surface-window` | `rgba(base, 0.88)` |
| `--tint` | `transparent`, one stop as hex, or `linear-gradient(160deg, <hex1>, <hex2>)` |
| `--tint-opacity` | opacity with three decimals |
| `--surface-card` | card hex |
| `--surface-raised` | `rgba(white, 0.8)` when ink is dark, else `rgba(white, 0.15)` |
| `--surface-hover` | `rgba(ink, dark ? 0.1 : 0.08)` |
| `--fill-subtle` | `rgba(ink, dark ? 0.09 : 0.06)` |
| `--hairline` | `rgba(ink, 0.12)` |
| `--ink-primary`, `--ink-secondary` | hex |
| `--accent`, `--focus-ring` | accent hex |
| `--accent-soft` | `rgba(accent, dark ? 0.3 : 0.16)` |
| `--ink-on-accent` | hex |
| `--danger`, `--ink-on-danger` | hex |
| `--surface-popover` | `rgba(popover, 0.94)` |
| `--ink-popover`, `--ink-popover-secondary` | hex |
| `--popover-hairline` / `-strong` / `--popover-hover` / `--popover-well` | `rgba(popoverInk, 0.1 / 0.28 / 0.07 / 0.035)` |
| `--control-raised` | `#ffffff` light, `rgba(white, 0.14)` dark |
| `--scrim` | `rgba([24,24,32], 0.14)` light, `rgba(black, 0.34)` dark |
| `--shadow-raised` | ink dark: `0 1px 2px rgb(0 0 0 / .08), 0 0 0 .5px rgb(0 0 0 / .06)`; ink light: `0 1px 2px rgb(0 0 0 / .3)` |
| `--shadow-card` | light: `0 0 0 1px rgb(0 0 0 / .07), 0 1px 2px rgb(0 0 0 / .06), 0 6px 18px rgb(0 0 0 / .06)`; dark: `0 0 0 1px rgb(255 255 255 / .07), 0 1px 3px rgb(0 0 0 / .4), 0 8px 24px rgb(0 0 0 / .28)` |
| `--shadow-popover` | light: `0 0 0 1px rgb(0 0 0 / .06), 0 10px 30px rgb(0 0 0 / .14), 0 2px 6px rgb(0 0 0 / .06)`; dark: `0 0 0 1px rgb(255 255 255 / .09), 0 10px 30px rgb(0 0 0 / .45)` |
| `--shadow-palette` | light: `0 0 0 1px rgb(0 0 0 / .06), 0 28px 70px rgb(0 0 0 / .22), 0 6px 18px rgb(0 0 0 / .08)`; dark: `0 0 0 1px rgb(255 255 255 / .1), 0 28px 70px rgb(0 0 0 / .6)` |

`normalizeTheme` turns untrusted input (a parsed JSON column, an IPC
payload) into a valid theme or `null`: `stops` must be an array of one or
two known hues; `intensity` must be a finite number, then clamped to 0–1.
Anything else returns `null`. PRD 10.3 relies on it.

### 2. Token CSS `apps/ui/src/styles/`

Create the directory and these files. `index.css` is the only file imported
by TypeScript.

- `index.css` — `@import` of every file below, tokens and base first.
- `tokens.css` — the only file allowed to contain literal colors. It holds:
  - the static tier on `:root`: spacing `--space-1` … `--space-9` =
    2, 4, 6, 8, 12, 16, 20, 24, 32 px; radius `--radius-control 6px`,
    `--radius-tab 8px`, `--radius-pill 10px`, `--radius-card 10px`,
    `--radius-tile 12px`, `--radius-palette 14px`; type `--font-ui:
    -apple-system, BlinkMacSystemFont, "SF Pro Text", "Helvetica Neue",
    sans-serif`, `--text-xs 11px`, `--text-sm 12px`, `--text-base 13px`,
    `--text-md 15px`, `--text-lg 17px`, `--text-xl 22px`, weights
    `--weight-regular 400`, `--weight-medium 500`, `--weight-semibold 600`,
    `--tracking-label 0.06em`; motion `--motion-fast 120ms`, `--motion-base
    200ms`, `--motion-space 320ms`, `--ease-standard cubic-bezier(.2, .8, .2, 1)`;
  - the null-theme semantic tokens for light on `:root` and for dark under
    `@media (prefers-color-scheme: dark)`, with exactly the values
    `themeTokens(null, "light" | "dark")` returns, so the first paint is
    correct before any script runs. A unit test (§5) keeps them in sync.
- `base.css` — `:root { color-scheme: light dark; }`, box-sizing, `body {
  margin: 0; font-family: var(--font-ui); font-size: var(--text-base);
  color: var(--ink-primary); -webkit-font-smoothing: antialiased; }`.
- One file per component, taking the matching block of `App.css`
  verbatim except for colors and the font stack: `sidebar.css` (sidebar,
  header, sections, empty state, drag and drop), `space-switcher.css`,
  `tab-item.css` (tab rows, icon buttons, shield, zoom badge, split pane
  markers), `update-banner.css`, `archived.css` (footer, downloads
  indicator, archived view), `command-bar.css`, `settings.css`,
  `find-bar.css`, `quick-browse.css`, `divider.css`.

Every color in the component files reads a semantic token. Map today's
dark hexes by role, not by value: backgrounds of the sidebar and settings to
`--surface-window` (the tint layer arrives with PRD 10.2), hover fills to
`--surface-hover`, selected and active rows to `--surface-raised`, borders
and separators to `--hairline` / `--popover-hairline`, primary and muted
text to `--ink-primary` / `--ink-secondary`, the command bar, find bar and
quick-browse chrome to the popover tokens, the `#6b6bff` accent family to
`--accent` / `--accent-soft`, danger buttons to `--danger`. Class names do
not change: e2e tests select `.sidebar__title`, `.sidebar__sections`,
`.sidebar__section--pinned` (asserted `position: sticky`),
`.archived-item__title`, `.tab-item--pane-focused`,
`.settings__section-item--highlight` and `.settings__sections`.

Delete `apps/ui/src/App.css` and its six imports. `apps/ui/src/main.tsx`
imports `./styles/index.css` once.

### 3. Renderer theme application `apps/ui/src/theme.ts`

```ts
import type { Appearance, SpaceTheme } from "@zeo/core";

export function applyThemeTokens(
  root: HTMLElement,
  theme: SpaceTheme | null,
  appearance: Appearance,
): void;
export function useAppearance(): Appearance;
export function useThemeTokens(theme: SpaceTheme | null): void;
```

- `applyThemeTokens` sets every entry of `themeTokens(theme, appearance)`
  with `root.style.setProperty` and sets `root.dataset.appearance`.
- `useAppearance` reads `matchMedia("(prefers-color-scheme: dark)")` and
  re-renders on its `change` event.
- `useThemeTokens` applies to `document.documentElement` in a layout
  effect whenever the theme or appearance changes.
- Call `useThemeTokens(null)` in `App`, `Overlay`, `Settings` and
  `QuickBrowse`. `Divider` paints no themed color beyond its handle and
  reads the stylesheet defaults.

The main window, overlay, settings and quick-browse webContents all follow
the macOS appearance through Chromium's `prefers-color-scheme`; no
`nativeTheme` call is needed in this PRD.

### 4. Literal-color lint `scripts/check-css-tokens.mjs`

A Node script (no dependencies) that scans every `*.css` file under
`apps/ui/src/styles/` except `tokens.css` and fails with `file:line: literal
color "<match>"` for any hex color (`#` followed by 3, 4, 6 or 8 hex digits)
or any `rgb(`, `rgba(`, `hsl(`, `hsla(`, `oklch(` or `color(` call. Named
colors are allowed only as `transparent`, `currentColor` and `inherit`.
Exit code 1 on any finding, 0 otherwise. Wire it into the root `lint`
script: `eslint . && node scripts/check-css-tokens.mjs && pnpm --filter
@zeo/desktop run lint:cycles`.

### 5. Tests

Unit (`packages/core/src/theme.test.ts`):

- `oklchToRgb(1, 0, 0)` rounds to `[255,255,255]`, `oklchToRgb(0, 0, 0)` to
  `[0,0,0]`; out-of-gamut input stays within 0–255.
- `contrastRatio([0,0,0],[255,255,255])` is 21 within 0.01;
  `contrastRatio(a,a)` is 1.
- **Sweep:** for every single hue (10) and every ordered pair of distinct
  hues (90), at intensity 0, 0.5 and 1, in both appearances (600 cases):
  `inkContrast ≥ 4.5`, `inkSecondaryContrast ≥ 4.5`, `accentContrast ≥ 3`,
  `popoverSecondaryContrast ≥ 4.5`, and the danger ink ≥ 4.5 on
  `--danger`. `inkSecondaryContrast` and `popoverSecondaryContrast` are
  minimums over the window and popover backgrounds defined above, not only
  the bare grounds.
- Null theme and intensity 0 both return `--tint` `transparent` and
  `--tint-opacity` `"0.000"`; intensity 1.7 behaves as 1; `NaN` as 0.
- Two stops return `--tint` matching
  `/^linear-gradient\(160deg, #[0-9a-f]{6}, #[0-9a-f]{6}\)$/`.
- Determinism: two calls with equal input return deep-equal output; the
  returned object has exactly the keys in `SEMANTIC_TOKENS`.
- `normalizeTheme`: valid one- and two-stop themes pass through;
  intensity 2 becomes 1; `null`, `{}`, three stops, an unknown hue, a
  string intensity and `NaN` intensity return `null`.

Unit (`apps/ui`, `theme.test.ts` next to `theme.ts`). `apps/ui` has no test
setup today: add `vitest` as a devDependency at the range the other
workspaces use and a `"test": "vitest run"` script. Tests run in the node
environment; test `applyThemeTokens` against a minimal fake root with
`style.setProperty` and `dataset`. Do not add jsdom.

- `applyThemeTokens` sets all `SEMANTIC_TOKENS` and `data-appearance`.
- `tokens.css` parity: parse the `:root` block and the dark media block of
  `tokens.css` (read the file with `node:fs`) and assert each semantic
  token equals `themeTokens(null, appearance)`.

Lint: a unit test runs `scripts/check-css-tokens.mjs` against a temporary
directory containing one clean file and one file with `color: #fff;`, and
asserts exit codes 0 and 1 (make the scanned directory overridable with an
argument for this test).

e2e (`e2e/tests/theme.spec.ts`):

- Sidebar window: `getComputedStyle(document.documentElement)
  .getPropertyValue("--ink-primary").trim()` equals `themeTokens(null,
  appearance).["--ink-primary"]`, where `appearance` is read in the page
  from `matchMedia`.
- Switching appearance: `app.evaluate(({ nativeTheme }) => {
  nativeTheme.themeSource = "dark"; })`, then the sidebar's `--ink-primary`
  equals the dark value; set `"light"` and it equals the light value; reset
  to `"system"` at the end. Repeat the dark check for the settings view
  (open with `settings.open` through the bridge) and the command-bar
  overlay.
- No regressions: the existing suites pass unchanged, including the sticky
  pinned section and the class-name selectors listed in §2.

## Constraints

- `packages/core` stays free of `electron`, DOM and `node:*` imports.
- Plain CSS with custom properties; no Tailwind, no CSS-in-JS, no new
  runtime dependencies. The only new dev dependency is `vitest` in
  `apps/ui`.
- No layout change: sizes, paddings, positions and view bounds stay as they
  are. Fonts move to `--font-ui`.
- Keep every `data-testid`, ARIA role and class name.
- TypeScript strict; no `any`. Nothing under `.github/workflows/` is
  written. Conventional Commits; no AI attribution.
- Versioning: bump the root `package.json` patch to the next free version
  at rebase time and add a dated `CHANGELOG.md` section (`### Changed`:
  light appearance, new palette; `### Added`: theme tokens).
- Leave `prds/` and `docs/design/` untouched.

## Acceptance criteria

1. `themeTokens` and `themeReport` exist in `@zeo/core` with the §1
   signatures, and the 600-case sweep passes.
2. `apps/ui/src/App.css` no longer exists; `apps/ui/src/styles/` holds
   `index.css`, `tokens.css`, `base.css` and the ten component files.
3. `node scripts/check-css-tokens.mjs` passes on the tree and fails on a
   literal color in any component file; `pnpm lint` runs it.
4. With macOS in light mode every surface renders light; in dark mode every
   surface renders dark; switching the system appearance re-colors open
   surfaces without a reload.
5. The computed semantic tokens in the sidebar, settings and overlay equal
   `themeTokens(null, appearance)`.
6. `pnpm lint`, `pnpm typecheck`, `pnpm test`, and `pnpm e2e` pass on both
   CI jobs.
