# PRD 10.7 — Motion and polish

## Context

zeo is a keyboard-first, workspace-centric open-source browser for macOS. The source for Epic 10 is the design book, `docs/design/README.md`. This PRD delivers §7 (motion) and the final pass of §8: focus, hit targets, contrast, and the end-to-end checks.

It assumes PRDs 10.1–10.6 have merged and uses their contracts as they stand:

| PRD | Contracts used |
| --- | --- |
| 10.1 | `themeTokens`, `themeReport`, `SEMANTIC_TOKENS`, `styles/*.css`, `check-css-tokens.mjs` |
| 10.2 | `ChromeState`, `contentRect`, `.window-tint`, `.window-card`, `.window-row` |
| 10.3 | `Space.theme`, `ThemePicker` |
| 10.4 | the sidebar and its testids |
| 10.5 | the full-window command bar and scrim |
| 10.6 | the settings sheet, find pill and dialogs |

Facts on main that shape the design:

- **Space switch.** A switch is one synchronous main-process transition, `switchSpace()` (`apps/desktop/src/main/spaces.ts:215-224`). It sets the active space, unloads the outgoing views, and `reconcileAndApply()` hides the outgoing tab view and shows the incoming one. Only then does `broadcast()` (`broadcast.ts:119-151`) push `TabsState`. The renderer therefore learns of a switch after the native views have already swapped.
- **Tab views.** They are native `WebContentsView`s stacked above the sidebar renderer (`views.ts:56-69`). They have no opacity API.
- **Space order.** Spaces are kept in creation order (`packages/core/src/space-store.ts:71-72, 321-323`). `TabsState.spaces` carries that order, and the 10.4 space dots render in it.
- **Open signals.** The command bar already detects its closed→open transition (`apps/ui/src/CommandBar.tsx:143-146`). Settings and find expose `TabsState.settingsOpen` and `TabsState.find.open`.
- **Existing motion.** The only motion today is `transition: opacity 0.1s ease-in-out` on `.icon-button` (was `App.css:255`).
- **Existing focus styles.** They are defined per component. Several use `outline: none` or `outline-offset: -2px`.
- **e2e harness.** Specs launch with `ZEO_E2E=1` (`e2e/tests/app.spec.ts:487`), find pages with `app.windows()`, and drive the `globalThis.zeo` bridge.

This PRD needs no schema change and no new IPC channel.

## Deliverables

### 1. Core `packages/core/src/motion.ts` (export from the barrel)

```ts
export const MOTION_FAST_MS = 120;
export const MOTION_BASE_MS = 200;
export const MOTION_SPACE_MS = 320;
export const MOTION_REDUCED_MS = 120;
export const EASE_STANDARD = "cubic-bezier(.2, .8, .2, 1)";
export const ENTER_SCALE_FROM = 0.97;
export const SPACE_SHIFT_PX = 28;
export const PRESS_SCALE = 0.96;
export type SpaceSwitchDirection = "forward" | "backward";
export interface SpaceSwitch { from: string; to: string; direction: SpaceSwitchDirection | null }
export function detectSpaceSwitch(previousActiveId: string, nextActiveId: string, spaceIds: readonly string[]): SpaceSwitch | null;
```

`detectSpaceSwitch` returns `null` when the previous id is `""` (the renderer's state before the first broadcast), when the two ids are equal, or when the next id is not in `spaceIds`. Otherwise the direction is `"forward"` when the next space's index is greater than the previous one's, and `"backward"` when it is smaller. The direction is `null` when the previous id is no longer listed, which happens when the active space was deleted (`spaces.ts:24-56`).

### 2. Tokens and `styles/motion.css`

10.1 already defines `--motion-fast`, `--motion-base`, `--motion-space` and `--ease-standard`. Add these to the static tier of `tokens.css`:

```css
--motion-enter-scale: 0.97;
--motion-space-shift: 28px;
--motion-press-scale: 0.96;
--transition-control: background-color var(--motion-fast) var(--ease-standard),
  color var(--motion-fast) var(--ease-standard), opacity var(--motion-fast) var(--ease-standard),
  box-shadow var(--motion-fast) var(--ease-standard), transform var(--motion-fast) var(--ease-standard);
```

`tokens.css` also gets two overrides:

- `@media (prefers-reduced-motion: reduce) { :root { --motion-base: 120ms; --motion-space: 120ms; --motion-press-scale: 1; } }`
- `.zeo-motion-off { --motion-fast: 0ms; --motion-base: 0ms; --motion-space: 0ms; }`

Create `apps/ui/src/styles/motion.css` and import it in `index.css` right after `base.css`. It holds:

- **Keyframes.**
  - `zeo-enter`: from `opacity: 0; transform: scale(var(--motion-enter-scale))`.
  - `zeo-fade-in`: from `opacity: 0`.
  - `zeo-space-in-forward`: from `opacity: 0; transform: translateX(var(--motion-space-shift))`.
  - `zeo-space-in-backward`: the same, with the shift negated by `calc(-1 * …)`.
  - `zeo-tint-in`: from `opacity: 0`.
  - `zeo-tint-out`: to `opacity: 0`.

  The "in" keyframes have no `to` frame, so each one ends at the element's own opacity. For the tint layer that is `var(--tint-opacity)`.
- **Classes.** `.motion-enter { animation: zeo-enter var(--motion-base) var(--ease-standard) both; }`; `.motion-fade`, the same with `zeo-fade-in`; `[data-motion="closed"] { opacity: 0; }`.
- **Reduced motion.** Under `prefers-reduced-motion: reduce`:
  - `.motion-enter`, `.sidebar__space--enter-forward` and `.sidebar__space--enter-backward` switch to `animation-name: zeo-fade-in`.
  - `input, textarea` get `caret-animation: manual`, so the caret stops blinking. Electron 44's Chromium supports this property, and e2e asserts it.
- **Motion off.** `.zeo-motion-off *, .zeo-motion-off *::before, .zeo-motion-off *::after { animation: none !important; transition: none !important; }`

Reduced motion removes every movement: no scale, no slide, no press shrink. Opens and space switches become 120 ms opacity fades. Hover and press color changes keep 120 ms, because they are already cross-fades.

### 3. Where each token applies

| Token | Elements | Rule |
| --- | --- | --- |
| `--motion-fast` | `.window-row` icon buttons, URL pill, favorite tiles, tab rows, tab close, zoom badge, New Tab, Clear, update-banner buttons, bottom-bar buttons (downloads, archived, space dots, new space), archived rows and delete, `ThemePicker` swatches and segments, find buttons, settings section items, buttons and segmented controls, dialog buttons, quick-browse buttons, divider handle | `transition: var(--transition-control)`. Icon buttons, tiles, dots and swatches also get `:active { transform: scale(var(--motion-press-scale)); }` |
| `--motion-base` | Opening the command-bar panel, find pill, settings sheet, `ThemePicker` and 10.6 dialogs, plus their scrims | Panels use `.motion-enter` (scale 0.97 → 1, and fade). Scrims use `.motion-fade` |
| `--motion-space` | Space switch in the sidebar renderer | See §4 |

The literal transition on `.icon-button` becomes `var(--transition-control)`.

By decision, these stay unanimated:

- **Command-bar row selection.** `.command-bar__row` has no transition, because a transition would lag behind held arrow keys.
- **Every close.** Main hides the native view at once, so no frame is left to animate.
- **Sidebar collapse, reveal, resize, and the divider.** They are native view bounds.
- **Theme edits and appearance changes.** They stay instant so the `ThemePicker` slider tracks the pointer.
- **The update banner and the archived list.** §7 does not list them.

Add `apps/ui/src/motion.ts`:

```ts
export type MotionToken = "--motion-fast" | "--motion-base" | "--motion-space";
export function parseDurationMs(value: string): number;
export function motionMs(token: MotionToken): number;
export function motionDisabled(): boolean;
export function replayClass(element: HTMLElement, className: string): void;
export function enterStep(previousOpen: boolean | null, open: boolean): "replay" | "close" | "none";
export function useEnterMotion<T extends HTMLElement>(
  open: boolean,
  className?: "motion-enter" | "motion-fade",
): RefObject<T | null>;
```

- `parseDurationMs` turns `"320ms"` into 320 and `"0.12s"` into 120. Empty or invalid input gives 0.
- `motionMs` applies `parseDurationMs` to the computed value of the token on `<html>`.
- `motionDisabled()` returns true when `<html>` has the `zeo-motion-off` class.
- `replayClass` removes the class, reads `offsetWidth`, and re-adds the class. This restarts the animation without a remount, so focus and input state survive.
- `enterStep` returns `"replay"` when `open` is true and `previousOpen` is not true (`null` means first mount), `"close"` when `open` is false and `previousOpen` is not false, and `"none"` otherwise.
- `useEnterMotion` runs `enterStep` in a layout effect. On `"close"` it sets `data-motion="closed"`. On `"replay"` it sets `data-motion="open"` and replays `className` (default `motion-enter`). The panel turns transparent the moment it closes, so when main shows the native view again it never flashes stale content.

Wire `useEnterMotion` into these components:

| Component | Element | `open` comes from |
| --- | --- | --- |
| `CommandBar` | `.command-bar` panel | `CommandBarState.open`. A mode change while the bar is open does not replay. |
| 10.5 scrim | `command-bar-scrim` (`className` `motion-fade`) | the same flag as the command bar |
| `FindBar` | the find pill | `TabsState.find.open` |
| `Settings` | the 10.6 sheet, and `settings-scrim` with `motion-fade` | `TabsState.settingsOpen` |
| `ThemePicker`, 10.6 `ConfirmDialog` | the picker or `.dialog`, and `.dialog-scrim` with `motion-fade` | true while mounted |

### 4. Space switch (sidebar renderer)

**Detection.** `App` keeps `previousRef = useRef({ activeSpaceId: "", theme: null as SpaceTheme | null })`. A layout effect keyed on `state.activeSpaceId` runs three steps:

1. Call `detectSpaceSwitch(previousRef.current.activeSpaceId, state.activeSpaceId, state.spaces.map((s) => s.id))`.
2. Animate only if the result is non-null and `motionDisabled()` is false.
3. Store the new id and the active space's theme in `previousRef`.

Because the renderer compares the previous and next `activeSpaceId`, every switch path animates: space dots, the ⌃1–9 menu items, command-bar space rows, cross-space `activateTab` and `restoreTab`, and deleting the active space. Theme edits keep the same id, so they stay instant.

**List slide.** One new wrapper, `<div className="sidebar__space" data-space-motion=…>`, holds the space-scoped block of 10.4's sidebar: the `h1.sidebar__title` space label and the `.sidebar__sections` scroll container (the pinned section, then `.sidebar__below-pinned` with the Clear divider and the today section with its New Tab row and `sidebar__empty` state). The wrapper is a flex column with `flex: 1; min-height: 0`, so `.sidebar__sections` stays the only scroll container and the pinned section stays sticky inside it. The window row, URL pill, favorites grid (favorites are global), update banner, the archived panel and space name editor above the bottom bar, and the bottom bar with its space dots stay outside the wrapper and do not move.

A switch replays one class on the wrapper and sets `data-space-motion` to match. All three classes run over `var(--motion-space) var(--ease-standard)`:

| Direction | Class | `data-space-motion` | Motion |
| --- | --- | --- | --- |
| `"forward"` | `sidebar__space--enter-forward` | `forward` | from +28 px, the side of the new space's dot |
| `"backward"` | `sidebar__space--enter-backward` | `backward` | from −28 px |
| `null` | `sidebar__space--enter-fade` | `fade` | `zeo-fade-in` |

Only the incoming list animates. A clone of the outgoing list would duplicate `tab-item`, `pinned-section` and other testids that e2e counts. `.sidebar` gets `overflow-x: clip`, so the 28 px offset never scrolls the sidebar. `clip` creates no scroll container, so the pinned section stays sticky.

**Tint cross-fade.** 10.2's `.window-tint` paints `--surface-window` itself and the tint in its `::after` (`var(--tint)` at `var(--tint-opacity)`). `--surface-window` depends only on the appearance, so only the `::after` changes on a switch. Right after `.window-tint`, the sidebar renders an outgoing tint layer, `<div className="window-tint-outgoing" aria-hidden="true" />` (`position: fixed; inset: 0`, in `styles/window.css`), above `.window-tint` and below the cards and the `<aside>`.

- Its inline `background` and `opacity` are `--tint` and `--tint-opacity` from `themeTokens(previous theme, appearance)`.
- `.window-tint` and `.window-tint-outgoing` are both `pointer-events: none`.
- When a switch changes either value, the effect sets `outgoingTint = { key, tint, opacity }`. The state update happens inside a layout effect, so it renders before paint.
- The outgoing layer then runs `zeo-tint-out` while `.window-tint` replays `window-tint--enter`, whose rule runs `zeo-tint-in` on `.window-tint::after`. Both run over `var(--motion-space) var(--ease-standard)`, so the fade starts exactly at the old tint and ends exactly at the new one.
- The layer unmounts on `animationend`, or on a fallback timer, whichever comes first: `OUTGOING_TINT_START_BACKSTOP_MS` (1500 ms) from mount until its `animationstart` fires, then `motionMs("--motion-space") + 50` ms from the start. A slow first frame therefore cannot remove the layer before its fade-out runs.
- A new switch during a fade gives `outgoingTint` a new `key`, and the fade restarts from that theme.

Every other token (ink, accent, raised, hairline) changes at once in 10.3's layout effect.

**Content views swap instantly.** When the broadcast arrives, main has already hidden the outgoing view and shown the incoming one (`spaces.ts:220-223`). Animating the swap is ruled out: native views have no opacity API, per-frame `setBounds` would reflow the page on every frame, and the incoming tab may still be unloaded and loading (PRD 9.3), so a slide would show an empty card. `.window-card` does not animate either.

### 5. Disabling motion in e2e

- `ZeoApi` (`packages/core/src/ipc.ts:517`) gains `readonly motion: "system" | "off"`.
- The preload (`apps/desktop/src/preload/index.ts:35`) sets `motion` to `"off"` when `process.env.ZEO_E2E === "1"` and `ZEO_E2E_MOTION !== "1"`, and to `"system"` otherwise. UI renderers run with `sandbox: false`, so the preload inherits the environment.
- Before `createRoot`, `apps/ui/src/main.tsx` adds `zeo-motion-off` to `<html>` when `window.zeo?.motion === "off"`.

With this in place, every existing spec runs with zero durations and no animations, so Playwright's stability checks never catch an element in motion. Only `motion.spec.ts` sets `ZEO_E2E_MOTION: "1"`. Packaged builds follow the system setting.

### 8. Contrast audit `packages/core/src/contrast-audit.ts`

```ts
export type ContrastCheckId =
  | "ink-primary/window" | "ink-secondary/window" | "ink-primary/raised" | "ink-secondary/raised"
  | "ink-secondary/hover" | "ink-secondary/fill-subtle" | "accent/window" | "accent/card"
  | "focus-ring/raised" | "focus-ring/popover" | "ink-on-accent/accent" | "ink-popover/popover"
  | "ink-popover-secondary/popover" | "ink-popover/accent-soft" | "ink-on-danger/danger"
  | "danger/popover" | "danger/card";
export interface ContrastCheck { id: ContrastCheckId; ratio: number; floor: 3 | 4.5; pass: boolean }
export function parseCssColor(value: string): { rgb: Rgb; alpha: number } | null;
export function contrastAudit(theme: SpaceTheme | null, appearance: Appearance): ContrastCheck[];
```

`parseCssColor` accepts the two forms `themeTokens` emits, `#rrggbb` and `rgb(r g b / a)`. Anything else returns `null`.

`contrastAudit` reads `themeTokens` and `themeReport(...).grounds`, and composites each color with `base + (top − base) × alpha`. It builds these grounds:

| Ground | Definition |
| --- | --- |
| Window | the report's grounds |
| Raised, hover, fill-subtle | the matching token composited over each window ground |
| Popover | `--surface-popover` over the color of `--surface-window` |
| Popover-secondary | the worst of the popover ground and `--popover-well`, `--popover-hover` and `--control-raised` over it |
| Accent-soft | `--accent-soft` over the popover ground |

Each ratio is the worst case across its grounds. The floor is 3 for `accent/*` and `focus-ring/*`, and 4.5 for every other check.

This PRD makes one change to `theme.ts`, described at the end of this section. Otherwise it relies on these 10.1 guarantees (10.1 §1 algorithm, enforced by its §5 sweep):

- `--ink-secondary` holds 4.5 on every window ground and on `--surface-raised`, `--surface-hover` and `--fill-subtle` composited over it, so `ink-secondary/window`, `/raised`, `/hover` and `/fill-subtle` pass.
- `--ink-popover-secondary` holds 4.5 on the popover base and on `--popover-well`, `--popover-hover` and `--control-raised` over it, so `ink-popover-secondary/popover` passes.
- `--ink-on-danger` is white or the dark ink, whichever has higher contrast on `--danger` (white in light, `#1a1a1f` in dark).
- `--accent` (and so `--focus-ring`) holds 3 against the card and every ground.

The audit re-checks these on composited surfaces and adds the pairs 10.1 does not sweep. The one pair that falls below its floor is the selected command-bar row: 10.5 draws its secondary line (and the action hint) in `--ink-popover-secondary` on `--accent-soft`, below 4.5 in dark. Fix it in CSS only: in `styles/command-bar.css`, `.command-bar__row--selected .command-bar__row-secondary` and `.command-bar__row--selected .command-bar__row-accel` use `--ink-popover`, which the `ink-popover/accent-soft` check covers.

The second pair near its floor is `ink-on-accent/accent`: primary buttons carry 12–13 px labels, so it needs 4.5, and teal at intensity 0 in light lands at about 4.50 with no margin. Extend the accent search in `theme.ts`: each step also requires `max(contrast(white, accent), contrast(darkInk, accent)) ≥ 4.5`, in addition to the existing 3:1 checks, and the 10.1 sweep test gains that assertion. Token values change only for themes where the old accent missed it; update the `tokens.css` parity values if the null theme moves.

### 9. Lint: motion literals

`scripts/check-css-tokens.mjs` also checks `transition` and `animation` declarations, including their `-duration` and `-delay` longhands, in every file except `tokens.css`. A declaration fails if it contains a time literal (`/\b\d*\.?\d+m?s\b/`), `cubic-bezier(`, or one of the keywords `ease`, `ease-in`, `ease-out`, `ease-in-out` or `linear`. Failures print `file:line: literal motion "<match>"`.

## Constraints

- `packages/core` stays free of `electron`, DOM and `node:*` imports. `motion.ts` and `contrast-audit.ts` are pure.
- Styling uses plain CSS with custom-property tokens. No literal colors, durations or easings appear outside `tokens.css`.
- No CSS-in-JS, no animation library, and no new runtime dependencies.
- Keep every `data-testid`, ARIA role and e2e-asserted class name. No screenshot assertions.
- Motion never delays input. No handler waits for an animation, and closing is immediate.
- `ZEO_E2E_MOTION` is honored only when `ZEO_E2E === "1"`.
- TypeScript is strict, with no `any`. Nothing under `.github/workflows/` is written. Commits follow Conventional Commits, with no AI attribution.
- Versioning: at rebase time, bump the root `package.json` patch to the next free version. Add a dated `CHANGELOG.md` section with `### Added` (motion, reduced motion) and `### Changed` (focus rings, hit targets, selected command-bar row contrast).
- Leave `prds/` and `docs/design/` untouched.

## Acceptance criteria

1. Hover and press on every §3 control transition over 120 ms with `--ease-standard`. Icon buttons, tiles, dots and swatches shrink to 0.96 while pressed.
2. The command bar, find pill, settings sheet, theme picker and dialogs open with a 200 ms scale from 0.97 to 1 plus a fade, on every open, without flashing a stale frame. Scrims only fade.
3. Switching to a later space slides the space-scoped block in from +28 px over 320 ms. Switching to an earlier space slides it in from −28 px. Deleting the active space fades it in.
4. During a space switch, the tint cross-fades over 320 ms through two layers, and the content views swap instantly.
5. With `prefers-reduced-motion: reduce`, opens and space switches are 120 ms opacity fades, and carets do not blink.
6. With `ZEO_E2E=1` and no `ZEO_E2E_MOTION`, `<html>` has `zeo-motion-off` and nothing animates.
7. Every §6 control except the two exempt inputs shows a 2 px `--focus-ring` outline, offset 1 px, on `:focus-visible`.
8. Every §6 control measures at least 28 × 28 px.
9. `contrastAudit` passes all 17 checks across the sweep.
10. After a space switch, the live tokens in the sidebar, overlay and settings equal `themeTokens()`.
11. View bounds match `contentRect` and `splitPaneBounds` across the §10 geometry matrix.
12. The lint rejects literal durations and easings.
13. `pnpm lint`, `pnpm typecheck`, `pnpm test` and `pnpm e2e` pass on both CI jobs.
