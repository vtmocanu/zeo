# PRD 4.2 — Command bar suggestions: tabs, archived tabs, spaces

## Context

zeo is a keyboard-first, workspace-centric open-source browser for macOS.
Design: `docs/specs/2026-08-30-zeo-v1-design.md`. Requires PRD 4.1
(`prds/done/4.1-command-bar-url-entry.md`) merged: the command bar overlay
exists, `Cmd+L` / `Cmd+T` open it, and submitting resolves text to a URL or a
search.

The bar currently takes text and navigates. This PRD makes it the tab switcher:
while typing, a ranked list of matching open tabs (across every space),
archived tabs, and spaces appears under the input, navigable with the arrow
keys; `Enter` acts on the selected row. The first row is always the navigate
or search action for the typed text, so existing behavior is unchanged when
the user never touches the arrows. Command items (actions with shortcuts)
arrive in PRD 4.3 as one more suggestion source on the same list.

## Deliverables

### 1. Suggestion model and ranking (core)

- Types in `packages/core`:

  ```ts
  type Suggestion =
    | { kind: "navigate"; url: string; label: string }
    | { kind: "search"; url: string; label: string }
    | { kind: "tab"; tabId: string; spaceId: string; title: string; url: string; spaceName: string }
    | { kind: "archived-tab"; tabId: string; spaceId: string; title: string; url: string; spaceName: string }
    | { kind: "space"; spaceId: string; name: string };
  ```

- A pure `suggest(query, catalog, options): Suggestion[]` where `catalog` is a
  plain input built by main from the store: every space (id, name, active
  flag), every open tab with its owning space id and `lastActiveAt`, every
  archived tab with its owning space id and `archivedAt`; `options` carries
  the bar mode and the active tab id. No store access inside `suggest`.
- Row 0 is always the text action: `resolveInput(query)` mapped to a
  `navigate` or `search` suggestion (label is the canonical url or
  `Search DuckDuckGo for "<query>"`). When `resolveInput` returns `null`
  (empty query) row 0 is omitted.
- Matching, on the trimmed query, case-insensitive: a candidate matches when
  every whitespace-separated query term is a substring of its haystack. Tab
  haystack is `title + " " + url` with the url's scheme stripped; space
  haystack is its name. No fuzzy or subsequence matching.
- Scoring, highest first, ties broken by `lastActiveAt` (tabs) or
  `archivedAt` (archived) descending, then by catalog order:
  1. Term matches at the start of the title or of the url host.
  2. Term matches at a word boundary in the title.
  3. Any other substring match.
  Open tabs in the active space rank above open tabs in other spaces at the
  same score; open tabs rank above spaces, spaces above archived tabs. The
  active tab itself is excluded from results.
- Empty query: in `new-tab` mode the list shows the 8 most recently active
  open tabs across all spaces (excluding the active tab); in `navigate` mode
  the list is empty. With a non-empty query the list holds at most 8 rows
  after row 0.
- Unit tests: each score tier, active-space precedence, kind ordering, the
  active-tab exclusion, multi-term AND matching, the empty-query cases, the
  cap, and stable ordering on equal scores.

### 2. State and bridge contract (core)

- `CommandBarState` gains `query: string`, `suggestions: Suggestion[]`, and
  `selectedIndex: number` (0-based into `suggestions`; `-1` when the list is
  empty). The renderer never computes or reorders suggestions.
- `CommandBarApi` gains:

  ```ts
  setQuery(text: string): Promise<void>;
  moveSelection(delta: 1 | -1): Promise<void>;
  accept(): Promise<void>;
  ```

  `setQuery` stores the text, recomputes `suggestions` from a fresh catalog,
  resets `selectedIndex` to 0 (or `-1`), and pushes the state. `moveSelection`
  wraps at both ends and pushes. `accept` performs the selected suggestion's
  action (below) and closes the bar; with `selectedIndex === -1` it behaves
  like `submit(query)`. `submit(text, mode?)` from PRD 4.1 is unchanged and
  stays the headless seam for URL and search entry.
- Channel constants for the three new methods.

### 3. Actions (main)

- `navigate` / `search` rows: identical to PRD 4.1 `submit` in the effective
  mode.
- `tab` rows: if the tab's space is not active, activate that space (same
  hide/show transition as `spaces.activate`), then activate the tab. The
  existing "tab commands resolve against the active space" guard stays; this
  path does the space switch first, in main, before the activation.
- `archived-tab` rows: activate the owning space if needed, restore the tab,
  then activate it.
- `space` rows: activate the space; its own active tab shows.
- `SpaceStore` gains a read-only `spaceOfTab(tabId): string | null` covering
  open and archived tabs, used by the catalog builder and by the tab actions.
  Issue #57 tracks the broader ownership index; this method is the minimum
  4.2 needs and must be unit tested.
- Overlay height follows the list: a pure `commandBarBounds(contentWidth,
  contentHeight, rowCount)` returns `COMMAND_BAR_HEIGHT + rowCount *
  SUGGESTION_ROW_HEIGHT` (constants in `layout.ts`), clamped so the overlay's
  bottom never exceeds the content height. Main re-applies bounds on every
  state push while the bar is open.

### 4. Bar renderer (ui)

- Under the input, one row per suggestion: an icon by kind (favicon for tabs
  when available, a glyph otherwise), primary text (title, space name, or the
  action label), secondary text (host for tabs, `Archived · <space>` for
  archived tabs, `Space` for spaces). The selected row is highlighted;
  hovering does not change selection, clicking a row accepts it.
- Keys: typing calls `setQuery` on every change; `ArrowDown` / `ArrowUp` call
  `moveSelection`; `Enter` calls `accept`; `Escape` calls `close`. No local
  state beyond the input's text.
- Style follows `App.css` conventions; the panel grows with the list and
  never scrolls (the cap keeps it bounded).

### 5. Tests

- Core: ranking rules above; `spaceOfTab`; bounds with row counts including
  the clamp against a short window.
- e2e:
  - Two spaces, a distinctly titled tab in the inactive one. Open the bar in
    `new-tab` mode, type part of that title, assert the state's
    `suggestions` contains a `tab` row for it with the right `spaceName`;
    `accept` on that row switches the active space and activates the tab, and
    no new tab is created.
  - Archived tab: type its title, accept the `archived-tab` row, assert it is
    restored and active.
  - Space: type a space name, move selection to the `space` row, accept,
    assert the active space changed.
  - Row 0 remains the text action: with a query that also matches a tab,
    `accept` without moving the selection navigates or creates per the mode.
  - `ArrowDown` from the last row wraps to row 0; `ArrowUp` from row 0 wraps
    to the last row.
  - Empty query in `new-tab` mode lists recent tabs, most recent first,
    active tab excluded, at most 8.
  - The overlay's bounds height grows with the list and shrinks back when the
    query stops matching.

## Constraints

- Ranking, state types, and bounds math live in `packages/core`; main builds
  the catalog and performs actions; the renderer stays thin.
- No history, bookmarks, or command items yet; no fuzzy matching.
- `submit(text, mode?)` behavior from PRD 4.1 is unchanged.
- Do not create or modify anything under `.github/workflows/`; root script
  names stay unchanged.
- Version bump to 0.0.10 with a dated `CHANGELOG.md` section.

## Acceptance criteria

- `pnpm lint && pnpm typecheck && pnpm build && pnpm test && pnpm e2e` green.
- In the running app: typing in the bar lists matching tabs from every space,
  archived tabs, and spaces; arrow keys move the highlight; `Enter` on a tab
  row jumps to it even across spaces; `Enter` on row 0 still navigates or
  searches; `Cmd+T` with nothing typed shows the recent tabs list.
- CI green on the merge request branch.
