# PRD 2.1 — Core tab model: pinning, ordering, MRU activation, archiving

## Context

zeo is a keyboard-first, workspace-centric open-source browser for macOS.
Design: `docs/specs/2026-08-30-zeo-v1-design.md`. Epic 2 builds the real tab
experience; this PRD is its foundation and touches `packages/core` only.

Current state (after PRD 1, `prds/done/1-scaffold-first-window.md`):
`packages/core/src/tab-store.ts` holds `TabStore` with `create`, `close`,
`activate`, `list`, `activeTabId`, `snapshot`; closing the active tab
activates the neighbor that takes its slot. `Tab` is
`{ id, url, title, createdAt }` (`src/tab.ts`). The IPC contract lives in
`src/ipc.ts`.

## Deliverables

All in `packages/core`, pure TypeScript, no Electron imports (lint-enforced).

### 1. Tab shape

Extend `Tab` with `pinned: boolean`, `lastActiveAt: number`, and
`archivedAt: number | null`. `create` seeds `pinned: false`,
`lastActiveAt` from the store clock, `archivedAt: null`.

The store additionally stamps a monotonic internal sequence number on every
activation and archival, so MRU selection and `archived()` ordering are
deterministic even when two operations share one clock timestamp. Tests for
every time-ordered behavior use a fixed injected clock.

### 2. Pinning and ordering

- `pin(id)`: sets `pinned` to `true`; `unpin(id)`: sets it to `false`. Both
  are idempotent (repeated calls keep the state, never toggle). A newly
  pinned tab appends to the end of the pinned group; an unpinned one appends
  to the end of the unpinned group. `pin` on an archived tab throws.
- `list()` returns pinned tabs first (stable order within each group).
- `reorder(id, toIndex)`: move a tab within its group (pinned or unpinned);
  the index is interpreted within that group and clamped to its bounds.

### 3. MRU activation

- `activate(id)` stamps `lastActiveAt`.
- Closing the active tab activates the most recently active remaining
  open tab (not the slot neighbor). Closing the last open tab leaves
  `activeTabId === null`.

### 4. Archiving

- `archive(id)`: sets `archivedAt`, removes the tab from `list()`; archiving
  the active tab picks the next active by the same MRU rule. A pinned tab
  cannot be archived (throws).
- `restore(id)`: clears `archivedAt`, sets `pinned: false`, appends the tab
  to the unpinned group; when `activeTabId` is `null` the restored tab
  becomes active.
- `archived()`: archived tabs, most recently archived first (sequence-based
  tie-break).
- `snapshot()` gains `archived: Tab[]` (same ordering as `archived()`)
  alongside `tabs` and `activeTabId`; update `TabsState` in `src/ipc.ts`
  accordingly, and extend `TabsApi` with exact signatures —
  `pin(id: string): Promise<void>`, `unpin(id: string): Promise<void>`,
  `reorder(id: string, toIndex: number): Promise<void>`,
  `archive(id: string): Promise<void>`, `restore(id: string): Promise<void>`
  (types only — the desktop/ui wiring is PRD 2.2/2.3 work, but the contract
  lands here so both sides build against it).

### 5. Tests

Vitest unit tests covering every new operation and invariant: pin ordering
and placement, pin/unpin idempotence, pin-on-archived rejection, reorder
clamping within groups, MRU close-activation with a fixed clock (including
same-timestamp tie-breaks, close-until-empty, and archived tabs never
becoming active), archive/restore round-trip (including archive of the only
open tab followed by restore activating it, and restore clearing `pinned`),
pinned-archive rejection, unknown-id errors.

## Constraints

- `packages/core` only. Do not modify `apps/desktop`, `apps/ui`, or `e2e`
  beyond what a changed `TabsState` type strictly forces to keep
  `pnpm typecheck` green (mechanical adjustments only, no new behavior).
- Persistence stays out of scope (in-memory store; SQLite is a later PRD).
- Do not create or modify anything under `.github/workflows/`.
- Root script names (`lint`, `typecheck`, `test`, `e2e`, `build`, `dev`)
  stay unchanged.

## Acceptance criteria

- `pnpm lint && pnpm typecheck && pnpm build && pnpm test` green.
- `pnpm e2e` still green (existing app behavior unchanged).
- Every new `TabStore` operation covered by unit tests, including the
  invariants listed above.
- CI green on the merge request branch.
